# 项目状态与开发边界

维护基线：本体 **2.16.3**，存档结构 **10**。本文保留影响后续开发的架构事实与验证方法，不累计历史检查数字。性能采样和后续优化顺序见 [分类导航与性能复核](navigation-performance-280.md)。

## 当前架构

引擎采用显式依赖与具名转发，普通行动和地图移动共用年度收尾及行动单位结算。普通关系按 NPC ID 引用权威人物；生存、拘禁与名册状态独立，转换规则见 [人物拘禁契约](npc-custody.md)。只允许结构 10；结构 1–9 不兼容，不转换、不映射，未知界面不默认成人界。会话准备与纯查询须分开；诸天边界见[诸天实装进度](heavens-implementation.md)。

架构第一阶段将原读档末尾的百鬼时钟、拘魂解除和灵田归属修正纳入统一单次提交，补齐独立空间准备的变更检测；原执行顺序、人物和资源归属、年龄及随机序列保持。依赖检查展开标准装饰器后审查真实实现，两个人物／势力年度函数补齐显式契约，时间契约测试分别验证地区调度与非地区路径，不改变年度运行算法。验证入口为 `tests/test_session_reconciliation.py`、`tests/test_persistence_pipeline.py` 及各依赖专项。

2026-10-19 架构第二阶段将职责边界落实为可独立调用的接口：`prepare_session` 只准备调用方的原工作状态并报告变化，读写由 `_load` 协调；地区算法只接收 `RegionalDependencies`，不再接收整个引擎。响应按原顺序协调边界排斥、原保存点和视图准备，随后生成不可变的 `PreparedGameView`。纯投影 `project_game` 只接收该快照，不能访问游戏、存档、时钟或成就服务。时间、转场、读档、视图准备及地区回调明确参数和返回值，装配仍支持构造后替换引擎方法、地图和存储。

原展示辅助函数中的状态补全与成就发放仍在显式视图准备阶段、沿原位置执行，未提前到读档，也未增加保存或发奖时机；兼容入口 `GameEngine.present` 仍是有副作用的响应入口，不能当作纯查询。仅复制公开展示数据，不复制权威人物、世界或资源池；未新增持久字段，保持结构 10。边界及顺序验证见 `tests/test_architecture_stage2.py`；`tools/replay_lifecycle.py` 支持以前置源码归档回放创建、读档、地区补算和空间场景，对比响应、完整存档与成就元数据。固定种子的时间回放仍由 `tools/replay_time_flow.py` 执行。

Debug 通过独立会话、临时引擎和原子提交复用正式玩法；控制台、CLI 和 MCP 共用注册表。正式引擎、系统、模型及规则不反向依赖 Debug。使用与扩展要求见 [开发规范](debug-development.md)。

2026-10-19 架构第三阶段移除最后九组玩法继承：119 个原方法成为各领域模块中的普通函数，机构入口及王庭结算也改用显式契约；引擎以静态声明的方法转发，旧 Mixin 仅为独立消费者保留适配器。`system/character/dependencies.py` 声明冻结能力，`wiring.py` 延迟解析当前方法、资源与可选参数；校验及傀儡预览没有保存或呈现接口。跨界请求、计划和结果位于无副作用的 `world_transition_schema.py`，原运行时模块保留同一类型的兼容导出。静态检查阻止恢复玩法继承、隐藏接收者及未声明能力；详见[第三阶段架构说明](architecture-stage3.md)。

空间裂缝、符箓与修罗派系采用独立规则模块和冻结依赖契约，没有增加引擎 Mixin。随机独立空间保存在存档内，按访问生成；外界交互在公开命令的读档边界统一拦截。详见 [空间开发契约](spatial-talismans.md)。

## 仍需关注的边界

| 现状 | 后续要求 |
| --- | --- |
| `ensure_*` 与部分展示辅助函数仍有状态补全副作用，现已集中到显式准备阶段 | 新增纯查询使用已准备快照；迁移旧辅助函数须另证 RNG、历史、奖励与保存时机等价 |
| GameEngine 已无玩法继承，内容注册与战斗等业务模块仍较大 | 按具体数据归属和明确契约扩展，不为减少行数重排规则或增加通用属性代理 |
| 仅支持结构 10 的完整状态回放 | 比较人物事实、关系、资源、历史及 RNG；不得添加旧结构迁移 |
| 专用活动保留独立时钟 | 新玩法选择公共策略或明确专属计时，验证中断、死亡、跨界及部分年份结算 |
| 旧活傀可能缺少原 NPC ID | 保留专用资源记录，不按同名猜测绑定；新活傀必须记录来源身份 |
| Debug 入口覆盖不等于穷举所有玩法分支 | 新增子操作同步参数 Schema，验证实际规则、禁用条件、失败回滚与副本隔离 |

## 验证与发布

完整回归使用 pytest，浏览器专项独立执行；修改相应系统时还需运行对应规则与设备场景。`tools/check_module_dependencies.py` 检查显式导入循环和边界，`tools/check_documentation.py` 检查本地链接、索引及当前版本声明，均不能替代玩法测试。

Windows 与 Android 发布必须重新构建并校验产物哈希、源码来源和当前版本的测试证据。Android 使用专用测试模拟器；实体设备和更高系统需单独验收。流程见 [项目入口](../README.md) 与 [安卓说明](../android/README.md)，当前产物事实见 `dist/` 发行清单。
