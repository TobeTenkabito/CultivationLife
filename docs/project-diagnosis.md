# 项目状态与开发边界

维护基线：本体 **1.59.2**，开发源码存档结构 **9**。诸天 M1 尚未打包发行。本文保留影响后续开发的架构事实与验证方法，不累计历史检查数字。

## 当前架构

引擎采用显式依赖与具名转发，普通行动和地图移动共用年度收尾及行动单位结算。普通关系按 NPC ID 引用权威人物；生存、拘禁与名册状态独立，转换规则见 [人物拘禁契约](npc-custody.md)。结构迁移与会话准备分开，支持 6→7→8→9，拒绝结构 1–5。8→9 只增加诸天空容器；基础契约见[诸天实装进度](heavens-implementation.md)。

Debug 通过独立会话、临时引擎和原子提交复用正式玩法；控制台、CLI 和 MCP 共用注册表。正式引擎、系统、模型及规则不反向依赖 Debug。使用与扩展要求见 [开发规范](debug-development.md)。

空间裂缝、符箓与修罗派系采用独立规则模块和冻结依赖契约，没有增加引擎 Mixin。随机独立空间保存在存档内，按访问生成；外界交互在公开命令的读档边界统一拦截。详见 [空间开发契约](spatial-talismans.md)。

## 仍需关注的边界

| 现状 | 后续要求 |
| --- | --- |
| 读档准备、`ensure_*` 和部分展示存在状态补全与结算副作用 | 区分纯视图与状态准备，固定 RNG、历史和保存时机；纯查询不得调用有副作用的入口 |
| GameEngine 保留九个局部 Mixin，内容注册与战斗模块仍较大 | 按具体数据归属与流程拆分，不为减少行数或继承数量改变规则 |
| 跨结构回放的文档摘要有预期差异 | 同结构比较完整状态；跨结构比较迁移后人物事实、关系、资源及 RNG |
| 专用活动保留独立时钟 | 新玩法选择公共策略或明确专属计时，验证中断、死亡、跨界及部分年份结算 |
| 旧活傀可能缺少原 NPC ID | 保留专用资源记录，不按同名猜测绑定；新活傀必须记录来源身份 |
| Debug 入口覆盖不等于穷举所有玩法分支 | 新增子操作同步参数 Schema，验证实际规则、禁用条件、失败回滚与副本隔离 |

## 验证与发布

完整回归使用 pytest，浏览器专项独立执行；修改相应系统时还需运行对应规则与设备场景。`tools/check_module_dependencies.py` 检查显式导入循环和边界，`tools/check_documentation.py` 检查本地链接、索引及当前版本声明，均不能替代玩法测试。

Windows 与 Android 发布必须重新构建并校验产物哈希、源码来源和当前版本的测试证据。Android 使用专用测试模拟器；实体设备和更高系统需单独验收。流程见 [项目入口](../README.md) 与 [安卓说明](../android/README.md)，当前产物事实见 `dist/` 发行清单。
