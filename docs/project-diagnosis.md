# 项目架构与开发边界

维护基线：本体 **3.11.0**，存档结构 **12**。结构1–11拒绝加载或导入，不迁移、不覆盖；未知界面不默认成人界。旧阶段排期、发行流水账和过时性能数字已移出当前说明，历史可从Git查阅。

## 权威状态与入口

`GameEngine` 使用普通领域函数、静态具名转发和显式依赖装配，不继承玩法Mixin。兼容适配器只服务既有独立调用方；新功能不能重新引入隐式接收者、任意属性代理或动态函数全局变量重绑定。详细接口见[引擎说明](../cultivation_life/engine/README.md)及[系统边界](../cultivation_life/system/README.md)。

原NPC、物资、组织账本、地图地址与实例各有唯一权威归属；普通关系按NPC ID引用。生存、拘禁和名册独立，见[人物拘禁](npc-custody.md)。跨界计划和提交沿统一入口，规则见[跨界开发规范](world-transition-development.md)、[当前审计](world-transition-audit.md)与[空间开发契约](spatial-talismans.md)。新持久字段必须进入归属合同。

## 准备、响应与事务

`prepare_session` 准备调用方的原工作状态并报告变化，读写由加载协调器负责。响应依原顺序处理边界、保存点和视图准备，再生成快照。纯投影不能访问或改写游戏、时钟、存档或成就；`GameEngine.present` 仍包含视图准备副作用，不能当作纯查询。

人物玩法依赖由 `system/character/dependencies.py` 声明、`wiring.py` 装配。资源与回调在调用时解析，保持省略参数、显式None、关键字限制、静态方法／类方法及替换回调语义；校验和预览不得获得无关的保存、响应或整引擎权限。

普通行动和地图移动复用年度收尾及单位结算。地区算法只接收明确的 `RegionalDependencies`；专用活动保留原时钟。优化须保持准备、费用、RNG、年度、死亡、中断、发奖、保存和失败回滚顺序，不能跳过世界年份或复制权威实体。

## 已实施的性能边界

- HTTP游戏响应在原准备和保存之后生成不可变JSON字节；Python调用接口保留原值语义和快照隔离。
- 市场配方只在同一次结算内复用；商品目录按实际任务需要选择。缓存不得遗漏内容代次、实际库存、资格和失效条件。
- 解码与快照的数据复制保持独立memo、共享引用及环语义，扩展类型沿原回退。
- 已审阅的无游戏状态读取可在长行动期间独立返回；游戏GET、写入、Debug与资格判断仍受原事务约束。文件读取和原子替换使用原短锁，不因并发读取取消账户与存档边界。

历史微基准不代表当前游戏或手机帧率。复测工具为 `tools/audit_architecture_performance.py`，只使用临时存档；记录最终代码、内容、种子、设备、样本及测量口径。导航与按需投影见[分类导航与性能](navigation-performance-280.md)。JSON存储、锁粒度和复制实现可以按证据改进，但必须验证外部替换、导入、删除、异常及并发失效。

## 尚需持续遵守的约束

大型战斗、内容注册及专用活动模块按数据归属扩展，不能为缩短代码重排规则。完整状态回放比较人物事实、关系、资源、历史与RNG，不删除差异字段以制造一致。旧活傀缺少原NPC ID时不得按同名猜绑定；新活傀保留来源身份。

Debug通过独立会话和临时引擎复用正式结算，正式引擎不得反向依赖Debug。新增子操作同步参数Schema，验证禁用条件、失败回滚和副本隔离；见[Debug开发规范](debug-development.md)。

## 验证与发布

三项开发门禁是跨界状态合同、模块依赖和文档检查；它们不能代替玩法测试。按修改领域运行pytest与独立浏览器专项，涉及跨界、旧事件和提交时遵守根AGENTS要求。架构回归保留 `test_session_reconciliation`、`test_persistence_pipeline`、`test_architecture_stage2`、`test_architecture_stage3` 及固定种子回放工具。

正式发布须以最终代码重建Windows EXE与签名Android包，完成要求的全仓、浏览器及双端验收。当前说明见[3.11.0](release-3110.md)，发布与远程资产校验见[发行流程](release-workflow.md)。历史测试数字和旧包不能代替新版本验收；原始验收清单、日志与哈希继续保留。
