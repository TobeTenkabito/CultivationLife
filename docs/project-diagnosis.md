# 项目状态与开发边界

维护基线：2026-10-31，本体 **3.3.2**，存档结构 **11**。本文保留影响后续开发的架构事实与验证方法，不累计历史检查数字。性能采样和后续优化顺序见 [分类导航与性能复核](navigation-performance-280.md)。

## 当前架构

引擎采用显式依赖与具名转发，普通行动和地图移动共用年度收尾及行动单位结算。普通关系按 NPC ID 引用权威人物；生存、拘禁与名册状态独立，转换规则见 [人物拘禁契约](npc-custody.md)。只允许结构 11；结构 1–10 不兼容，不转换、不映射，未知界面不默认成人界。会话准备与纯查询须分开；诸天边界见[诸天实装进度](heavens-implementation.md)。

架构第一阶段将原读档末尾的百鬼时钟、拘魂解除和灵田归属修正纳入统一单次提交，补齐独立空间准备的变更检测；原执行顺序、人物和资源归属、年龄及随机序列保持。依赖检查展开标准装饰器后审查真实实现，两个人物／势力年度函数补齐显式契约，时间契约测试分别验证地区调度与非地区路径，不改变年度运行算法。验证入口为 `tests/test_session_reconciliation.py`、`tests/test_persistence_pipeline.py` 及各依赖专项。

2026-10-19 架构第二阶段将职责边界落实为可独立调用的接口：`prepare_session` 只准备调用方的原工作状态并报告变化，读写由 `_load` 协调；地区算法只接收 `RegionalDependencies`，不再接收整个引擎。响应按原顺序协调边界排斥、原保存点和视图准备，随后生成不可变的 `PreparedGameView`。纯投影 `project_game` 只接收该快照，不能访问游戏、存档、时钟或成就服务。时间、转场、读档、视图准备及地区回调明确参数和返回值，装配仍支持构造后替换引擎方法、地图和存储。

原展示辅助函数中的状态补全与成就发放仍在显式视图准备阶段、沿原位置执行，未提前到读档，也未增加保存或发奖时机；兼容入口 `GameEngine.present` 仍是有副作用的响应入口，不能当作纯查询。仅复制公开展示数据，不复制权威人物、世界或资源池；该历史阶段未新增持久字段，保持当时结构 10；当前按 v3.2.0 授权仅支持结构 11。边界及顺序验证见 `tests/test_architecture_stage2.py`；`tools/replay_lifecycle.py` 支持以前置源码归档回放创建、读档、地区补算和空间场景，对比响应、完整存档与成就元数据。固定种子的时间回放仍由 `tools/replay_time_flow.py` 执行。

Debug 通过独立会话、临时引擎和原子提交复用正式玩法；控制台、CLI 和 MCP 共用注册表。正式引擎、系统、模型及规则不反向依赖 Debug。使用与扩展要求见 [开发规范](debug-development.md)。

2026-10-19 架构第三阶段移除最后九组玩法继承：119 个原方法成为各领域模块中的普通函数，机构入口及王庭结算也改用显式契约；引擎以静态声明的方法转发，旧 Mixin 仅为独立消费者保留适配器。`system/character/dependencies.py` 声明冻结能力，`wiring.py` 延迟解析当前方法、资源与可选参数；校验及傀儡预览没有保存或呈现接口。跨界请求、计划和结果位于无副作用的 `world_transition_schema.py`，原运行时模块保留同一类型的兼容导出。静态检查阻止恢复玩法继承、隐藏接收者及未声明能力；详见[第三阶段架构说明](architecture-stage3.md)。

空间裂缝、符箓与修罗派系采用独立规则模块和冻结依赖契约，没有增加引擎 Mixin。随机独立空间保存在存档内，按访问生成；外界交互在公开命令的读档边界统一拦截。详见 [空间开发契约](spatial-talismans.md)。

### 第一批落地（2026-10-31，源码）

游戏 GET 使用独立 `PreparedJsonGameView`，在原“边界结算→必要时保存→完整视图准备”之后直接生成不可变 UTF-8 JSON 字节；发送仍在原事务锁释放后进行。`get_game(id)` 继续返回原字典，`PreparedGameView/project_game` 继续保留 tuple 与键类型；实例、类级与子类响应钩子沿原路径处理，旧签名和不可检查签名的嵌入读取器也保持可用。没有跨请求保存游戏对象或新增保存点。

前端的游戏 GET 通过 `fleet_goods=deferred` 摘出 `fleet_network.order_goods`，仅在原经营导航打开商盟面板时，经 `UtilityPanels.schedule('merchant', ...)` 调用只读 `/api/fleet-goods` 并绘制。目录只包含原公开商品编号和名称；商队位置、库存相关状态、订单、资格、事件与忙碌判断仍来自主响应。回包须同时符合当前渲染代次与当前游戏响应；切档、返回开始页或后续响应使旧回包失效，关闭期间不重画。目录失败提供原导航内的真实重试，绘制后刷新原有子页和忙碌禁用状态。个人流水仍沿原更新时机。

本批仍完整执行原视图准备，目录仅在 HTTP 投影处摘出；尚未延迟目录构造本身或拆分地图、资金与权限投影。无此查询参数的 HTTP 调用和 Python 接口继续得到完整字段；原创建、提交选项及其他 POST 响应未改成字节入口。这个范围优先消除重复冻结／展开和不必要传输，避免把有副作用的 `public_*` 直接延后。

宗门与家族财务页也复用原订单控件。当原响应含有 `can_order` 为真的宗门／家族商队时，GET 即使带按需参数也保留完整商品目录，兼容这些既有消费者；其余场景才摘出目录。该判断只消费原权威资格结果，不增加或改算权限。专项同时实际建立宗门、家族商队并打开对应页面，验证完整目录、订单选择器、无额外目录请求及存档／成就不变；本批未另建多面板异步状态。

居民经济只在同一市场、同一次篮子结算内复用配方。该作用域中原算法仅改变库存、交易价格、资金及产消记录，不改变配方所依赖的商品集合、阶级和参考价；返回后丢弃缓存，下一批重新查询。缓存按实际配方函数区分，生产仍先执行原拒绝检查，再查询配方；数量、可负担额度、采集限额、费用、舍入、实际转账、交易顺序和 RNG 均沿原入口。没有全局市场缓存、合并年份或新增持久字段。

复核修复了异步目录错误页直接分组导致重试按钮丢失按钮语义的问题；同时覆盖实例／类级旧响应钩子、旧读取签名与原结构 1–10 的拒绝且不覆盖。领域回归暴露一条旧测试仍断言结构 10，已在 HEAD 隔离代码复现；只将其改为核对当前结构并明确是可选经济策略补全，原资金、库存、欠款和已付款任务断言全部保留。

性能与回放入口：`tools/benchmark_http_views.py` 对相同隔离输入执行真实 HTTP 并逐值比较完整 JSON，延后目录后重新拼合比较；`tools/benchmark_economy_actions.py` 保存三种种子的完整百年结果；`tools/benchmark_basket_queries.py` 在同一控制器下按 ABBA 交错原版与缓存篮子算法，比较完整状态与 RNG，仅排除墙钟 `updated_at`。原版篮子函数冻结在 `tests/fixtures/basket_consumption_332.py` 并由 SHA-256 约束；报告保存在 `build/architecture-batch1-20261031/`。本批仅交付源码，未发布或进行双端原生发行验收。

真实 HTTP 最终对照在同一当前服务器下交错旧字典适配器、新完整字节路径和前端按需路径，每种 7 次去预热采样、逐轮正反序切换。计时包括回环 HTTP 读取及 JSON 解码，不含随后目录请求或浏览器绘制；使用改动前保存的相同输入与完整 JSON 作为等价基准。结果只代表本机、本场景：

| 金丹 | 209.726 | 145.179 | 142.884 | 794759 → 531041 |
| 真仙 | 229.072 | 164.153 | 157.771 | 1029643 → 749245 |

最终三项必需检查通过，30 个相关模块共 1042 项回归通过；此前 971 项成功用例全部保留，并覆盖修正后的经济策略补全测试及新增边界。事件恢复浏览器覆盖四主题、桌面／手机与过期选项、后续奖励、忙碌解除及仍应禁用的控件；原商队浏览器覆盖八布局的真实建队、护卫、建盟、账目与重载；新增目录浏览器覆盖关闭不读取、忙碌／权限、切档过期回包、真实重试、宗门／家族订单及存档和成就字节不变。源码与证据指纹核对见该目录 `final-report.json`。

事件浏览器与三组领域回归并行时曾一次等待过期事件按钮超时；没有据此改动事件运行逻辑或放宽断言。随后两次独立四主题复验通过，其中一次带失败现场捕获，未再捕获该超时；原失败日志保存在 `browser-events-212-concurrent-timeout.log`，不将这次未复现现象表述为已定位并修复的游戏缺陷。

### 第二批落地（2026-10-31，源码）

本批只修改纯内容引用整理与存档列表查询，不增加已加载游戏的跨请求缓存。引用整理跳过无需遍历的标量，同一次调用至多复用 4096 个精确字典键查询，返回即释放；值引用仍调用原 `canonical_content_id`。独立 `Player`、`Item` 解码仍接受原内容别名，新旧键冲突仍原样拒绝，玩家文本、未知字段、未修改分支的对象身份及按需复制语义保持。没有取消嵌套解码边界或以全局“已整理”标志绕过独立解码。

`SaveStore` 的摘要索引只保留列表字段的不可变小型 JSON 和实际文件内容 SHA-256，不保存游戏对象，不写入旁路文件。每次列表仍读取全部原文件字节；即使大小、修改时间均相同的原地编辑或原子替换也会失效。保存、删除及导入的原提交路径不依赖索引维护；下次读取比较内容，删除文件按目录结果剔除，损坏文件修复后重建。读档仍经过原结构校验与完整模型解码，摘要不能授予权限。结构兼容和显示名称每次重新计算，未知界面保留“未知界面”；返回值相互隔离，调用方修改列表不会污染索引。

索引按原目录锁保护，最多 1024 项；单项摘要载荷上限 16 KiB，全部载荷合计上限 1 MiB，超限元数据照常返回而不缓存。这里的字节上限只计算 ASCII JSON 载荷，另有条目和 Python 容器开销；源文件仍是唯一权威。首次访问需要完整解析，收益主要来自同一进程的重复列表，不能表述为避免了磁盘读取或所有读档均同比提速。

复核中淘汰了更慢的全字符串缓存方案，并复现递归闭包令临时键缓存延迟到循环 GC 才释放的问题；最终使用模块级纯函数递归，关闭循环 GC 的对象生命周期测试确保返回后立即释放。专项以冻结的前版实现进行 600 组随机文档差分，并覆盖引用冲突、独立解码、摘要字段与顺序、外部同时间替换、权限读取、原子提交失败、多实例并发、损坏修复及缓存边界。

可复跑入口为 `python -X utf8 tools/benchmark_storage_queries.py --prepare --output-dir build/storage-query-recheck`。它用冻结原版引用整理生成隔离的结构 11 输入，再正反序交错原版与当前实现，分别测纯整理、完整 `SaveStore.load`、包含模型导出的读取及真实回环 HTTP GET，逐次比较完整模型和 HTTP JSON。1／10／30 档列表使用相同的约 1.49 MB 有效文档副本；冷索引指新建内存索引、操作系统文件缓存已热，不是冷磁盘。本次最终数字和验证记录保存在 `build/architecture-batch2-20261031/`，绑定最终运行时输入及工具指纹。

最终主对照每种路径 9 次去预热采样，表中为中位数，括号为耗时减少比例。两种开局均使用全 11 项 DLC、种子 280 的相同预先保存文档；全量模型和 HTTP JSON 逐值一致，原输入及账户元数据字节不变：

### 第三批落地（2026-10-31，源码）

本批优化已有深复制边界，不减少会话准备、权限判断、视图补全、成就评估或保存步骤。`snapshot_copy.copy_plain_data` 只对精确的内置字典、列表和不可变标量使用快速复制；每个原复制入口独立建立 memo，保留内部共享引用和环，其他类型沿标准 `deepcopy` 及其扩展钩子处理。源容器保留到本次复制结束，防止扩展复制钩子修改源图后对象编号被复用；临时 memo 返回即释放。字典值先于键复制，保持标准库对自定义钩子的执行顺序。

接入范围为 `SectState`／`Player`／`GameState.from_dict` 内原有显式深复制，以及视图准备中的生成事件结果、末次战报和拘禁记录。没有改动字段、解码校验、RNG、补算、边界排斥、保存和发奖的顺序；原有不复制的字段也不借此扩大复制范围。`GameState.__deepcopy__` 的预览克隆及关系重绑定保持原实现，Python 不可变视图和 HTTP 字节快照接口保持。没有跨请求保存已加载对象或视图，也没有跳过完整视图准备。

冻结的函数 AST 摘要位于 `tests/fixtures/snapshot_boundaries_332.json`；专项将新复制调用还原为原 `copy.deepcopy` 后核对整段函数，确保四个边界的规则分支和调用顺序未变。复制专项覆盖 600 组嵌套数据差分、键与值类型、共享引用、环、tuple、自定义复制钩子、源图修改时的对象存活、即时释放、模型源数据隔离和不支持对象的原异常行为。复核实际复现并修正了原型先键后值的钩子顺序差异，失败现场保留在本批构建目录。

复跑入口为 `python -X utf8 tools/benchmark_snapshot_views.py --prepare --output-dir build/snapshot-view-recheck`。原版对照只在经 AST 校验的入口替换回标准 `deepcopy`，不修改标准库全局函数、游戏规则或 GC。使用相同全 DLC、种子 280 的金丹、真仙和合成长战报存档，每种路径 21 次去预热采样并逐轮反转顺序。单独的视图准备段与真实请求一样，共用读档预热过的素材目录作用域；该段的读档及输出校验在计时外。完整 HTTP 测量包含回环读写、原会话准备、视图准备、编码及客户端 JSON 解码，分别比较完整目录和现有按需目录参数，不用分段收益代替整个请求。

### 持续约束

| 现状 | 后续要求 |
