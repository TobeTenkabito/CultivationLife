# 仙域战斗内核

本次实现新增仙域前置阶段，保持已有六维交锋与无能力数据时的旧结算路径。
静态 `systems.transcendent_combat.voisinages` 保留给场景能力。仙界随机道统通过
`CapabilitySource` 提供领域快照，详见 [道统与转化](doctrines.md)。其他三级界面可以
实现自己的能力提供方，不必把养成规则写进战斗循环。

## 架构边界

| 模块 | 职责 |
| --- | --- |
| `system/combat/contracts.py` | 数据契约、有限能力定义、参数校验、`CombatPhases` 协议；将外部修为事实解析为能力快照 |
| `system/combat/voisinages.py` | 单场仙域覆盖、相持/受压/支配、按单位判断至道、有限资源账本 |
| `system/combat/ordinary.py` | 玩家与 NPC 复用的常规伤害曲线，不认识仙域 |
| `system/combat_system.py` | 原有六维、功法、血脉、阵法等交锋；通过协议调用前置阶段，不读取道统配置 |
| `engine/combat_capabilities.py` | 从真实人物记录读取状态，绑定战斗单位，战后回写玩家/NPC/偶遇缓存/家族字典 |
| `system/combat/npc_battle.py` | NPC 简化交锋适配；复用相同仙域与至道规则，保存实际消耗和伤势 |
| `system/combat/npc_lifecycle.py` | NPC 生成策略、按需恢复、跨界分段账本和战斗资源快照；不承担道统养成 |
| `system/doctrine/provider.py` | 按需结算仙界道统，并为玩家和 NPC 提供相同格式的能力快照 |

纯规则模块不导入引擎、存档、全局内容注册表。它们不推演人物修炼，不消耗世界随机数，
也不调用任意内容脚本。伤害曲线需要的随机波动由交锋调用者提供。

`PlayerCombatSystem.resolve(..., phases=...)` 是注入边界。未提供能力或所有能力未启用时，
不会经过仙域循环、改变旧战斗的随机数序列，或替换旧战力快速判定。

## 长期状态与能力定义

玩家与 `SectNpc` 各新增一个可选 `transcendence` 字段，默认 `None`。示例仅说明接口，
不是实际道统内容或最终数值设计：

```json
{
  "version": 1,
  "conversion": 1.0,
  "capacity": 1000,
  "current": 800,
  "force_tier": 2,
  "ward_tier": 2,
  "attack_cost": 10,
  "ward_cost": 100,
  "attainments": {"example_attainment": 4},
  "voisinage_ids": ["example_voisinage"],
  "plan": {
    "stance": "press",
    "investment": 0,
    "protect_ids": [],
    "target_ids": []
  }
}
```

- `attainments` 是能力提供方填写的中立键值，没有预设道统树、经验公式、转化事件或升级速度。
- `voisinage_ids` 表示传承允许访问的能力；达到定义中的修为阈值后才能成为可用能力。
- `conversion` 约束可用容量；转化为零时不能调用仙级资源。
- `force_tier` 与 `ward_tier` 是普通作用和护持的性质，不替代六维数值。
- `attack_cost` 是发动本轮仙级普通作用所需资源；无法支付时退回凡级作用。
- `ward_cost` 是吸收一个完整单位战斗态势损耗所需资源。零值表示只有至道资格门槛；
  正值表示有效攻击还能消耗防护资源。被完全阻断的凡级攻击不消耗金光。
- `stance` 支持 `off`、`guard`、`protect`、`press`。护持对象与敌方目标均按单位 ID 指定；
  默认为保护自身，压制姿态在当前抽象战场内选择敌方单位。
- `reachable_ids` 可由场景限制可达对象；不指定时使用现有近距离抽象战场，不模拟坐标。
- `sealed` 由外部封印系统提供，限制仙域调用；不根据身处下界一律禁止仙域。

NPC 使用独立资源。玩家也可以显式选择 `resource_link: "legacy_mp"`，以既有 MP 为唯一
资源账本，此时不需要保存 `capacity/current`，容量与当前值从玩家读取。主动五阶段转化
继续使用同一 MP 池，转化程度限制可用容量，不产生第二份仙灵力余额。
新独立资源不会因普通调息、普通规则中的 MP 恢复或重新进入战斗而自动补满。

### NPC 生命周期与计算预算

NPC 沿用一个 `transcendence` 字段，不为每个道统增加人物字段。长期账本新增的
`lifecycle` 仅有 `at`（世界时间）、`world`（上次环境）、`rate`（每年恢复量）。
活动仙域、覆盖关系和逐轮结果仍只存在于单场战斗。

- `initialize_native` 只在新人物生成时使用。配置指定的上界、达到最低境界的新人物，
  获得 `native_state` 基础转化模板；显式状态（包括 `{}` 或 `conversion: 0`）优先。
  基础模板不含道统；仙界已转化 NPC 首次参与能力解析时，由道统提供方建立稳定传承。
  宗门模板、招募、偶遇、生成关系人物、社会道侣及
  家族外聘人物使用同一策略；展示用的临时 `SectNpc` 不初始化。
- 旧人物 `transcendence: null` 保持旧路径，不因境界补造已转化事实。
  已有能力但没有时间戳的旧存档，首次接触仅建立时间基准，不追补无法证明的恢复。
- 恢复公式是 `min(可用容量, 当前资源 + 经过年数 × 上次保存的恢复速度)`。
  在实际参战、生成或跨界时计算一次；年度 NPC 循环不添加恢复遍历。
  同时刻重复遭遇、缓存提升为正式人物、加入家族和读档都不重置资源。
- `move_world` 先结算原界面，再切换环境。若旧逻辑直接改了世界且无法确定迁移时间，
  放弃该段未知恢复，不按目的地环境倒算。未来转化系统修改容量或转化率之前，也应
  先调用 `settle` 结清原状态对应的时间。
- 战斗快照按环境限制本场可调用容量，未调用的资源留在长期账本。战后回写
  `保留资源 + 本场剩余资源`，避免下界封存变成资源销毁或战后免费补满。
  回到上界不丢失 `attainments/voisinage_ids`。下界是否能展开仙域仍由实际资源和费用决定。
- 后台凡人交战在解析仙域定义之前直接返回旧流程，不新增随机抽取。
  玩家战斗对参战 ID 批量定位真实记录，宗门成员至多扫描一遍；不维护容易过期的全局索引。

当前可调初值位于 `systems.transcendent_combat.npc_lifecycle`：基础容量 1000，
上界每年恢复可用容量的 1%，下界不自然恢复；一、二、三级界面本场可调用容量分别为
2%、10%、100%。这是资源接入的初始数值，不是已经完成的转化或道统平衡方案。

现有玩家完成转化的标记通过 `converted_player_state` 接到同一个 MP 池，提供基础
仙级攻防，不授予仙域；显式 `player.transcendence` 优先。这样新上界 NPC 的护体金光
不会把已经完成旧转化流程的玩家错误地判为凡级攻击。

可重复性能探针：`python scripts/benchmark_npc_combat.py --world-step`。
微基准比较 1 万份账本跨 1、100、10000 年，以及 48 名仙域单位交战；运行时间不作为
不稳定的测试门槛。完整行动样例临时使用 100 年单位，并关闭归墟日历中断、移除定期
雷劫日程，报告实际经过年数与未参战 NPC 的账本是否保持不变。生产真仙时间单位目前
已调整为 100 年。不同机器、存档人口和战争规模会影响整体行动耗时。

能力定义由静态 `systems.transcendent_combat.voisinages` 或外部 `CapabilitySource` 提供：

```json
{
  "id": "example_voisinage",
  "name": "示例仙域",
  "attainment": "example_attainment",
  "required_level": 4,
  "strength": 100,
  "strength_per_level": 10,
  "opening_cost": 120,
  "upkeep_cost": 40,
  "max_investment": 80,
  "extra_target_cost": 10,
  "max_targets": 3,
  "effect": "suppress",
  "effect_cost": 20,
  "effect_power": 0.25
}
```

有限效果：`strike` 直接仙域杀伤，`suppress` 镇压使目标失去本场战斗能力，
`seal` 封闭退路。生成领域声明 `authority` 后，镇压按权能逐次侵蚀，封禁按权能累积至
完全收束，后者不造成气血损失；旧静态定义不声明权能时保持原语义。
新增效果应在规则模块扩展有类型的语义，不向内容开放执行代码。
镇压不自动造成死亡，不自动产生永久俘虏；明确的擒获行动复用已有俘虏流程。

## 每轮顺序

1. 同步资源，处理明确配置的仙力供给。
2. 各施术者选取已掌握的能力，核算展开、维持、覆盖及额外投入。先收缩无法负担的额外覆盖，
   仍不足时停域。不收取没有实际展开的费用。
3. 所有有效仙域建立后，按单位比较敌方 `incursion` 与己方 `stability`，不汇总为总分。
   旧定义缺少这两项时使用原 `strength`。默认容许 `1.25` 倍以内继续抵抗，
   由 `contest_ratio` 配置；此值只是可调的初始结算参数。
4. 形成相持、受压、支配关系，再同时处理有预算的仙域效果。双方互相突破时同时执行，
   其他失去自身保护的施术者不能抢先发动攻势；人物列表顺序不决定仙域胜负。
5. 仅未受支配、未被镇压、且未以仙域效果占用进攻行动的单位贡献普通攻击。
   对已经处于支配关系的目标，不免费追加一次普通攻击。
6. 常规交锋沿用六维与原有特性。先拆分单位贡献，再按攻击/护持的至道等级过滤，最后结算
   金光吸收与身体损耗。凡修同伴不能因为队中有仙人而继承仙级攻击。
7. 更新资源、单位状态、仙域持续资格与战斗目标。下一轮依据受创后的状态重新比较仙域。

没有独立的仙域血条。强度来自道统定义、修为、投入、覆盖负担和施术者当前状态。
仙域略强但尚不能破开保护时，仍调用常规交锋；胜负不依赖仙域数值精确相等。

显式供给使用场景 `resource_supplies`，例如：

```json
[{"owner": "immortal_npc", "source_id": "furnace", "amount": 50, "first_round": 1}]
```

双方单位必须真实存在于本场战斗。供给源被击败或镇压后，下轮停止供给；可选
`last_round` 表达持续期限。此接口不意味着普通天地灵气可以补充仙灵力。

## 结果与回写

- 有仙域/至道资格参与时，禁用只看三倍总战力的快速胜负与狩猎强制结果。
- 达到轮数上限仍未形成胜负，返回 `stalemate`，不虚构击杀、捕获或撤离。
- 领域已经完成的击杀不再掷追击概率；已经镇压的擒获目标不再掷普通生擒概率。
- `capability_updates` 保存资源与单位后果；`voisinage` 轮次记录保存覆盖、保护者、控制者、
  对抗强度及资源，供战报解释。活动仙域本身不写进人物长期状态。
- NPC 资源回写真实记录，包括偶遇缓存中的字典，不写向临时构造的 NPC 壳。
- 后台野战和自动战争共用同一套仙域判定；不能再用独立伤亡抽签杀死仍受保护的单位。
  本场战争中被镇压的 NPC 从后续出阵名单中排除。

## 尚未定义的内容边界

道统养成与主动仙灵力转化已接入，具体道统克制表、其他三级界面的养成仍待设计。
没有改写洛天衡剧情。后续系统通过状态与能力定义接入，
不应在六维循环中新增 `if 某道统` 或 `if 某世界`。

验证覆盖 `tests/test_voisinage_combat.py` 的阶段、资格、混编保护、资源、存档及 NPC 后台场景，
`tests/test_npc_combat_lifecycle.py` 覆盖生成、按需恢复、跨界、缓存提升与真实人物回写，
并回归已有战斗、规则引擎、内容校验、战争和依赖边界测试。
