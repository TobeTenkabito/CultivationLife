# 空间裂缝、符箓与界面排斥

当前源码规则；本体仍为 1.58.0，发行包须另行构建。所有参数以 `content/world.json` 为准。

## 玩家操作

包裹面板可学习制符法，选择两份材料、法术属性与注灵者合成符箓。符纸、朱砂在普通坊市出售。自行注灵须有对应灵根并支付法力；缺少灵根时，可请同界、自由且好感不低于零的对应灵根 NPC 注灵，支付灵石。选两份同名材料也会实际扣除两份。

符箓战斗属性只有 `power`、`protection`、`assistance`、`uses`。名字、元素和启用标记是身份及操作信息。新符默认停用；战斗开始依次调用威力、防护、辅助，非零属性每调用一次消耗一次次数，单项战斗增益最多 8%。轮次复用已计算的增益，不重复扣次数。护持预览不扣次数，真正进入裂缝才调用防护。

地图面板显示裂缝位置、剩余年数、护持要求及当前评分。普通裂缝每 120 年有 55% 概率刷新，同一空间最多保有三条，持续至少 800 年，且不短于最长行动单位加 100 年。护持评分为符箓防护 × 0.65 + 随身阵法生势 × 0.35；不足会立即死亡，界面明确提示。通过后按 25:30:45 抽取秘境、界面通道、本界随机地图。正常地图的随机落点忽略通常的境界准入危险；裂缝本身的护持判定仍然生效。

不世秘境无界面修为上限。修炼机缘为基础收益六倍，魔修在此免除自然修炼折损；寿元、魂蚀、突破和雷劫仍然结算。外界市场、人物、组织等操作被服务端拒绝，界面也隐藏外界入口。可以使用随身物品、制符、调整阵法和功法。每隔 160 年有 35% 概率重新开缝，可能多次不开放；化神后期（五阶七层）可消耗四分之一法力上限自行开缝。自行开辟的裂缝无额外护持门槛，去向仍随机，也可能继续留在当前空间。

界面通道为单程，不校验原有飞升等级；抵达后的界面排斥依然生效。失落界面为零级，可生成多个，第一次进入才生成地图、宗门、人物、功法和材料并保存。可探索、拜入当地宗门、交流及委托注灵。当地自由 NPC 由实例自己的权威人物表管理，仍有寿元和雷劫；离开后暂停该实例模拟。在普通界面中，九阶真实修为且已秘法压制至八阶九层以内，可随机下界或定向重访；身处独立空间不能借此入口绕过裂缝离开。没有“删除旧实例”的自动清理规则。

所有实例专属物品及功法使用 `SPATIAL_` ID，不加入全局内容目录、商店或赠予目录。探索取得的物品可以携带离开并炼化为机缘，外界不能生成它们。生成定义、获得记录和随机状态随存档保存。

## 境界边界

- 人界自然修炼仍止于化神初期（三层）。空间节点是提前偷渡的途径，不是正常飞升的前置。
- 未压制的五阶七层及以上道果，在一级界面视为突破或运转时显露超限力量，按道途立即排斥至相应上界。儒释道前往灵界、魔修前往真魔界、鬼修前往地府、妖修前往妖界；九阶及以上直接匹配三级界面。
- 秘法真正压制到五阶九层以内，可在一级界面停留；二级、零级容纳至八阶九层。收敛气机只改变外观，不能代替压制。解除压制会恢复真实修为并重新判定排斥。
- 普通下界入口要求先施展压制秘法；恢复修为请使用秘法面板的“解除”。既有封印返界及商盟专用通道保留各自转换契约。
- 控制台设置境界同样经过排斥规则，只作用于独立调试副本。正在处理事件、劫战时先完成当前流程，再判定边界。

## 开发边界与工具

`system/spatial.py` 管理存档内实例和隔离策略；`system/talismans.py` 管理四维符箓；`system/world_boundary.py` 纯判定去向。`engine/actions/exploration.py` 通过冻结的 `ExplorationDependencies` 接入保存、展示、时间和跨界，不新增 Mixin。两个静态 world profile 仅提供底层数值和兼容落点，随机地图和人物不写入全局注册表。

公开命令在既有串行事务内携带命令上下文，`_load` 使用独立空间操作白名单阻断外界交互。新增个人操作须明确纳入白名单，并验证 HTTP、直接引擎调用与 Agent 三条路径；不能只隐藏按钮。实例时间复用公共年度入口和 `advance_elapsed_year`，不能另写跳年结算。新增随机世界系统不要让普通世界初始化遍历生成其内容。

控制台、HTTP、CLI 和 MCP 共用以下具名操作，沿用正式费用和门槛：

```text
game view /talismans
talisman action learn ward
talisman action craft ward talisman_paper talisman_cinnabar metal
game view /spatial
spatial action open
spatial action enter rift_1
spatial action explore
spatial action descend
spatial action descend lost_2
```

ID 以当前 `game view` 返回为准；结构化调用推荐使用具名参数，例如 `{"command":"talisman action","arguments":{"action":"craft","method_id":"ward","material1":"talisman_paper","material2":"talisman_cinnabar","element":"metal"},"session_id":"..."}`。写操作的修订号和幂等键约定见 [Debug 文档](debug-development.md)。

回归入口：`tests/test_spatial_talismans.py`、`tests/test_royal_factions.py`；界面验收：`python tests/browser_spatial_royal.py`。另须运行现有跨界、时间、DLC 隔离、模块依赖和控制台测试。
