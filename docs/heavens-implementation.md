# 诸天实装进度：M1 法则天海

2026-10-05，依据[诸天系统策划案 V0.5](诸天系统与跨界战争_策划案_V0.1.md)推进 M1。源码提供法则天海本地调查、真实人物合作、有限参悟及维护闭环；异象、跨界迁移和战争仍留在后续阶段。开发存档结构为 **9**，发行版本仍为 v1.59.2，未重新打包发行。

## 进入玩法

六主题侧栏都有“诸天”入口。新建角色默认允许发现联系，旧档迁移仍只增加空容器，不自动开启；可在面板勾选“允许发现新的诸天联系”。满足未受控、未压制的九阶以上修为后，到仙界 `law_sea` 法则天海体察。生成关闭后不产生新对象，已建立的联系、期限和托管继续处理。

| 行动 | 实际耗时与成本 | 结果 |
| --- | --- | --- |
| 体察潮汐 | 20 年，无新增费用 | E1 当期观测 |
| 查证旧碑 | 30 年、10000 灵石 | E2 本地应用依据 |
| 对照抄录 | 20 年、20000 灵石，观澜散人在场且未被占用 | E3 合法抄录；支出进入本联系的合作项目账目 |
| 登记参悟 | 零年、无即时奖励 | 随后实际普通修炼获得额外收益，最多覆盖登记时的一整个行动单位 |
| 维护节点 | 50 年、20000 灵石、一个闲置九阶普通阵材实例、开始时实付法力上限的 5% | 本地窗口延长 600 年，允许本周期第二次参悟 |

E1＋E2 的额外收益为合法普通修炼原收益的 10%，累计上限 2% B；取得 E3 后为 15%，上限 3% B。B 在本周期第一次登记时锁定为当时有效境界的 `opportunity_base`。维护后的第二次参悟共用上限。每年把额外项与原收益合并，调用一次原有机缘入口；仙痕与气经验不额外结算。没有合法普通修炼收益时不凭空发奖。

开始动作前可预览时间、费用、材料、退款与已知期限；新命令确认后才扣费和推进。待处理事件会暂停短活动，处理事件后用下一序号继续，也可取消。费用按累计实际进度支出；取消退未耗灵石与未耗材料，已过时间和实付法力不退。维护开始即占用当期一次维护机会，取消不会补回该机会。完全未执行的参悟登记取消后退回次数，已有实际修炼则保留已用次数与收益。

## 时间、人物与持久事实

诸天年度入口仅位于 `GameEngine._advance_world_year` 的既有普通／独立空间年度返回之后，包括返回 false 和死亡。原年度顺序不变，不使用语义事件订阅，不重复魂蚀。已处理序号独立于身体年龄，同一序号重放不重复处理。

法则天海首次生成时固定 T0；旧碑记录为 T0−4000、T0−2000，每周期 2000 年，原窗口前 1200 年可用。刷新面板不重写年代。维护只延续本地余韵，最迟至当期 1800 年。下周期保留 E2／E3、项目账目和人物身份，清空当期应用与维护预算，须重新完成 E1。

观澜散人是保存于现有权威人物容器的本界九阶散修，以 NPC ID 引用，并保存 `location_id=law_sea`。原普通年度负责成长；合作核验生存、拘禁、地点、队伍、势力、独立空间和旧战争名册。人物离开或死亡不重建，已取得证据仍保留。被引用的人物记录受名册清理保护。

个人发现每实际 100 年检查一次，以真实境界概率和独立 SHA-256 计数随机流求值；没有符合条件的已实现内容时记录检查窗口，不消费旧 RNG。目前只支持法则天海一项联系。默认只通知；“完整修行单位结束时停下”为额外主动设置。旅行、短活动、归墟和独立空间不在诸天通知中间强制停下。

短活动每段锁定当时单位年数，以约分后的分数累积 `unit_credit`，只有完整单位进入公共收尾。20＋30＋20 年在九阶留下 7/10 单位；升境后不会追溯改算旧余量。年度系统、魂蚀和机构实际年数照常运行，零完整单位不发工资、不推进单位市场、不发普通修炼奖励。单条耗时命令最多执行 100 个实际年，任务暂停后由新命令续做。

## 存档、接口与恢复

8→9 的纯迁移仍只加入 `{}`，支持 6→7→8→9。旧档第一次启用建立子协议 1 的日历、随机计数、短活动余量及有限容器。法则天海首次生成保存定义快照与版本，后续内容修订不追溯重写已有实例。

本阶段最多一个现象与一名新增合作人物，同时一项亲自任务；保留最近四项任务、三条通知、128 条纪要和 128 份命令回执。已获取证据、项目账目与人物引用独立保留。解码和保存校验版本、字段、数值、容量、周期、人物引用与阵材重复所有权，损坏时拒绝覆盖原文件。

| 正式引擎入口 | POST 路由后缀 | 用途 |
| --- | --- | --- |
| `heavens_view` | `heavens-view` | known / opportunities / tasks / history，纯投影 |
| `heavens_preview` | `heavens-preview` | 纯报价与当前修订 |
| `heavens_command` | `heavens-command` | 连续 `command_seq`、`expected_revision`、动作、对象、有限选项 |

动作包括 `configure`、`dismiss`、`observe`、`check_history`、`exchange`、`attune`、`maintain`、`resume`、`cancel`。关注设置通过 `configure.options.watch` 修改，暂停选项为 `pause_on_opportunity`。研究目标为 `sea_echo`，继续／取消任务使用返回的任务 ID，交流与维护分别要求权威 `person_id` 与唯一 `material_id`。不接受自报收益、期限、费用或任意状态补丁。

整个准备态深拷贝后执行，费用、NPC、旧随机流、新随机流、任务、日历及回执同段原子保存；成功后才发布请求缓存，失败失效缓存并保留原档。相同序号和规范化参数先读取原回执，再检查当前资格，因此窗口结束、人物死亡或内容开关变化不会让重试再扣费。不同参数复用同序号拒绝，过期回执不重新执行。普通修炼沿用原 API 提交语义。

面板、HTTP 与 Debug 使用同一正式能力。受控状态与独立空间仍可读取、设置和清理托管，耗时参与由领域资格阻止。Debug 示例：`heavens preview observe '{}' sea_echo`；命令序号与修订须取诸天视图，不能使用调试会话修订。诸天查询对准备态纯读，原加载流程仍可能执行旧系统补全。

## 验收记录

- [M0 契约测试](../tests/test_heavens.py)与[M1 专项测试](../tests/test_heavens_m1.py)：实际时间、证据路径、单次收益、托管、取消、人物死亡／移动／占用、周期、独立空间、参考完整性、精确余量、重试和存盘失败恢复。
- [浏览器验收](../tests/browser_heavens_m1.py)：六主题 × 1440／393 像素，预览不写档，模拟服务器提交成功但响应丢失后重试，无重复耗时。截图与报告位于 `build/heavens-m1-browser/`。
- [关闭态回放](../tools/replay_heavens_m0.py)：与改动前源码的 78 个检查点一致。只归一化结构 8→9、空诸天存档、框架定位文案、新增纯诸天视图和独立空间的诸天面板入口；资源、人物、旧日历和随机流不归一化。
- [性能测量](../tools/benchmark_heavens_m1.py)：三个固定种子输入、每组十次关闭／开启对照，每次完整 500 年普通修炼。为保证完整长度，两侧均禁用归墟弹窗中断，保留其他年度模拟与结算。记录中位耗时、纯视图 P95 和状态字节数；详见 `build/heavens-m1-benchmark.json`。

三组性能测量全部达标：未接触、已有证据、128 条纪要及四项历史任务三组的 500 年中位新增耗时分别为 −266.2／99.6／48.6ms（负值属于运行噪声）；最高相对新增耗时约 1.02%，低于 20% 门槛。纯视图 P95 最高 1.45ms，新状态最大 39723 字节。完整回归首轮为 2410 项通过、2 项失败：旧迁移夹具遗漏移除新字段，以及运行中更新源文件导致 `inspect.getsource` 行号错位。夹具已修正，源码稳定后两项定向复验通过，日志为 `build/heavens-m1-failures-resolved.log`。最终诸天专项在默认扩展环境与无 DLC 环境各 62 项通过（包括累计完整单位后的真实公共结算），197 项调试回归通过，8 项引擎依赖测试通过。原生九阶人物初始化补齐后的专项和浏览器亦已复验。首轮完整日志保留于 `build/heavens-m1-pytest.log`，不将其表述为一次全绿运行。未验收 Android 或发行二进制，未生成新的发布包；M2、M3 仍未实现。
