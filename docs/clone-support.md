# 分身类别与高阶劫战

2026-11-15首批：按当时用户要求，只接入分身类别、培养与战斗，暂不实装获取方式。首批不添加炼制、购买、兑换、事件投放或自动赠送；后续按用户新要求增加《临岚天魔功》的明确秘术获取，见[风岚与霜剑](wind-frost-techniques.md)。

## 原状态与培养

分身为 `Player.puppets` 中 `type=clone` 的独立资产，与机关、炼尸、活傀并列；不是师承中的“身外化身”，也不是第二元婴。使用原资产唯一 ID、修为、炼体、神识、主修功法、战力、完整度 `durability` 和能源记录；不复制玩家或 NPC，不另造人物／库存／元力池。

复用 NPC 培养窗口，以“分身”标记目标。修为、炼体、神识、丹药培养减耗、主修传授、能源更换沿原傀儡结算。沿原门槛、灵根、实际材料与机缘收费；培养不恢复完整度或能源，不赠 NPC 专属邻域与肉身神通。普通机关与炼尸仍不能学习人物功法。分身不开放吞噬，不追加新按钮。

分身不写入 `Player.party`，不占普通队友名额。普通出战按自身原战力加入独立单位；单挑等原有禁援场景仍禁入。能源沿原阶差、有限耐久、玩家垫付开关与实际余额，不能透支。已毁坏、封印／压制、神游或超过本界承载时不得参战；未知界面及独立空间不兜底为普通世界。

2026-11-15用户明确战力口径：分身的自身战力只用于该分身实际参战，不计入玩家本体战斗力与组队战斗力，也不改变依赖这两项汇总数值的门槛。携带、培养、能源耗尽、损毁或移除分身均不影响两项汇总；实际战斗仍使用原分身的战力、能源与损伤。原计算入口已经排除分身，本次将分身投影的 `battle_contribution` 与比例明确设为0，卡片保留自身战力并说明独立参战，撤销易被误读的“100%贡献”。不改变机关、炼尸和活傀的原贡献规则。

口径复核：35项分身专项通过，覆盖有／无其他傀儡时携带、培养、耗尽、损毁、移除分身对本体与组队汇总及公开面板的隔离；实际普通战与劫战继续参战。双主题、三种尺寸下真实切换御傀子页核对可见文案与无横向溢出，原培养流程亦通过；三项开发门禁通过。证据：`build/clone-power-tests.log`、`build/clone-power-browser.log`、`build/clone-browser/power-*.png`。

## 分身视觉

2026-11-15按用户要求，分身头像、培养立绘、御傀卡片和完整人物卡以原形象为底图，统一采用62%不透明度、青蓝偏色与轻度虚化；头像使用较弱模糊，保持小尺寸可辨识。战斗沿已有 `ActorVariants` 渲染分支添加同色系半透明灵影，覆盖待机、攻击、受击、防御及败退动作；只处理分身所在图层，不把本体、敌人或DLC界面一起染色。不是直接复制玩家原样立绘，不写入或覆盖原PNG与动作图集，不添加获取渠道。

原人物性别、种族、道途与形态筛选继续决定底图，不为未知形态强配人形；独立分身投影以 `visual_variant=clone` 标记，既有镜像劫相各自的色调不变。特效无闪烁和额外循环动画，在减少动态模式下仍显示透明、偏色与虚化。此为只读视觉，重看／重播不改变战力、资源、随机数和存档。

视觉验收：分身专项、战斗回放与修罗形象测试共82项通过；双主题三种尺寸下查看培养图、完整立绘、头像及真实战斗回放。浏览器验证 Canvas 中心透明度、蓝色色偏、柔化边缘以及上下文恢复，普通人物仍保持原色与不透明度；回放前后存档字节相同。三项开发门禁通过。证据：`build/clone-art-tests.log`、`build/clone-art-browser.log`、`build/clone-browser/figure-*.png`、`build/clone-browser/combat-*.png`。

## 高阶劫战的明确例外

用户明确授权“分身可以用于高阶劫战”，因此允许当前本人随身的九阶及以上分身进入仙界人五衰、天五衰、斩三尸、邻域反噬，修罗劫战／八部融合，以及幽冥、轮回的大境界劫战。责任入口为 `system.clone_support.units` 和三族劫战初始化；普通同行、师承化身、机关、炼尸与活傀继续被这些入口排除。

参与者仍是原资产，在当前原世界／地点就地参与，不移动、复制或远程召入。劫战时间与费用沿原入口；战中每次实际攻击沿原能源结算。敌方镜像只读取玩家本体，不复制分身，也不因携带分身提高敌人属性。

原 `active_trial` 保存分身参战快照及有限六属性贡献。每轮依实际存续、控制和出手资格读取贡献；能源不足不能留下免费攻击加成。各次请求结束后将剩余能源与完整度回写同一资产，损失不能靠续战、读档或培养清除。完整度归零／被击毁后不可出战。玩家本体死亡仍判劫战失败，不能靠分身替代过关。劫战中不得培养、换能源、换主修或解除控制。

## 跨界与验证

无跨界移动例外：分身沿原傀儡随身资产的保留／遗失规则，不享受第二元婴永久飞升随身特例；无新顶层存档字段，无旧档迁移或历史补发。原师承身外化身不转换为分身。

专项 `tests/test_clone_support.py` 覆盖培养和资源守恒、普通名额、高阶各路线初始化、敌方镜像不放大、耗尽停手、真实劫战结算、快照续战与旧类别拒绝。四道途经真实加载、事件提交和续战验证，并核对战报动画名单包含原分身 ID。浏览器沿原 NPC 培养窗口验收。

2026-11-15 验证：33 项分身专项、318 项既有战斗／培养相关回归、119 项跨界及旧事件回归通过（去重合计470项，非全仓回归）。额外复核4项真实劫战动画名单通过。`browser_clone_support.py` 验收双主题与桌面／竖屏／横屏、实际培养／换能源／传授及过期请求拒绝；`browser_events_212.py` 验收旧事件、后续奖励、过期页面恢复及仍应禁用的控制。三项开发门禁通过。证据位于 `build/clone-final-tests.log`、`build/clone-domain-regression.log`、`build/clone-world-regression.log`、`build/clone-visual-events.log`、`build/clone-browser/`、`build/clone-events-browser.log`；领域批次首次运行的4项新测试夹具断言已由专项复跑修正并全部通过，既有318项无失败。

发现并修复：修罗与妖鬼镜像此前复制玩家的护持 ID，加入分身后可能将己方分身当作护持对象；现镜像清除玩家护持名单。劫战期间的旧御傀操作同时复核 `active_trial`，不能在待选事件异常缺失时解除正在战斗的原资产。未修改版本号或生成发行包。
