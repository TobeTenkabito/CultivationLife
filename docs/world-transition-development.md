# 跨界开发规范

本规范自 v2.1.1 起执行。制定依据是[当前跨界审计](world-transition-audit.md)，不是把现有实现直接视为正确规则。适用于本体、DLC、剧情、诸天、商盟、空间、自动人物行为以及控制台调用。

## 1. 先确定行为语义

跨界描述必须包括：谁移动、源地址、目标地址、移动方式、授权、人数或载荷、时间、资源代价、成功与失败结果。地址为 `(world, instance_id, location_id)`；`lost`、`rift` 是空间类型，不是唯一地点。远程打听、通商、援助和宣战不等于玩家移动。

方向由内容配置的界面层级计算，不能根据名称或修为猜测。人界与魔界为第一层；灵界、真魔界、妖界、幻冥界、地狱界为第二层；仙界、修罗界、幽冥界、轮回界为第三层。特殊空间不套用主界面的社会规则。

| 方式 | 语义 | 必须保持的区别 |
| --- | --- | --- |
| `progression` | 经过特定道途门槛或劫关，永久离开原社会组织 | 可以触发已有离宗、随行筛选、傀儡遗失规则；不能由“向上移动”自动推断 |
| `sealed_descent` | 有资格的压制下界 | 保存真实道果、原界及劫期余额；显露境界受目标法则限制 |
| `sealed_return` | 沿封印记录返界 | 只允许回到该封印登记的原界；不得用任意目标解除封印 |
| `passage` | 商盟逆灵通道 | 验证总部、职衔、路线、费用；凭证和影响力仍归原总部 |
| `study` | 最高界面之间的个人访学 | 人数、通道占用、具体地点、已付经费、实际进度和返程预留全部校验 |
| `story` | 有明确授权的专用路线 | 必须在内容中登记；不允许以此作为万能传送。现有用途是祖兽梦径与撤销旧商路后的封印护送 |
| `rift` | 随机空间通行及有限异象进出 | 不附送境界、不套用飞升离宗清理；护持、实例和落点按空间规则处理 |
| `expulsion` | 显露修为超过本界承载而被排斥 | 与玩家主动飞升区分；由修为边界统一判定，道途决定去向 |

系统自动发起的界面战争仅允许同层级；玩家主动行动不受这一战争限制。该豁免不等于免除路线、资源、封印和落点规则。

## 2. 统一执行边界

玩家移动必须经 `WorldTransitionRequest → plan_world_transition → apply_world_transition → finish_world_transition`。新增调用应显式填写方式及原因；`_plan_world_transition` 的历史默认值不能作为新接口设计依据。

规划只读：不能扣款、投骰、移动人员、改封印、填充事件或刷新市场。玩法在自己的命令事务中验证资格、结算真实时间与代价；如果期间发生死亡、事件中断、人员离开、路线撤销，应停止或按既定失败规则结算。落地前重新验证条件，不能拿多年前的预览直接提交。

提交前核对源界、源实例、源地点、修为和封印快照。失效必须在拍卖退款、清理和移动之前拒绝。提交负责社会状态切换、人员转移、封印和地址变更；玩法只在授权范围内追加劫关升阶、剧情奖励等结果。最后执行必要的修为排斥判断与目的地刷新，再持久化和呈现。

预览、正式执行、Debug 工作台必须复用同一业务入口。服务器负责验证，按钮可用性只是投影。请求锁和单档保存提供事务边界；预览不得写档，失败不得留下半套持久状态。具有必死风险的强渡是已声明的玩法结果，必须在执行前说明，不能伪装为校验错误。

## 3. 状态归属与迁移矩阵

[完整字段合同](world-transition-state-contract.json)逐一列出 Player 与 GameState 字段。新增字段必须人工判断属于下列哪类，并增加跨界测试；不能因为暂时没人访问就认定安全。

| 状态类别 | 通行时规则 | 主要检查 |
| --- | --- | --- |
| 身份、根骨、道途、血脉、性别、真实成长 | 跟随同一玩家保留 | 空间落地不改变真实境界、不额外长寿、不重抽血脉 |
| 个人资源与已得成长 | 库存、机缘、煞气、因果、神识、炼体、仙痕、本命物保留，扣除已声明成本 | 不因更换主界面重复奖励、恢复资源或重建材料实例 |
| HP/MP 与法则适配 | 普通移动保持相对损耗；目标环境和仙灵力可用上限立即生效 | 飞升劫关的升阶恢复须由劫关明确处理；随机抵达仙界不等于完成飞升转化 |
| 修为封印与秘法压制 | 分别保存与校验，不相互冒充 | 原始层数、寿元、返界地址、劫期余额不可被二次封印覆盖 |
| 威名及族群敌意 | 按实际界面／空间实例存放，首次到达默认零，返回恢复原值 | `fame` 和当前 `race:*` 是当前作用域的活动值；不能用它们向另一界直接签发追杀 |
| 宗门、家族、全界敌意及追杀 | 原实体记录保留，只在主体存在且可触及时生效 | 唯一势力 ID 不等于全局种族 ID；远方仇敌不得无视所在界直接接战 |
| 人际关系、随行、俘虏 | 区分“仍有关系”“在同界”“加入队伍”“实际通行” | 使用权威人物身份；永久离界按已有随行清单处理，临时通行不复制人物；拘禁限制由路线入口校验 |
| 宗门职位、机构、商盟、影响力 | 任职记录与地理权限分开 | 临时离界不抹掉履历，也不能在异界使用原驻地权限；永久离界办理既有交接 |
| 战局、委托、诸天任务、归墟会话 | 留在所属系统和地点，由系统决定暂停、继续、失败或退费 | 不随玩家改写任务目的界，不复制任务本金，不把跨界当完成条件 |
| 地产、驻地、灵田、地面阵法 | 宿主字段在 Player 上也不代表能携带建筑 | 使用系统已声明的地理归属；不能将世界资源当玩家背包迁移 |
| 市场、拍卖、遭遇与展示缓存 | 目的地重新投影；跨界取消未完拍卖并按原规则退款、退货 | 黑市已交割物不可二次返还；独立空间不得展示外界坊市 |
| 历史、已知情报、里程碑 | 保留真实记录，按可见性展示 | 原始内容与投影分离；五级消息不能只在 CSS 隐藏详情；商盟报告为购买时快照 |
| 所有时钟与随机序列 | 移动本身不凭空推进／重置 | 年龄、肉身年龄、魂蚀、劫期、行动次数、世界年度、任务工期各有所有者；只结算实际经过的时间 |
| 仙灵力转化 | 保留阶段；仙界等待在离界期间暂停，返界续算 | 不能在低界等多年后瞬间获得仙界转化机会 |
| 即时交互次数 | 当年每种一次，随档持久化 | 读档、切界和换页面都不能刷新 |
| 临时事件与战斗 | 活动劫关、事件、关押、附身控制由入口明确约束 | 事件中授权的转场由该事件结算；普通移动不能逃避正在结算的战斗 |

个人历史和离界记录与“当前本地可操作对象”必须分开。任何跨界功能都要审阅相应系统的读、写、年度钩子、UI 和控制台，不能只修改移动函数。

## 4. NPC、运输、情报和实例

NPC 必须使用 `system/combat/npc_lifecycle.move_world` 结算旧环境资源，再切换世界并登记新环境速率；使用玩家年龄代表的世界时钟，禁止把 NPC 生理年龄代入。移动后更新地点、实例名单和任务占用，引用仍指向同一人物。

人物迁居、访学、战地输送需要真实人员、路线许可和进度；族群、势力迁移还要更新本地权限与驻地。货运只转移真实库存和所有权，不隐含玩家或随行人移动。商盟情报中继只传递消息，不为押运、实物采购或玩家通行创建路线。

独立空间必须明确当前实例；离开清除当前指针但保留可重访实例。不同 `lost` 实例之间也是移动。空间节点目的地在生成时绑定并隐藏；打开界面、预览和读档不得重抽。探测若将来加入，应有独立授权和代价，不能从未授权 API 字段泄漏终点。

## 5. 有限例外

仅下列行为不是正式玩家通行：新游戏首次建立地址；纯数据结构迁移；隔离 Debug 快照编辑／恢复。它们不得触发正常通行收益，也不得直接写用户其他存档。未知内容或未知界面必须拒绝并保留文件，不能通过“纠正”传送到人界。

已登记的剧情护送仍使用正式提交入口，只豁免该剧情明确承担的费用。通常不得新增例外。确需新增时，在本节注明理由、最小范围、调用者、失效条件、正反向测试和防滥用证据，不能只留下 `special_case=True`。

## 6. 合并与发行检查

1. 更新入口清单、路线和字段合同，说明实际去向及每项改变的状态。
2. 执行 `python tools/check_world_transition_contract.py`；它枚举 AST 调用、写入、配置路线及字段，禁止已识别玩家别名在正式边界外写 `world`。它不是完整别名分析，动态快照写入仍须人工审查。
3. 执行模块依赖和文档检查，以及跨界、空间、受控人物、委托、诸天和改动领域测试。
4. 至少验证初访／返访、正向／反向／同阶、不同修为、封印与解封、当前事件或拘禁、无钱或通道失效、随行／俘虏、不同空间实例、旧界仇恨、未转化法力、任务中断与存读档。
5. 比较前后持久状态：允许变化的字段及其原因必须可解释，其余保持；失败校验必须不消费 RNG、不扣费、不移动人、不返还拍卖。
6. 正式包完成相同入口的浏览器及双端验证，禁止用只改按钮文案的测试替代后端行为测试。
