# 跨界开发规范

2026-11-11修罗军政：本体 `institution_garrisons` 占用原人物，原道路规划复用于 `military_movement`，仅同界原三城与万战城，无跨界军用许可。在途保持原出发地址，按实际年抵达再登记目的地，折返按已走路程耗时；拘禁、离场或实例变化不强制移回。原组织不能同时参加其他战役。起兵是独立争位授权，原址举兵、原人支持、实款、实际到场、原战斗与旧王身份比对均核验，原逐级血战资格不变。军费为服务预付款，非遥取实物。见[军政实施](asura-military-and-succession.md)。

2026-11-11地方议事授权：通用公署在任许可允许原址调整公开使用权，并在公署未公开时进入；责任入口为 `building_projects.set_public`、`buildings.can_enter`，逐次校验原任职、原建筑ID、产权、固定地址与到期。NPC经原BuildingActor验证自由、实际到场及占用。没有添加永久users或转移产权，撤权立即失效。修罗预算／续任只可在王庭裁决，地方案须原址办理；原署损毁仅开放原城市许可下的工程请款、公款和在办项目交接。验证见 `test_asura_politics` 及真实页面 `browser_asura_politics`，详见[实施记录](asura-politics-and-disputes.md)。

2026-11-11总督府授权：本体 `institution_authority.can_repair` 只授予原在任人对登记公署的重建权，产权须仍与原机构一致；原址和费用由建筑入口复验。修罗适配只为配置列出的三座原背景城市授权设府，不从公开访问权推导占地权。停用专属功能保留本体原资产访问及依法自费修复，不开放公款支取；原款只可交接上缴。无新增移动、跨界或空间例外，验证见 `test_institution_authority`、`test_asura_governorship` 与[实施记录](asura-governorship-implementation.md)。

本规范自 v2.1.1 起执行。制定依据是[当前跨界审计](world-transition-audit.md)，不是把现有实现直接视为正确规则。适用于本体、DLC、剧情、诸天、商盟、空间、自动人物行为以及控制台调用。

## 1. 先确定行为语义

跨界描述必须包括：谁移动、源地址、目标地址、移动方式、授权、人数或载荷、时间、资源代价、成功与失败结果。地址为 `(world, instance_id, location_id)`；`lost`、`rift` 是空间类型，不是唯一地点。远程打听、通商、援助和宣战不等于玩家移动。

方向由内容配置的界面层级计算，不能根据名称或修为猜测。人界与魔界为第一层；灵界、真魔界、妖界、幻冥界、地狱界为第二层；仙界、修罗界、幽冥界、轮回界为第三层。特殊空间不套用主界面的社会规则。

| 方式 | 语义 | 必须保持的区别 |
| --- | --- | --- |
| `progression` | 经过特定道途门槛或劫关，永久离开原社会组织 | 可以触发已有离宗、随行筛选、傀儡遗失规则；不能由“向上移动”自动推断 |
| `sealed_descent` | 有资格的压制下界 | 保存真实道果、原界及劫期余额；显露境界受目标法则限制 |
| `sealed_return` | 沿封印记录返界 | 只允许回到该封印登记的原界；不得用任意目标解除封印 |
| `passage` | 商盟逆灵通道 | 验证总部、职衔、路线、费用；凭证和影响力仍归原总部 |
| `study` | 最高界面之间的个人访学 | 人数、通道占用、具体地点、已付经费、实际进度和返程预留全部校验 |
| `expedition` | 原势力批准的民用开拓往返 | 三层普通界面的17组同层双界；每组固定落点、双向共用单人容量。原组织与目的界分别签文书，原文书、实际修为、工时、界层费用和已付返程均校验，不授予研究或军事输送权限，见[同层开拓](heavens-outposts.md) |
| `story` | 有明确授权的专用路线 | 必须在内容中登记；不允许以此作为万能传送。现有用途是祖兽梦径与撤销旧商路后的封印护送 |
| `rift` | 随机空间通行及有限异象进出 | 不附送境界、不套用飞升离宗清理；护持、实例和落点按空间规则处理 |
| `expulsion` | 显露修为超过本界承载而被排斥 | 与玩家主动飞升区分；由修为边界统一判定，道途决定去向 |

系统自动发起的界面战争仅允许同层级；玩家主动行动不受这一战争限制。该豁免不等于免除路线、资源、封印和落点规则。

## 2. 统一执行边界

玩家移动必须经 `WorldTransitionRequest → plan_world_transition → apply_world_transition → finish_world_transition`。新增调用应显式填写方式及原因；`_plan_world_transition` 的历史默认值不能作为新接口设计依据。

规划只读：不能扣款、投骰、移动人员、改封印、填充事件或刷新市场。玩法在自己的命令事务中验证资格、结算真实时间与代价；如果期间发生死亡、事件中断、人员离开、路线撤销，应停止或按既定失败规则结算。落地前重新验证条件，不能拿多年前的预览直接提交。

提交前核对源界、源实例、源地点、修为和封印快照。失效必须在拍卖退款、清理和移动之前拒绝。提交负责社会状态切换、人员转移、封印和地址变更；玩法只在授权范围内追加劫关升阶、剧情奖励等结果。最后执行必要的修为排斥判断与目的地刷新，再持久化和呈现。

预览、正式执行、Debug 工作台必须复用同一业务入口。服务器负责验证，按钮可用性只是投影。请求锁和单档保存提供事务边界；预览不得写档，失败不得留下半套持久状态。具有必死风险的强渡是已声明的玩法结果，必须在执行前说明，不能伪装为校验错误。

## 3. 状态归属与迁移矩阵

[完整字段合同](world-transition-state-contract.json)逐一列出 Player 与 GameState 字段。新增字段必须人工判断属于下列哪类，并增加跨界测试；不能因为暂时没人访问就认定安全。

| 状态类别 | 通行时规则 | 主要检查 |
| --- | --- | --- |
| 身份、根骨、道途、血脉、性别、真实成长 | 跟随同一玩家保留 | 空间落地不改变真实境界、不额外长寿、不重抽血脉 |
| 个人资源与已得成长 | 库存、机缘、煞气、因果、神识、炼体、仙痕、本命物保留，扣除已声明成本 | 不因更换主界面重复奖励、恢复资源或重建材料实例 |
| HP/MP 与法则适配 | 普通移动保持相对损耗；目标环境和仙灵力可用上限立即生效 | 飞升劫关的升阶恢复须由劫关明确处理；随机抵达仙界不等于完成飞升转化 |
| 修为封印与秘法压制 | 分别保存与校验，不相互冒充 | 原始层数、寿元、返界地址、劫期余额不可被二次封印覆盖 |
| 威名及族群敌意 | 按实际界面／空间实例存放，首次到达默认零，返回恢复原值 | `fame` 和当前 `race:*` 是当前作用域的活动值；不能用它们向另一界直接签发追杀 |
| 宗门、家族、全界敌意及追杀 | 原实体记录保留，只在主体存在且可触及时生效 | 唯一势力 ID 不等于全局种族 ID；远方仇敌不得无视所在界直接接战 |
| 人际关系、随行、俘虏 | 区分“仍有关系”“在同界”“加入队伍”“实际通行” | 使用权威人物身份；永久离界按已有随行清单处理，临时通行不复制人物；拘禁限制由路线入口校验 |
| 宗门职位、机构、商盟、影响力 | 任职记录与地理权限分开 | 临时离界不抹掉履历，也不能在异界使用原驻地权限；永久离界办理既有交接 |
| 战局、委托、诸天任务、归墟会话 | 留在所属系统和地点，由系统决定暂停、继续、失败或退费 | 不随玩家改写任务目的界，不复制任务本金，不把跨界当完成条件 |
| 地产、驻地、灵田、地面阵法 | 宿主字段在 Player 上也不代表能携带建筑 | 使用系统已声明的地理归属；不能将世界资源当玩家背包迁移 |
| 市场、拍卖、遭遇与展示缓存 | 目的地重新投影；跨界取消未完拍卖并按原规则退款、退货 | 黑市已交割物不可二次返还；独立空间不得展示外界坊市 |
| 历史、已知情报、里程碑 | 保留真实记录，按可见性展示 | 原始内容与投影分离；五级消息不能只在 CSS 隐藏详情；商盟报告为购买时快照 |
| 所有时钟与随机序列 | 移动本身不凭空推进／重置 | 年龄、肉身年龄、魂蚀、劫期、行动次数、世界年度、任务工期各有所有者；只结算实际经过的时间 |
| 仙灵力转化 | 保留阶段；对应上界主动支付机缘推进，旧年进度仅抵扣当前阶段费用 | 离界等待、旧事件和读档不能免费推进阶段 |
| 即时交互次数 | 当年每种一次，随档持久化 | 读档、切界和换页面都不能刷新 |
| 临时事件与战斗 | 活动劫关、事件、关押、附身控制由入口明确约束 | 事件中授权的转场由该事件结算；普通移动不能逃避正在结算的战斗 |

个人历史和离界记录与“当前本地可操作对象”必须分开。任何跨界功能都要审阅相应系统的读、写、年度钩子、UI 和控制台，不能只修改移动函数。

已触发事件的完成资格与随机事件的触发资格必须分开：加载和跨界后的状态准备不得因为修为变化，重新套用随机事件筛选条件来删除正在处理的事件。选择时校验当前事件编号、实际提供的选项及行动条件；界面收到拒绝后读取一次权威状态，禁止自动重发有副作用的请求。旧选项结构由统一事件准备入口修复；不可用内容只移除对应节点，必须保留后续奖励及其原始随机结果，并记录被移除的事件编号。独立空间遵循同样规则。

## 4. NPC、运输、情报和实例

NPC 必须使用 `system/combat/npc_lifecycle.move_world` 结算旧环境资源，再切换世界并登记新环境速率；使用玩家年龄代表的世界时钟，禁止把 NPC 生理年龄代入。移动后更新地点、实例名单和任务占用，引用仍指向同一人物。

人物迁居、访学、战地输送需要真实人员、路线许可和进度；族群、势力迁移还要更新本地权限与驻地。货运只转移真实库存和所有权，不隐含玩家或随行人移动。商盟情报中继只传递消息，不为押运、实物采购或玩家通行创建路线。

独立空间必须明确当前实例；离开清除当前指针但保留可重访实例。不同 `lost` 实例之间也是移动。空间节点目的地在生成时绑定并隐藏；打开界面、预览和读档不得重抽。探测若将来加入，应有独立授权和代价，不能从未授权 API 字段泄漏终点。

## 5. 有限例外

2026-11-08公共修持对象授权：原主动培养由私人培养关系解析对象。七曜批准的有限项目允许`court_project_offers.beneficiary`引用同地原自由道修真仙作为公共受益人，排除本人亲属、道侣、师徒，不创建私人关系。`npc_development.service.quote/apply`接受仅内部传入的原`Target`及项目`stock`，继续执行原同界、地点、实例、神识、拘管、任务、培养门槛和元力结算；专材仅从已付货单扣除，不扣玩家机缘、不恢复元力。普通HTTP培养不接受这两个参数。实际工时与预算见`court_projects`；测试验证原人物成长、目标失效与材料守恒，原培养回归验证普通权限不变。

2026-11-08仙圃承办修复许可：承办人不是产权人，若设施损毁使原付费批次暂停，只允许产权人重建将封死经营交接。`system/building_projects.quote`仅对仍附有本人`operating_lease`、产权为`yaochi/yaochi`的原产业开放`rebuild`；到期仍可自费修复以收尾。`building_destruction.rebuild`继续核验原地址并沿原价格实扣本人钱货，原批次按实际停工年延后，产权／库存／欠费／合同不重置。此许可不改变`owns`，不放宽拆毁代价、扩建或转让；没有原许可的产业仍拒绝。`tests/test_yaochi_fair.py`与真实浏览器覆盖原建筑事件摧毁后修复、付费批次续作及原产权保留。

2026-11-08地方灾后恢复：普通地仙庙务要求庙城完好；若此限制同样套在损毁庙城的重建调查上，会封死原址恢复。`system/earth_disputes.access`仅对已绑定原遗址的`rebuild`来报允许在损毁原庙／原城现场调查、执行及按原`building_destruction.rebuild`权限交付；仍要求仙界原地址、本人产权、道修真仙转化、存活、非封印、无事件／旅行／拘束。不得提前恢复助修、无权修复他人建筑或借此办其他案。撤回使用原庙恢复权限，不扣无效对象罚金。`tests/test_earth_disputes.py`覆盖原庙真实摧毁后两种方案、无效／提前交付和跨界暂停；浏览器覆盖真实加载、点击、事件中断及修复后解除忙碌。

2026-11-07神魂危机解困：副本／拘管／封印中也可能由原神魂枯竭结算引发夺舍危机，原抵御按钮与普通秘法共同禁用会堵住处理入口。`system/soul_actions.py` 的 `resistance_blocked` 为即时本魂抗争单独核验存活、待决事件及活动劫战；只有已存在危机可提交。沿原概率、死亡和第二元婴承接结算，不推进时间，不解除副本、玩家监禁或修为封印，不修改地点／实例，不开放普通秘法。空间命令白名单只放行到该领域复验，UI使用相同资格投影。`tests/test_soul_followup_audit.py` 与 `tests/browser_soul_lifecycle.py` 覆盖真实失落界面、裂缝秘境、归墟进入后的解困，失败死亡／承接、地址不变，以及普通秘法仍拒绝。

2026-11-04 NPC邻域培养差异：用户要求继续简化高阶培养。责任入口`system/npc_development/domains.py`按原配置等级与修为门槛确定性提升，不经过玩家随机参悟或另付传承工期；原仙界NPC已过修习区间先结算，`cultivated`明确主动培养资格，不再套用随机NPC稀有度上限。不得免费回满元力、移动人物或覆盖专属传承；界面、身份及拘禁规则不豁免。测试`test_npc_development_stage3.py`、`browser_npc_development.py`，详见[第三阶段](npc-development-stage3.md)。

2026-11-04 NPC成长差异登记：用户明确要求高阶简化培养。责任入口`system/npc_development/service.py`与`upper.py`允许已在对应第三级普通界面的八境圆满NPC升九境，九至十二境一轮一层、高阶肉身从零培养；不走玩家开脉和大劫，不改地址、世界时钟或已有周期劫期。低界迁界关口、封印、任务与身魂限制不豁免。扩容前结旧资源区间，不回满余额。傀儡为原资产，按后续同日用户要求优先使用实际装备能源，品阶／耐久不足且供能开启时才由同场玩家垫付MP或原元力；每次只扣一个来源，详见[傀儡能源](puppet-energy.md)。测试为`tests/test_npc_development_upper.py`及`tests/browser_npc_development.py`，规则见[NPC高阶培养](npc-development-upper.md)。此授权不新增跨界移动方式。

仅下列行为不是正式玩家通行：新游戏首次建立地址；纯数据结构迁移；隔离 Debug 快照编辑／恢复。它们不得触发正常通行收益，也不得直接写用户其他存档。未知内容或未知界面必须拒绝并保留文件，不能通过“纠正”传送到人界。

已登记的剧情护送仍使用正式提交入口，只豁免该剧情明确承担的费用。通常不得新增例外。确需新增时，在本节注明理由、最小范围、调用者、失效条件、正反向测试和防滥用证据，不能只留下 `special_case=True`。

## 6. 合并与发行检查

v2.16.1 冻结补算的有限例外：用户明确要求异界任务也全部延后，并允许当前任务与异界交易时由系统垫付钱货。责任入口为 `regional_context.py`、`engine/world/regions.py`、`economy/deferred.py` 与 `deferred_settlement.py`；原人物、原库存和原府库不复制。唯一收据登记款项、货物和年份，实款托管、垫款核销及债务均持久化；冻结目标不因付款被唤醒。历史补算不追造新自动跨界商机。个人迟到迁入只补原人物缺失年份，不重演已完成的群体战局。`tests/test_deferred_economy.py`、地区历法和综合测试覆盖不足款、收货、冻结任务、重载与重复结算。普通本地行为不享有虚空付款权限，原通行与战斗规则仍适用。
