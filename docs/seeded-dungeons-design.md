## 一、设计目标与已确定的边界

让玩家愿意冒险的理由，是一次有限、不可重刷、可能改变当前修行处境的机缘。探索的重点是判断环境、人物和机会，决定继续深入、合作、背叛、站队或撤离；奖励需要兑现这种风险。

以下按用户已经明确的要求执行：

1. 每张地图有对应的副本生成方案。同一界面内，不同地图的层次、主题与收益不同；界门古塞处于人界最高档。
2. “不漏”指避免重复以前探索过的文本，不代表到达地图就保证发现副本。
3. 副本与掉落由种子决定。NPC 发出邀请时，目标副本已经确定，不能通过读档、重新收信或开关页面刷新。
4. 普通、稀有、史诗、传奇四档在生成时随机判定。限制单地图可进入的副本总量；另按每个界面分别限制传奇生成次数。传奇同时受概率与次数约束，不给每张地图预分传奇名额，也不增加史诗数量配额。
5. 入本及探索不消耗通常的行动时间；离开后，同一行动时间单位内不能再次进入副本。
6. 史诗和传奇都会引来大批宗门的高阶修士。史诗同样存在交战、夺宝和真实伤亡，只是整体惨烈程度相对传奇较低；传奇必有剧烈争斗和大量低阶伤亡，并出现超出该副本基础层次的强者。
7. NPC 会权衡修为、真实作战能力、求宝动机、准备程度、关系和既往交易，既可能背叛玩家，也可能背叛 NPC。玩家可以站队或逃跑。帮助弱势一方获胜，应获得感激和额外分配；站队之后仍可能被清算。
8. 非玩家参与的争夺、伤亡和收获，用文本或隐晦信息表达。没有必要实例化这些 NPC，更不建立他们抢到多少宝物的库存。
9. 玩家取得的资源归玩家所有。NPC 的后台收获不扣减玩家的掉落；“多分一份”直接增加玩家的奖励，不需要先生成 NPC 的那份。
10. 强者下界可以直接生成在副本当地，记录本体修为及受界面压制的修为，按实际拥有的邻域等能力参与战斗；无需模拟其从上界出发的全套行程。
11. 进入前不提供基础层次、势力名单、已确认强者、冲突阶段等情报面板。这些内容由玩家入本后探索。
12. 道祖是“大罗后期且邻域至臻”的身份称号，玩家同样可以取得，不新增境界。
13. 信箱有右侧 UI 和主界面两个入口，收到未读消息显示红点，首期服务于双方副本邀约。
14. 归墟之潮现有行动循环、组队博弈、索宝、背刺和后台争夺逻辑不能用于本案。新副本独立设计这些规则；玩家库存、人物身份、通用战斗、生存与时间等本体权威入口仍须使用。
15. 副本内有可回看的日志，展示玩家获知的各方动向与大致结果；消息按“实证／据说／听说”标记，而非全知战报。
16. 博弈必须展示具体指标的数值条，包括双方境界差距、战斗能力对比、对指定宝物的志在必得程度、准备与关系等；不能再以总体争夺进度或总体合作条替代。队伍成员、宗门归属与同行状态也须持续可见。
17. 传奇奖励按所属界面的最高境界对应数值定标，相等或略高，不受所在地图的强度和奖励上限压低。史诗仍受地图限制。奖励数值、仙凡性质与使用资格分别处理。
18. 玩家会直接遭遇其他宗门修士、势力代表与行动队伍；可以交涉、合作或交易，也可能被盘查、索宝、驱逐、伏击或卷入冲突。不能只把外宗放在背景日志里。
19. 原“威名”数值由新“凶名”承接，相关变量必须改名；凶名承担杀戮的惩罚与代价。新威名独立反映威望、实力与综合素质，不把杀戮惩罚继续当作正面声望。
20. 正式更新时，NPC 主动邀请玩家组队的评价必须包含新威名；保留关系、适配、实际实力与合作风险等因素，不以凶名代替威名。
21. 组队目的独立影响行动。以杀死玩家为主要目的的新生成修士，初始风险非常高，后续难以靠普通合作降低；生成时境界不得低于玩家。
22. 探索中可有其他修士加入或退出队伍，各有独立目的。真正暴露之前，玩家不能完全知晓其意图，只能从蛛丝马迹推测；真实目的不直接出现在 UI、日志或风险条中。
23. 第三级界面传奇副本有很大可能直接产出合练版本的完整功法，而非仍需搜集的散篇；其他层级按本界对应传承处理。保持传奇顶阶标尺、仙凡性质和修习资格的区别。


本文中的具体次数、概率、奖励预算、入口形式及实施顺序都是**建议值或待审项**，不能当作用户已经批准的数值。

### 2.1 对当前奖励的判断

现有遗泽的基础数值使用 `expected_combat_power(realm, 5)`，再乘 `0.12～0.20` 和品质系数 `1.2／1.45／1.7`；法器生成结果的 `combat_effects` 为空。它提供了按境界缩放的物品，却没有形成“为何为这件东西深入险境”的独特目标。

归墟已有带战斗机制或秘法绑定的固定内容，不能一概称为纯数值奖励；但其固定内容、库存争夺和周期规则与本案不同，直接扩大归墟池也不能解决新玩法的目标。

高阶资源还要结合真实成长入口：[机缘结算](../cultivation_life/system/opportunity.py)、[仙痕取得](../cultivation_life/system/immortal_cultivation.py)、[仙脉费用](../cultivation_life/system/doctrine/cultivation.py)。大额机缘不自动等于补齐仙痕等瓶颈，也不能把一次奖励拆成大量小额发放来重复触发附带判定。

**目前没有足以证明“新副本收益已经足够”的数值实验。** 本案给出奖励结构和校准方法，实际强度必须在接入真实成长、战斗后验证，不以一个夸大的倍率替代验证。

## 三、地图生成、有限总量与稳定种子

### 3.1 地图配置覆盖

每个实际启用的 `(world, location_id)` 必须明确绑定生成方案。共用主题组件可以减少制作成本，但每张地图要明确其取值，不能最终都落入同一个默认模板。

| 普通界面 | 当前基础地图数 | 普通界面 | 当前基础地图数 |
| --- | ---: | --- | ---: |
| 人界 | 28 | 灵界 | 28 |
| 魔界 | 27 | 真魔界 | 27 |
| 幻冥界 | 34 | 地狱界 | 30 |
| 仙界 | 21 | 修罗界 | 23 |
| 幽冥界 | 27 | 轮回界 | 28 |
| 妖界 | 34 | 合计 | 307 |

运行时还要核对 DLC 合并后的实际地图集合。裂缝、失落空间必须另定宿主实例归属：建议其中副本消耗来源地图的有限额度，不因反复生成空间而无限增加奖励；无法确定来源的特殊实例暂不产生新副本。此项待审，不把它们伪装成人界地图或漏掉覆盖校验。

每张地图至少配置：

- 基础境界范围、奖励基准和强度上下限。
- 环境主题、遗迹形态、路径结构、危险类型、可产生的事件组件及禁配组合。
- 四档品质的生成权重、显世方式、可登场的竞争者原型及压制条件。
- 有限副本总数、每个副本的探索节点范围和退出条件。
- 奖励家族、材料与道途倾向、固定珍品候选，以及文字素材。

| 澜沧海 | 海底古洞、暗流、不同出口；退路本身是可探索的信息 | 古修传承、水域珍材，原地图危险规则继续有效 |
| 界门古塞 | 界面残痕、古塞禁制、断界通路；更高阶的遗存与争夺 | 人界最高基础层次和预算上限，更容易出现适合高阶修士的目标 |

“古塞最高”指普通、稀有、史诗在相近完成度下的基础档与地图上限。传奇是明确例外：无棣原与界门古塞的传奇奖励都采用人界最高境界标尺，不能因无棣原较弱就降低其传奇数值。地图仍影响主题、环境、路线与奖励类型，不再限制传奇数值档位。

### 3.2 地图总量、品质概率与界面传奇次数

建议每张地图有固定的有限副本槽位，一生不刷新。首次发信、发现入口等正式生成命令激活某个槽位；查界面不激活，拒绝邀请不换槽位，过期的副本不补发新品。

维护两套不同的限制：地图有限槽位限制该图的副本总量；界面传奇计数限制本界面累计生成的传奇。这里的界面是人界、灵界、仙界等具体世界 ID，并非把所有第二层界面共用一个额度。每个界面的上限可以配置，具体数值尚未定案。

正式生成时，先校验地图槽位与所在界面，再按固定种子判定品质。传奇额度未满时按本地图概率生成；额度已满时，在普通、稀有、史诗的有效权重中用固定子种子作一次判定，不生成超额传奇，也不循环重抽或保证补成史诗。已生成副本的品质永远不因后来额度耗尽而改变。

传奇蓝图、界面计数与发现／邀请回执在同一事务中提交；同一个副本被多位 NPC 提及只计一次。同时发生的生成请求按稳定顺序处理剩余额度。建议生成时即占用次数：玩家未参加、拒绝邀请或过期都不返还，避免筛选和刷取。读档、换地图、夺舍或切换界面不重置计数。特殊空间按已确定的宿主普通界面计入，归属不明时不生成。

每张地图不预分传奇名额。界面额度尚余时，同一地图可以连续产生传奇，也可以一个都没有；史诗仍无单独次数配额。新规则取代 V0.1 中“各品质不设独立生成次数上限”的规定，地图总量限制继续保留。

建议首轮调试使用每普通地图 3 个槽位，但**不是推荐直接发布的最终数值**：307 张图即最多 921 个普通地图副本，还要结合跨地图累计永久成长验证。总量、冷却、单本收益与永久属性上限必须同时控制，有限次数本身不能保证平衡。

品质建议先用“普通 70%、稀有 24%、史诗 5%、传奇 1%”作为传奇额度尚余时的基准测试分布，再由地图显式修正。概率不是保底；界面传奇上限是另一项独立限制。这些比例仅供比较发生频率，正式值待审。

建议一次正式进入即消耗该副本的进入资格。暂停存档后继续属于同一次探索；撤离、通关、死亡收尾后不能重进刷另一条支路。若需要允许重返，必须保留原节点、原资源和原清算状态，不能重新生成；首版建议不开放，待用户决定。

### 3.3 种子固定什么

根种子由“本局种子＋地图地址＋固定槽位号＋生成版本”派生，避免使用会被炼丹、开菜单等无关操作改变的共享随机游标。发现日期、打开信件的次数、玩家尝试顺序不能用于重抽品质。

独立派生环境、品质、人物原型、奖励、事件、叙事表达等子种子。生成时固定蓝图及版本；尚未展开的节点可以延迟计算，但结果必须已由蓝图、路径和稳定编号唯一决定。

必须区分：

- **不能重抽的事实**：副本品质、地图参数、核心珍品、人物本体身份、潜在能力、初始真实目的及对应生成参照。人物原型生成时冻结玩家的真实境界参照，完整实例化只是展开原结果；不能推迟到读档后的第一次见面重新配强者。
- **会因玩家行为改变的结果**：走哪条路、谁相信玩家、何时动手、是否结盟、谁活下来。

同一存档和相同选择重放得到相同结果；不同策略可以得到不同结果。防读档不等于把玩家的所有选择做成同一结局。

普通本地存档无法阻止用户任意改档或回退全部历史。这里保证正常加载和相同决策不能重抽，避免声称提供客户端无法兑现的绝对防作弊。

## 四、四档副本的玩法区别

| 品质 | 探索结构 | 竞争和危险 | 回报职责 |
| --- | --- | --- | --- |
| 普通 | 较短，地方遗存、有限岔路 | 环境、守卫、小规模合作与冲突 | 可感知的当期资源补充，有机会改善一处配置 |
| 稀有 | 更完整的遗迹结构与多条取舍路线 | 有目的的求宝者、交易与伏击 | 明显改善一项能力或补足一个修行瓶颈 |
| 史诗 | 大型机缘、大批宗门高阶修士参战，玩家可以游走、合作、取偏路 | 存在夺宝、杀人、围攻和宗门局部冲突；相互顾忌使整体伤亡相对传奇较轻，不提供免死保护 | 重要传承或关键成长资源，足以改变当前阶段的养成安排 |
| 传奇 | 同样有探索和人物博弈，但主冲突必然失控 | 超出副本基础层次的强者争斗，封路、余波、阵势崩塌和大量低阶死亡 | 生还并夺得核心机会者获得跨越式收获，强度与稀缺性均有实质区别 |

品质先在后台判定。玩家看到的是发生的事情，不是进入前四种颜色的难度卡。

### 4.1 史诗：围绕互相顾忌形成选择

史诗的克制是对全面失控的顾忌，不是停战协议。无需玩家介入，NPC 也可以杀人夺宝、伏击敌宗和在局部冲突中战死；玩家同样可能死亡。伤亡的相对规模和波及范围与传奇有别，不能把史诗做成安全合作副本。

后台只需保存影响事件的少量局势条件与参战势力引用，如“双方尚有制衡”“协议被破坏”“关键禁制已开启”。不需要每个势力的完整成员名单、财富和军事资源模拟；参战宗门、代表与局部阵营的归属规则见第八节。

可以产生：双方交换进入权、有人想借玩家破阵、弱势修士求援、同盟私下谈条件等事件。玩家行动、NPC 毁约或关键机缘暴露都可能使局势升级；升级要有可追溯的事件原因，不能每个史诗走到固定节点都自动演变为传奇屠场，也不能规定只有玩家先动手才会发生伤亡。

### 4.2 传奇：强者争夺一定发生，玩家并非一定参战

传奇显世即确定争夺背景和超规格强者原型。玩家不参加时，结果仅在合适的后续消息中以传闻出现，不生成全体参战者，也不逐人计算死伤。玩家参加时，逐步遇到逃亡者、失控禁制、余波或真正的争夺者。

必然惨烈不等于每个选择都强制安排玩家对战最强者，也不等于后台投一个“九成死亡”的固定骰子。直接挑战、冒险取宝、利用掩护、提前撤离具有不同后果；是否活下来由实际遭遇和能力决定。

| 所在层次 | 传奇叙事与实际出场原则 |
| --- | --- |
| 人界等第一层普通界面 | 可有化神级争斗，元婴后期也可能死于围杀或余波。出场强者应超过该本的基础层次；若地图基础已经接近本界上限，使用更高真实修为及压制设定，不能只把同阶普通敌人改名 |
| 灵界等第二层普通界面 | 多位大乘角逐，可引出真仙下界。真正交互时才生成对应本地人物，显露修为可受限至大乘后期 |
| 仙界等第三层普通界面 | 大罗角逐，可引起道祖注意。道祖是否亲自现身取决于该副本种子与事件条件，不规定每个传奇必有道祖露面 |

跨道途界面的具体修为名称、邻域体系由对应配置提供，不把仙界道修称谓机械套在全部界面。

### 4.3 压制强者与道祖

新生成的下界强者，概念上保留“本体修为、本体层数、当前受压修为与层数、已修成的能力、有限可用能源”。例如本体真仙、当地显露大乘后期：基础战斗参数受当地限制；确实修成的灵域保留资格，再按当地法则和资源决定如何使用。

不是所有真仙自动拥有相同灵域，也不因写了本体修为就获得无限元力。需要补充现有能力投影中仍只看显露境界的环节，避免出现“剧情说真仙、实际战斗完全没有上界手段”。这是一处生成与战斗适配工作，不扩展成跨界交通模拟。

已有世界 NPC 继续引用原身份与位置；不能把一个正在别处活动的知名人物复制成副本版本。没有到场依据时使用新的本地生成角色或背景传闻即可。

道祖按本次设定采用大罗后期与邻域至臻的共同条件。后期建议对应现行九层制的 7～9 层；至臻对应当前邻域 rank 13。称号本身不额外附送战力倍率，危险来自实际至臻邻域及其战斗能力。

现有代码另有道论等级要求，而且未必要求九级道论与至臻邻域属于同一条道论。按用户本次定义，称号判定不额外附加这项道论等级条件；邻域本身的修炼资格仍由原培养系统处理。修订必须统一玩家与 NPC，并同步称号展示、成就及战斗对象识别，不能只改副本文案。

## 五、入口、邀约与信箱

### 5.1 发现与进入

建议优先把当地入口挂在现有地图／建筑导航下，由已发现遗址或明确建筑承载。没有合适建筑的地图使用当地遗址入口，不强行为每个副本新增一栋具有产权、生产等功能的建筑。

发现来源可包括当地探索中的迹象、NPC 来信或玩家已有线索。每种来源都指向同一个副本 ID，不各生成一份。是否发现、何时发现由实际触发决定，不保证刚到地图就收到邀请。

邀请信只表达发信者愿意透露的邀请理由、会合地点和条件。不给出副本完整档案，不承诺信中判断一定正确，也不提前提示史诗／传奇标签、幕后强者和冲突阶段。

### 5.2 两个信箱入口

- 右侧区域新增信箱入口；主界面在现有导航中放置同一入口。
- 两处共用未读状态和红点。读信后同步消除对应未读计数，不能按页面各记一份。
- 小屏仍能通过主界面导航进入；两个像素主题均支持，不恢复旧文字布局。
- 已读、已接受、已拒绝、已失效是不同状态。读信不是接受邀请，删除或收起信件不使副本重新生成。
- 首期只做副本邀约与其必要回执，不借机扩展交易、邮件附件、全世界新闻或独立社交聊天系统。

NPC 邀请顺序必须是：确定有限槽位 → 固定副本蓝图和邀请关系 → 写入信件。三者同一次事务保存，不能先发信、点击接受时再抽副本。

### 5.3 玩家发起邀请与人员状态

玩家从已发现副本发起邀约，选择可联系的原 NPC。是否答应由真实目的、关系、对邀请内容的判断、求宝动机及现有占用决定，不默认所有人无条件跟随。对方也可能为接近并谋害玩家而答应；接受邀请不构成其善意的证据。

NPC 主动邀约及回复玩家邀请纳入第十三节的新威名。威名影响合作价值，凶名单独影响合作风险；邀请仍先绑定已经生成的副本，不因玩家威名而重抽品质、奖励或传奇次数。

建议首期把可直接同行的已有人物限定为满足原接触和到场规则的人物；远程来信只是信息，不代表跨界传送。用户接受副本邀请也不瞬移到入口，原地图移动时间和资格不变。

软加载的新邀约者可先保存稳定身份、必要通信信息和决策原型；在会合、交谈或开战真正需要时生成详细人物。同一人在后续交互始终保持身份，不能每次开信抽一次性格。

原 NPC 的死亡、离场、拘禁、派遣冲突会使同行资格失效。副本本身不因此被重抽。刷新页面不临时解放忙碌人物；到场和原人物占用在正式进入时再次核对。

邀请是否设置等待期限，建议首期不统一强制倒计时；若某副本明确配置截止时间，必须在收信时冻结，同世界时钟比较，未读不暂停、重读不延期。

## 六、零行动时间、内部推进与退出冷却

副本内使用“有效探索步骤”推进局部事件。移动节点、实施探查、谈判承诺、尝试逃跑等实质命令可以推进；开菜单、看背包、读取文本、恢复存档不推进。

路径和事件数量有界。同一节点的再次访问读取原状态，不重抽一组新敌人和新宝箱；反复谈同一条件也不反复增加准备、好感或报答。局部阶段只向前推进，不能通过来回走动把一个有限副本变成无限事件生成器。

进入、探索、交战、退出本身均不直接增加通常行动年数，不触发一整年的世界演算，也不因跨了一步就自然回满法力。允许主动使用已有物品；额外休整若加入，必须有固定次数、实际资源或风险成本，不能零代价无限疗伤。

### 6.1 推荐冷却口径，待审

建议设为玩家全局冷却：

`下次允许进入时刻 = 本次实际退出时刻 + 入本时冻结的一行动单位时长`

- 单位长度按入本时真实、未压制的境界读取，避免靠压制境界缩短等待；出本途中境界变化不改写已冻结长度。
- 时间使用现有原玩家年龄所代表的连续时钟；夺舍后的肉身年龄不能作为冷却时钟。
- 换地图、换界面、换邀请人、读档不能消除冷却。查看信箱、发现入口不受冷却阻止。
- 实际经过不足一单位时不能入本。例如大乘单位为 100 年，实际只过 1 年不能因向上取整记作一个行动而解除冷却。
- 使用 [world.json](../content/world.json) 当前配置：境界索引 0～3 为 1 年，4 为 5 年，5 为 10 年，6 为 20 年，7 为 50 年，8～12 为 100 年。最终不在副本代码复制这张表，读取权威配置。

需要用户确认：这里的“相同单位时间内”是否就是上述退出后完整等待一单位。本文不擅自改成仅禁止同一日历区间再次进入。

### 6.2 退出与失败

正常撤离、通关、强制退出后的幸存收尾均启动冷却；终局死亡保持原死亡状态。失败的逃跑仍在副本内，不启动一个可以借机解除忙碌的假退出。

关闭游戏和保存暂停不是退出，不重新开本、不重置战斗损耗。待决战斗中不能用返回主界面绕开选择；过期页面也不能重复发奖或重复扣款。

死亡沿原生存系统处理，包括符合资格的元婴、第二元婴等情况，不能为了体现传奇凶险而一律绕过已有保命机制。若以后增加明确克制元神的危险，应使用实际战斗机制并有对应线索，而非隐藏强制删档。

## 七、探索事件与不重复文本

### 7.1 生成的是因果过程

每个事件由“地点状态＋当前可见线索＋人物目的＋可执行行为＋后果条件”组成。文字根据这些事实生成，选项与真实条件绑定，不能只换人名和形容词。

例如同样遇到封闭石室，可以因为禁制能源不足、有人从内控制、第三方设伏、先前行为破坏阵眼而产生不同选择。玩家破阵、绕行、交易或撤离，会改变后续路线和人物判断，而不是四个选项最终都进入同一战斗。

建议采用本地规则生成与组合文本。结构、谓词和措辞由种子挑选，不依赖联网大模型，不让自然语言生成结果直接控制奖励和战斗。作者提供可组合语义组件，不逐本预写完整剧情。

### 7.2 去重要求

要同时防止“整段完全相同”和“机制、因果完全相同，仅换几个词”。维护两类记录：完整探索段落指纹，以及结构签名（事件机制、动机、局势、分支结果）。

- 本局不同的新探索事件不重复既有完整段落。签名匹配时优先更换结构、参与关系或路线条件，再生成文字。
- 公共操作名称、战斗术语、固定物品说明可复用；不是要求每个常用词都只出现一次。
- 读档恢复同一个未完成事件，必须显示原文。这是恢复，不是又生成一次新事件。
- 已生成事件不因另一个副本后来使用相似文本而重写。候选去重用稳定顺序，不能消耗无关随机流。
- 去重记录随存档保留，不做周期清空来重复利用旧探索段落。有限副本数量下保存短指纹即可。
- 素材不足时由内容校验报告具体覆盖缺口；不能运行时无限重抽，也不能靠追加编号假装不重复。

精确文本去重可以硬性验证；语义重复还需要大批种子样本审阅。没有经过样本验收前，不宣称“所有可能剧情在语义上绝不重复”。

### 7.3 信息只在探索中揭示

后台完整事实与玩家所知分开。战斗显示可以受侦察、对方伪装和已显露手段影响；未确认修为不在 API 里先发送再用 CSS 隐藏。

示例：“远处两股气息骤然相撞，方才经过的石桥已只剩半截。”可以提示局势加剧，不自动附上对战者姓名、境界、阵营名单和阶段编号。

NPC 的陈述可不完整、误判或说谎；客观叙述不能为了悬念否认玩家已经亲眼确认的事实。选项只描述玩家有理由想到的行为，不用“偷袭成功率 72%”泄漏隐藏实力；明确物品支出等操作代价仍应如实告知。

### 7.4 副本日志：实证、据说、听说

日志是本次副本的持续见闻记录，包含人物交手、宗门冲突、夺宝结果、封路、撤退、结盟与毁约。日志中的“各方”指已被玩家获知的参与方，不是在入本时公开完整势力名册。

| 标记 | 含义与来源 | 可以展示什么 | 不能据此确认什么 |
| --- | --- | --- | --- |
| 实证 | 玩家亲历、现场直接观察，或已经核验且足以支持相应结论的证据 | 被证实的身份、动作、局部结果、目击的宝物交接 | 看见一具尸体不自动证明杀人者；看见夺宝不自动证明最终安全带出 |
| 据说 | 有具体来源的转述，如同行者、败逃修士或某宗弟子的陈述，尚未独立核验 | 来源提供的姓名、宗门、显露境界和所称结果；允许不完整或错误 | 具体人名不等于可靠；同一消息被多人转述不自动升级为实证 |
| 听说 | 辗转传闻、远处风声，或不足以确认人物与结果的模糊消息 | 相对方向、异常迹象、粗略烈度及推测 | 不补出精确战力、真修为、暗中准备、伤亡人数或未知宝物 |

同一个冲突的记录可以经历“听说有异动 → 据说某两宗交手 → 实证目击一方撤退”。后续证据补充新记录并关联原条目，保留玩家当时所知；若推翻传闻，标注“后证修正”并说明修正了哪项事实。原实证只对观察时刻与范围负责，后续逆转不是把旧实证改成谣言。

消息必须标注本次探索步骤、发生区域／相对方向、来源类别、证据标记和涉及的已知人物／宗门。未知字段直接省略或写“未辨身份”，不为满足模板而泄漏完整资料。方向在收到消息时根据玩家所在区域换算并冻结；玩家走到另一侧后，旧日志不会把原来的“东北”偷偷改成“西南”。发生步骤与收到步骤分别保存，UI 可写“数步前”，不伪造副本外已经过了多少年。

以下是表达结构示例，括号表示生成变量，实际事件还需要多套语序、因果和结果组件，不能循环复用几句固定文本：

| 场景 | 日志示例 |
| --- | --- |
| 边缘处收到核心动静 | **听说** 在【方向】有灵力波动，杀气重重，想来是有不得了的人物在交手。 |
| 个体争夺的转述 | **据说**【门派甲】的【显露境界甲】【姓名甲】在与【门派乙】的【显露境界乙】【姓名乙】的争夺中【败退／重伤／失踪／身亡】，此言来自【可公开的来源】。 |
| 亲历夺宝结果 | **实证**【门派甲】的【显露境界甲】【姓名甲】击退了【门派乙】的【显露境界乙】【姓名乙】，【宝物】当场落入【姓名／宗门】手中。 |
| 宗门代表直接冲突 | **据说**【门派甲】由【境界】【代表姓名】领衔，与【门派乙】争夺【阵眼／殿门／通路】；【一方退守／双方死伤后暂歇／盟约破裂】，具体伤亡不明。 |
| 目击宗门局部败退 | **实证**【代表姓名】率【门派甲】修士退出【当前可见地点】，【门派乙】随后封住入口；你亲见其中数人负伤。 |
| 只感知到余波 | **实证** 你亲眼看见【方向】石壁崩裂。关于交手者的消息仍为**听说**，不将两个判断合成“已确认某强者出手”。 |
| 宝物归属纠正 | **实证** 你见到【姓名乙】携带【宝物】。先前“据说由【姓名甲】夺得”的消息，仅能说明当时的传闻，最终归属尚需结合后续经过判断。 |

结果词区分击退、败逃、重伤、失踪、俘获与死亡；不能把“未再出现”直接判为死亡。门派代表败退不等于整个宗门灭亡，几名弟子受伤不推出完整伤亡表。已知宗门／人物可以点开本副本已知记录，未知对象不链接出完整人物档案。

日志按事件增量写入，一次有效步骤可以产生有限的相关消息；开日志、切筛选、读档不产生新消息，也不重抽真假。重复传播同一来源只更新关联次数，不刷屏、不提高可信程度。远处事件可延迟传到玩家耳中；已离本后只保留既有记录，未参与的后续结果仍按有限传闻处理。

“【宝物】落到【NPC／宗门】手中”仅需保存事件的叙事归属，不需要给 NPC 创建物品对象或背包。无关背景事件使用独立的背景宝物标识，不能把玩家已得或已冻结的唯一核心奖品写成被别人带走。若同一件宝物进入玩家亲历的争夺链，就由该事件的唯一结算凭据关联后续取得／交付，保持叙事与真实玩家库存一致，不另发第二件。

### 7.5 博弈数值条：具体对象、具体宝物、具体因素

参考《维多利亚 3》的日志条目呈现方式：条目可以展示进度条、条件与结果说明，见 [Paradox 官方开发日志 #78](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-78-update-1-2-changelog)。本案据此设计“可持续关注的局势卡片＋横条＋变化依据＋关联日志”；下述信息隐藏、争夺与队伍规则是本游戏的方案，不声称照搬其完整机制。

每张博弈卡先明确比较对象：玩家与某修士、甲与乙，或者两支已知队伍；再绑定宝物或交易目标。切换对象时，数值、原因和来源随之变化。队员、外宗遭遇对象和日志中已知代表均可被观察；未接触的人物只显示已经获知的数据。

| 数值条 | 示例与量纲 | 对决策的影响及可见范围 |
| --- | --- | --- |
| 双方境界／差距 | 你：元婴五层；对方：元婴八层；对方高 3 小层 | 并列展示已识别的显露境界；跨境另标高几个大境界。只知后期则显示七至九层，不能编成八层或泄漏本体 |
| 相对战斗能力 | 你为 100，对方为 145（估计 120～170） | 指明单人或同场队伍及估计依据；共用刻度，不是胜率，也不能覆盖仙凡资格差异 |
| 对宝物的志在必得 | 霍厉对玄水珠：90／100（估计 80～95） | 每个人、每件宝物分别计算；疗伤、修行与宗门任务影响该值，不等于 90% 会背叛 |
| 动手／脱身准备 | 对方动手准备：40／100（估计 20～60） | 依据已知封门、同谋、伏击和退路。玩家自身实际完成的准备可确切显示；对方隐藏部分不下发 |
| 对玩家的信任／敌意 | 对方信任你：25／100（估计） | 分别记录、有明确方向；影响合作、交付和清算，不显示秘密交易 |
| 动手的顾忌 | 报复／受伤顾忌：65／100（估计） | 宗门后果、第三方压力、损伤风险影响冒险代价；未知援军不能通过条值提前泄漏 |

博弈主区默认展开境界对比、相对战力、目标求宝决心；准备、信任／敌意、顾忌可在同一卡片展开。每条带数字、量纲、对象和来源，不能全部收起后又只剩总体条。估计显示中心值与区间；未知写“未探明”，不是 0／100。不能用“合作紧张”一句话替代数值。

同境可以一至九层并列；跨境使用 [现有境界坐标](../cultivation_life/cultivation_coordinates.py) 的 `rank_for` 和境界分段，不能把炼气十三层与仙境跨度强行当成相同九格。相对战力超过刻度时同时扩展双方刻度，不截断数字。0～100 动机条是评分，不是概率。

保留此前确定的信息探索：后台真实决策值与玩家可见估计分开。已知修为、玩家自己的准备可以确切显示；他人内心和隐藏准备显示估计或未知。可见性处理不能取消数值条本身。估计由已获知的事实和固定规则得出，同一消息版本不重抽，没有依据不随机编造精确分数。

每次变化说明原因，例如“得知玄水珠关系其疗伤，求宝决心估计由 60 升至 90”，并关联来源日志。消息过时显示“最后获知于第 N 步”；无新信息时保持旧估计，不随着后台真值实时跳动。

这些因素参与第八节决策，不能相加出一个替代真实战斗的总胜负条。境界、仙凡攻击与防护、邻域、同场人数和有限资源共同决定实际能力；面对已确认的仙凡资格障碍，另列“已知手段不具备相应伤害资格”等条件。未探明资格时显示未知，不提前揭露本体。共同行动的完成项可留在事项详情中，但不再作为博弈主面板。

### 7.6 组队状态可视化

队伍摘要置于当前区域下方，局势／日志页也保留紧凑版本。队员卡显示姓名、已知宗门、已识别修为、队长／同行身份、当前位置或最后见到的位置、可观察伤势，以及“已答应未会合／同行／分头行动／失联／敌对脱队／已退出”等明确状态。

途中加入者显示实际会合步骤和其自述来意，并将自述明确标为自述；离队者留有最后可见状态，不能直接从历史中消失。未暴露的真实目的与后台初始风险均不下发；线索与行为记录按第 8.2.3 节展示。

已有人物仍使用原身份和同一份资源；副本队伍只保存本次队伍关系与成员引用，和原 `party` 的有效随行统一校验。宗门相同不自动组队，临时共同对敌不自动成为永久队友，失联者不能同时在玩家身边参加战斗。

选中队员可查看公开约定、已知援助和争执记录。显示“合作紧张”的依据，不展示“此人 83% 会背叛”；秘密交易只对实际参与或获知者显示。加入、离队、受伤、战死、站队改变都同步更新队伍卡和日志；读档与小屏折叠不造成两处状态不同。

组队、解除约定和支援等命令放在相应队员／事项的上下文中，复验当前位置、是否同场、忙碌和待决事件。不能在已经受围攻时点一下头像“解散队伍”就跳过战斗或逃离结算。

## 八、NPC 软加载与玩家相关的博弈

### 8.1 只生成当前确实需要的人

后台保存副本原型、关键角色的稳定种子及少量已发生事实。背景中的“众多修士”“几方势力”是叙事规模，不是待创建的一百个 NPC 对象。

以下情况才需要完整人物：玩家与其交谈、同行、交易、站队、战斗，或者确实要将其转为持续存在的关系人物。远处交战、听说某群人死伤、某方取走异宝，都不需要人物实例、背包和逐年资源结算。

物化后保留同一身份、资源与伤势。再次遇到不能重新满状态。已有世界人物引用原记录；新人物若建立持久关系，则登记一次权威人物身份，副本只留引用。普通背景传闻不能擅自把实际世界中的某个具名 NPC 判死。

下界强者的本地生成是本案明确的剧情出生方式。实施时登记其有限范围、责任入口和状态差异；不把此方式开放为玩家或已有 NPC 的免费跨界移动入口。

### 8.2 背叛决策需要哪些因素

| 因素 | 影响 | 数据从哪里来 |
| --- | --- | --- |
| 真实目的 | 为何同行、目标是谁、完成条件及放弃代价；决定如何评价合作或背叛 | 冻结的角色目的与后续真实事件，不由好感值推断 |
| 预期胜负 | 自身与目标、同盟、第三方的作战差距 | 已观察到的修为、战斗表现、伤势、邻域等；NPC 不默认全知 |
| 求宝动机 | 某物是否解决自身关键需求、是否已作承诺 | 固定动机原型与当前发现，不依赖 NPC 宝物库存 |
| 准备程度 | 是否掌握退路、布置伏击、取得同谋 | 已发生的有效步骤和事件结果，不能突然凭空准备完毕 |
| 关系与信誉 | 信任、恩怨、守约倾向、报恩倾向 | 原关系与本次人物原型、玩家行为 |
| 代价与顾忌 | 可能受伤、泄密、被第三方报复、错过更大机缘 | 当前局势和实际知情者，不能无因累加全世界仇恨 |
| 时机 | 是否处于背对入口、共同破阵、战后虚弱等局面 | 实际节点状态与资源损耗 |

建议按“条件能否成立 → 比较继续合作、索要、伏击、退出等收益 → 固定随机判定”决策。数值权重集中配置，先有可以解释的原因再调概率，不把所有 NPC 压成一个统一背叛率。

准备不足或明显打不过时，可以继续合作、试探、招揽盟友或放弃当前行动。放弃行动不等于放弃目的；预谋杀人者可隐忍等待，不能仅凭一次顾忌就清除其杀人目标。贪婪不等于总会自杀式动手；高好感也不意味着对唯一救命之物永远没有冲突。

NPC 根据其知道的玩家表现估算战力。真正开战时用完整实际能力；这允许隐藏实力、虚张声势与错误判断有用，避免后台读取玩家全部面板后精准算计。

### 8.2.1 真实目的、公开说辞与行动分别保存

每个有必要参与玩家交互的角色保存轻量目的记录：主目的、目标引用、次要诉求、坚持程度、完成／中止条件、已发生的准备事实，以及对玩家说过什么。目的原型由种子固定，不因入队、离队、开信或重新交谈而重抽；确实发生目标完成、委托取消等事件时才记录目的演变。无需为此创建背景库存或全世界关系网。

| 后台主目的示例 | 可能的公开说辞 | 对行为的实际影响 |
| --- | --- | --- |
| 求取特定传承／疗伤物 | 共同破禁，各取所需 | 目标取得后倾向离开；分配冲突可使其转而强夺 |
| 借队伍护送、保命 | 熟悉侧路，可带众人前行 | 更看重退路和掩护，危险超出预期会要求撤离 |
| 营救同门、执行宗门任务 | 顺路寻找失散同伴 | 达成局部目标后可能转向本宗队伍，不以玩家收益为优先 |
| 试探实力、探听线索 | 仰慕威名，愿助一臂之力 | 在交手时留意玩家底牌，未必急于夺宝 |
| 杀死玩家／受托伏杀玩家 | 任何符合身份的合作理由 | 合作可能只是接近、耗损、孤立玩家或布置伏击的手段 |

同一行为可以对应不同目的：援手既可能出于情义，也可能为了保住伏击目标；退出既可能是怕死，也可能是去与同谋会合。不能按“救过一次就是好人”“没有抢宝就没有敌意”反推真实目的。个人目的、同宗利益、对某件宝物的欲望和队伍约定分别存在，不压成一个性格标签。

### 8.2.2 预谋杀人者：初始高风险、难以消解

用户确定的是这类角色的持续危险，不是见面即强制开战。其杀人目标从初始就存在；建议在决策中设独立的高位敌对倾向与持续约束，普通好感、让宝、共同破阵和几次援助只能影响行动条件，不能把谋杀目的逐次扣成零。具体高位分值、风险下限与极少数消解条件待校准，不把它们当作已批准的背叛概率。

分别判断“仍想杀玩家”“当前是否准备好”“此刻动手是否合算”。玩家的戒备、强援或实力展示可以压低当下出手机会；杀意未必因此降低，对方可能继续伪装、等战后虚弱，或暂时离队。真正消解必须有足以改变目标的具体事件和唯一记录，不能靠循环送礼、反复入退队或高威名自动洗去。

**专门生成的定向杀人角色，生成境界不低于玩家。** 建议采用原型首次冻结时玩家真实、未主动压制的修为，以 `rank_for(境界, 层数)` 比较，包含同境小层；同为元婴不能用元婴初期去满足元婴后期玩家的下限。记录该参照时点，与原型一同冻结；途中物化、换装、读档不重新计算，不做随玩家每次提升而无条件追涨的橡皮筋敌人。

本体修为、当地显露修为、伪装和实际战斗能力保持分离：下界强者仍受本界压制、有限能源和仙凡资格约束，不能为满足生成下限解除界面之力；NPC 自己的战力判断仍依据其所知信息。这个下限是后台生成约束，不等于 NPC 全知玩家底牌，也不向玩家预告此人真实修为。

合法角色范围与下限取交集；地图／品级角色范围或世界规则不允许时，该专门角色槽位不启用，不能向下截断后声称满足“不低于玩家”，也不越权生成更高界面人物。种子与禁用结果保存，不循环刷候选。上述是新生成角色的约束；原世界 NPC 按真实身份、修为和恩怨行动，不为加入副本被强行升阶，也不通过复制一个同名高阶版本满足要求。后续玩家成长、角色受伤或跌境不会抹去既已成立的目的与历史。

### 8.2.3 暴露前只能窥见线索

**直到真正暴露，玩家不能完全知晓其意图。** UI 不展示真实目的枚举、谋杀目标、坚持程度、敌对下限或“刺客概率”。也不能把这些值伪装成精确的“杀意 95／100”横条、颜色或提示，借隐藏字段间接剧透。已有数值条继续展示双方可知境界、战力估计、求宝决心与可观察的准备；每一项都有来源，不汇总成揭穿身份的总危险条。

| 可以观察到的内容 | 合适的日志措辞 | 不能据此宣布的结论 |
| --- | --- | --- |
| 对方反复询问消耗和护身手段 | **实证**某修士又问起你的法力余量，听完后没有继续谈宝物 | “已确认其准备杀你” |
| 对方坚持改变路线 | **实证**某修士提议绕向偏殿，称可避开争夺；其所称近路尚未核实 | “该路线必有伏击” |
| 接触可疑同门、临时离开 | **据说**有人见他与某宗修士低声交谈，内容不明 | 直接列出同谋名单和暗中交易 |
| 面对目标宝物反应异常 | **实证**你让出他自称急需之物，他却仍要求与你同行 | 唯一解释为谋杀，排除其他隐藏目的 |

“实证”修饰亲眼见到的动作，不自动确认动作背后的动机；同一个线索可有多个合理解释。线索必须由已有目的、准备或真实事件产生，不在事后为解释背叛补写历史，也不能让每个杀人者都按同一顺序说同一句话。没有可见线索时保持未知；隐藏不能代替真实结算或让 NPC 获得凭空完成的伏击。

暴露由真实事件形成，例如明确袭杀、当场承认并有行为印证，或玩家取得并核实足以揭穿其计划的关键证据；不是探索到固定末步自动翻牌。暴露时只确认已证实的目标／行动，不顺带公开所有同谋、委托人和未来计划。质问、戒备、改变路线、拒绝结伴或提前撤离可影响安全，但不能要求玩家先把隐藏目的解锁到 100% 才允许自保。

### 8.3 NPC 背叛 NPC：玩家的选择链

1. 玩家遇到真实存在的冲突迹象，了解双方愿意公开的诉求。
2. 可以援助任一方、按已知条件谈判，或趁机逃离。选项由当前处境决定，不预告最佳答案。
3. 站队后双方形成真实战斗参与者。不能用剧情一句“你支持的人赢了”替代战斗。
4. 逃离根据实际可用战力、伤势、控制／追击能力和地形结算。强者有优势；被封锁退路时也不能只比较面板数值就必走。
5. 帮助事发时实际较弱的一方并使其获胜、存活，给予明确感激及额外玩家奖励。弱势身份在介入前冻结，不能靠战后伤势变化判定。
6. 获胜后的处置考虑之前交易、履约情况、秘密是否暴露、玩家剩余战力、对方性格与恩情。可以守约、议价、分道扬镳、背约或袭击，不固定二次背刺。

额外奖励建议预留一个有界的“援弱报答”槽位，参与副本总奖励校准；原弱势 NPC 没有任何需要预先分配的实体宝物。核心奖励和报答奖励各自只结算一次，不能反复加入退出队伍领取。

玩家主动毁约、抢夺已承诺交付的物品，应留下相应因果；一个从未得知这件事的远方人物不会自动仇视玩家。离本后的追责只对实际涉及玩家、且有权威身份与可达条件的角色建立记录，不补算整场势力战争。

### 8.4 一条完整的生成示例：如何产生不同结果

以下用于说明规则如何组合，不作为所有副本必经的预写剧情。地点、人物、宝物、条件和措辞都来自各自的种子组件。

初始组合：一处水府、一道尚未开启的禁制、对疗伤材料志在必得的甲、已与玩家约定共同破禁的乙。甲在玩家所见范围内更强，乙掌握侧路；双方尚未开战。后台不需要为甲乙生成此前抢到的物资。

| 玩家行为或已有事实 | 决策变化 | 实际结算 |
| --- | --- | --- |
| 玩家先探明侧路并告诉乙 | 乙的撤退准备提高；甲判断强夺未必能困住目标 | 甲可转为议价或等待，不必立即开战 |
| 玩家暴露伤势，甲又完成封门准备 | 甲对强夺的判断改善；仍要衡量乙与玩家的联手、守约性和第三方风险 | 满足动手条件才触发索要或突袭，不按第三次点击自动背叛 |
| 玩家提前与甲约定交付某材料 | 甲的目标可以通过守约获得 | 真正交付时检查玩家原背包并实扣；未履行才影响信用，不凭空生成一笔 NPC 收入 |
| 甲袭击乙，玩家援助乙 | 原关系、承诺与实际双方能力进入多人战斗 | 若乙是事发时较弱者且存活获胜，玩家取得预定战利与一次额外报答，乙增加感激 |
| 甲袭击乙，玩家帮助甲 | 甲因援助获益，但会考虑玩家是否背弃与乙的承诺 | 甲可兑现分配，也可能因不信任和战后实力差距考虑清算；不固定选强者就被杀 |
| 玩家趁乱离开 | 侧路知识、实际战力、伤势和封门状态影响脱身 | 成功才退出并启动冷却；已经取得的资源仍归玩家，未探索的节点不发奖 |
| 战后有人仍想灭口 | 要有确实需要隐瞒的事实、知情关系和可行实力 | 成立时进入新的交互或战斗；条件不成立则结束，不为增加戏剧性强塞第二次背叛 |

同一副本可以因提前探路而避免战斗，也可以因毁约而出现清算。文本变化对应实际状态差异，区别于固定故事换词。人物决策只在相关有效步骤计算；强弱估算用已观察能力与少量权重，不为每次选择预跑数百场战斗，更不计算所有背景人物两两关系。

### 8.5 大批宗门参战的归属与代表

史诗、传奇生成时确定参与的宗门集合、各方在本次机缘中的诉求、可能出现的代表原型及局部关系。规模可体现为多个宗门、多个高阶代表和大量背景随从；不将其压缩成几个毫无归属的散修，也不因此实例化全部门人。正式数量区间按地图与品质配置，尚不设未经验证的固定人数。

| 关系 | 含义 | 示例 |
| --- | --- | --- |
| 宗门归属 | 人物真实所属组织，引用稳定势力 ID | 某修士属于青岚宗，不因临时帮助赤霄宗就改宗 |
| 副本代表身份 | 此人是否以该宗门名义在本次副本内行动 | 奉宗门命令争夺阵眼，与弟子私下盗宝是两种事件 |
| 局部支持方 | 当前具体争夺中支持谁，可以随公开事件改变 | 两宗暂时联手对抗第三方，之后重新争夺 |
| 临时队伍 | 玩家身边实际同行的个人组合 | 可以跨宗门组队，同宗门成员也可能彼此倾轧 |

现有宗门绑定原 `faction_id`、原世界和存续状态；同名组织依 ID 区分，不能把族群 ID 当成某个宗门。优先选用有合理参与资格的原组织。远方或上界背景宗门需要稳定的出处与组织引用；若仅作叙事来源，可保存副本内的轻量势力身份，不顺带生成一个拥有山门、府库、产业和全部成员的可经营宗门，也不能凭相同名字冒充现有势力。

代表在尚未接触时，只需稳定角色 ID、名称／名号、归属、境界原型和已发生的叙事状态；这些字段足以支持“某宗的某修士败退”的转述。真正交互时才物化其能力和资源，继承已固定的身份、归属与结果。已经实证战死的代表不再次作为活人出场；未经证实的死讯可按既定事件真相被推翻。

若代表引用一个原世界具名 NPC，其到场与原状态必须真实有效。不能因为需要高阶角色就克隆、瞬移或擅自改写其宗门；可以改用当地新生成的该宗参与者原型。新代表不是原宗门人口、库存或战力的副本，不给宗门凭空增加可调遣军队。

个人冲突与宗门冲突在事件事实中明确区分：前者可因私怨、私下交易、个人求宝产生；后者应有代表身份、宗门诉求或公开行动作为依据。日志据此选择“甲与乙交手”或“甲率某宗与某宗争夺”的表达，不能因为两个人宗门不同就自动升级为全面宗门战争。

同宗关系会影响援助、报复、守约和遮掩，但不抹去个人动机。对某代表的援助可以换来该代表的感激或其有权作出的局部承诺；不自动取得整个宗门的终身盟约。副本内的损失和胜负只更新必要的局部事实与玩家相关关系，不为背景伤亡扫描和扣减原宗门全体人口、财库。

### 8.6 直接遭遇外宗修士与势力队伍

此类遭遇是正常探索内容，普通、稀有也可以出现；史诗、传奇的数量、修为与组织性更高。不是只让原队友背叛，也不是只通过日志听说别宗在交战。生成时固定潜在遭遇槽位，按路径、有效步骤和局部局势触发，不因反复进入同一节点无限刷来人。

| 遭遇对象／诉求 | 玩家可作的选择 | 后续需要结算的关系 |
| --- | --- | --- |
| 外宗独行修士探路、求宝 | 交谈、交换线索、交易、结伴、回避 | 个人信任、交易承诺与目标冲突；未答应结伴不加入队伍 |
| 宗门小队看守通路或阵眼 | 报明身份、议价、绕行、冲关、提出合作 | 队长的实际代表权限、同场队员、通行承诺；支付时实扣玩家原资源 |
| 与玩家无仇的势力争同一宝物 | 交换条件、退出争夺、临时联手、先取宝或交战 | 对该宝物各自的求取程度及所知实力；中立不等于永远安全 |
| 敌宗或追踪者截路索宝 | 交涉、反制、求援、战斗或尝试脱身 | 已知宗门关系、可达援助、实际同场人员与追击条件 |
| 同时遇到两宗冲突、败逃者或受伤代表 | 旁观、援助一方、掩护撤退、趁隙离开 | 个人感激与宗门相关责任分开，是否代表宗门报复须有依据 |
| 同宗不同队伍／外宗临时同盟 | 互认身份、重谈条件、交换消息或分道 | 真实宗门不变，临时支持方和队伍可以变化；同宗也可能因私利冲突 |

遭遇卡与队伍栏分开：前者显示“已接触／交涉中／敌对／最后见于某处”、已知宗门、代表权限和已确认同场人数；后者只列实际加入本队的人。点击遭遇对象可切换到该对象的博弈数值，不能因为观察或点击头像就把敌人加入队伍。

多人遭遇分别保留领队动机、个体动机与已知支援关系。比较“玩家对领队”时不能遗漏领队身边同场同盟造成的威胁；比较队伍时说明纳入了哪些已确认成员，不默认远方全宗都在场。背景随从先用数量级或匿名单位描述，只有交互与真实参战所需者才物化；未确认援军不提前进入玩家可见战力条。

实际参战者继承同一身份、伤势与资源，交涉破裂、离场再遇不会重新满状态。可观察到的行动会更新求宝、准备、信任、顾忌的估计，并写入带来源的日志；失败交涉不能靠重开窗口重抽结果。未知人物、先前只在传闻中出现的人物、原世界人物分别按原型／原 ID 解析，不克隆既有人物。

### 8.7 途中加入与离队

队伍是随探索变化的关系，不在入本时永久锁死。潜在来人和接触机会属于有限、固定种子的遭遇槽位，目的及境界原型提前冻结；实际出现由路线、同场条件和已发生局势触发。只有需要交谈、会合或参战时才物化，拒绝和离队不补刷新的陌生人。

- **加入**：先接触、听取其公开条件，由玩家接受或拒绝；NPC 也会依真实目的决定是否加入。核对原身份、同场地址、存活、拘禁、部署和其他占用；成功后同一事务更新队伍引用、有效约定、成员版本与日志。替某方站队一次不自动转成长期同行。
- **途中成员目的**：新加入者可以求宝、借路、避祸、找人、奉命观察或谋杀；同宗也不共享同一目的。目的可针对玩家或某位队员，队内因此会出现新的合作、猜忌、保护与冲突。
- **离队**：区分友好告别、目标完成、改投别队、分头行动、失联、被驱逐、敌对脱队、战死和真正离开副本。离队不等于出本，更不自动启动玩家冷却或清除该人的敌意；敌对离队者仍可能在合法后续节点重遇。
- **离开是否成功**：普通安全分开可以直接成立；已被围困、牵制或处于待决战斗时走真实逃离／冲突结算。玩家不能用踢人跳过袭杀，NPC 也不能靠离队按钮无条件瞬移脱困。既有 NPC 的后续真实移动仍沿原入口。
- **队伍变化的后果**：重算当前同场人数与可见战力、支援关系和分配承诺，不追溯分走玩家已经获得的物品。仅对后续真实收益执行有效约定；加入者不补领已结算报答，离开者不后台抢走背包。
- **再次相遇与恢复**：沿同一人物 ID、原目的进度、伤势、有限资源与既有交易，不刷新成无伤友善新人。加载不重新投加入／离队骰，旧页面提交必须核对当前成员版本与事件凭据，不重复入队或让已经离场者参战。

队伍卡和日志同步表现变化与公开理由，理由注明“自称”或“亲见”；不因离队自动把其真实目的全部公开。后台目的保持隐藏，玩家能够回看先前线索，自行判断当时的合作是否可信。

V0.7 界面演示从第 11 步开始：第 12 步陆衍请求结伴，未接受时不进入队伍；婉拒则留下未结伴日志并结束本段。接受后第 13 步同场人数从 2 变 3；第 14 步记录反复问询法力、催促改道的亲见行为，以及洛凝转述的点头示意；第 15 步离队，同场人数恢复为 2，保留“已离队”卡片、最后所见与全部先前记录。不存在被指定为“刺客”的演示真值，也没有可供前端泄漏的隐藏目的字段。

成员详情可跳到相关见闻，日志筛选不改成员状态；新步骤显示全部日志，避免沿用旧筛选而漏掉队伍变化。切回外缘时仅显示当时已知信息，再回近处恢复当前演示步骤。新队员未展示实力时，不按已识别境界编出战力；在整队对比中展示实际人数，并将缺少依据的整体战力标为未探明。离队后恢复原两人比较基准。演示回看是快照重放，不代表正式游戏可回退时间或重抽人物。


## 九、奖励：让机缘值得争，又不造成无限膨胀

### 9.1 玩家奖励与背景争夺分离

每个副本生成玩家可取得的奖励节点、条件与有界预算。NPC 抢到多少资源只是叙事，不扣这个预算。玩家错过某条路线、主动撤离或未能战胜守卫，可以失去那条路线尚未取得的机会；原因必须来自自己的探索结果。

物品一旦获得，按原库存和成长入口归玩家。此后只有玩家相关的真实结算能改变它：例如玩家明确答应交出某物，并在该次交付中实扣。不能后台结算一句“被某势力夺走”就悄悄删掉背包。

与玩家直接相关的索宝、劫夺仍可发生，但必须有真实交互、战斗／交付结果和唯一凭据；不能为了模拟其他 NPC 的收入另建一个复制库存。

副本新人物的战斗装备定义只负责能力投影，不因此额外建立可掉落的整套背包。击败该人物的玩家收益由对应奖励节点结算，避免战斗默认奖励与副本奖励各发一次。若参战者是原世界 NPC，其原有死亡、关系和财物处置沿既有权威规则执行，不复制该人物的资产，也不再补一份同源副本奖励。

### 9.2 四类收益共同支撑冒险

| 奖励类型 | 作用 | 实施边界 |
| --- | --- | --- |
| 当前修行资源 | 缩短本阶段实际培养过程，补充材料、机缘及道途相关资源 | 按原结算入口发放，遵守停滞、上限、转化、资格，不用万能机缘包代替所有资源 |
| 随机功法与法器 | 形成可感知的战斗手段和组合取舍 | 从已支持的战斗语义中选机制，附带有限属性预算、适用境界、能源要求和互斥条件 |
| 特殊传承与培养机会 | 改善邻域、秘法、法器等长期成长的具体瓶颈 | 具体接入哪个养成入口要逐项定义；不跳过原劫关、道途及转化资格 |
| 少量固定珍品 | 保留可辨识的名物和稀缺目标 | 固定物品也受副本参数、唯一结算与取得条件限制，不成为反复刷固定极品的入口 |

普通、稀有、史诗的随机物品由地图基础、品质、节点与奖励家族共同决定，并在地图上限内变化；史诗不能绕过该限制。传奇改用本界最高境界标尺，不乘地图强度折扣，不取玩家当前修为，也不被地图上限截断。名称、描写、数值和机制必须对应，不能写“破尽万法”却只加几滴气血。

传奇的正式奖励条目都依本界顶阶定标，不仅核心奖励如此。外围和浅层路线可以奖励更少、种类不同、未含核心传承，不能把单件奖励降为当地低阶物品来变相恢复地图限制。普通副本也可出现较好局部奖励，但不借随机越过其地图预算。

#### 9.2.1 传奇数值标尺与“略高”

以副本所属普通界面的合法最高境界及最高层数为锚点，为每类物品建立对应的顶阶成品数值预算 `B(本界顶阶, 奖励家族)`。传奇预算为 `B × (1 + ε)`，其中 `ε ≥ 0` 且有较小上限；建议首轮测试为 0～10%，具体上限待审。这个倍率不再乘地图系数，不以进入者修为升降，不直接把角色完整总战力作为单件物品的加成。各家族标尺仍需根据同阶成品与实际战斗补齐并校准，当前代码没有这份完整新标尺。

| 副本所属界面 | 当前源码最高境界锚点 | 传奇奖励的定标 |
| --- | --- | --- |
| 人界、魔界 | `cultivation_ceiling` 为化神九层 | 化神顶阶同类奖励数值或略高；无棣原传奇与古塞传奇使用同一境界标尺 |
| 灵界、真魔界、妖界、幻冥界、地狱界 | `cultivation_ceiling` 为大乘九层 | 大乘顶阶同类奖励数值或略高；不因下界真仙出现就全改成真仙奖励 |
| 仙界、修罗界、幽冥界、轮回界 | 当前可用修为体系最高为大罗九层；这些世界未填写 `cultivation_ceiling` | 显式绑定现行最高合法境界的同类奖励标尺，不把缺省值当作人界，也不创造大罗以上境界 |

正式配置须逐界面登记与校验奖励锚点，不以 `npc_realm_cap` 单独推断玩家成长上限。特殊空间沿已明确的宿主界面。生成时冻结锚点、标尺版本与系数，读档、换装备、带去其他界面使用均不重算成另一套数值。

“略高”作用于有预算的奖励数值，不把全部机制分别乘一次后再次累乘；也不等于自动高一个大境界、自动突破至臻上限或凭空提升仙凡力阶。材料数量、修行资源和成品属性分别采用本家族的顶阶口径，不能给灵石、仙痕和战力套同一个数字单位。

#### 9.2.2 仙凡关系独立判定

必须分别保存并验证：数值标尺、奖励品阶、攻击／防护性质、使用条件、能源类型、已修能力及当地压制。拥有物品不等于满足使用条件，使用条件也不能简化成“玩家必须已是真仙”。

- 当前 [物品资格](../cultivation_life/system/item_qualification.py) 按 `force_tier`、`immortal_attack` 等明确属性判断性质；[仙级本命法宝](../cultivation_life/system/immortal_artifacts.py) 还有独立晋升规则。新奖励沿相应资格入口，不因为面板数字大、名称写仙宝或品质为传奇就自动获得仙级伤害。
- 大乘标尺增加少量数值，默认仍是其明确配置的凡级性质；不能把 1.1 倍大乘奖励伪装成仙级。若某奖励明确属于仙阶，须另有合法仙阶定义和使用／培养条件，按原规则处理；不一律禁止下界持有，也不免费提供所需仙力。
- 仙级功法按现有仙力转化、道途、境界、修习和能源要求投影；法器按本类已存在的资格规则处理，不擅自给所有仙器加同一条新门槛。不能为显示出强度而把 `requires_immortal_power` 清除或把凡力冒充仙力。
- 邻域有真实能力来源与有限资源，不由物品攻击数值自动赠送；压制修为也不自动抹去本体已经掌握的邻域。真仙下界的资源、能力与当前法则约束仍按第四节。
- 真正攻击时核对主战功法／法宝及目标防护资格；仅持有重宝不自动使所有普通攻击变成仙级，队友的资格也不传给全队。高额凡级面板不绕过原仙凡防护与邻域机制。
- 获取页面可以说明已知的使用限制；未满足条件时物品仍归玩家，不能偷偷降阶、补能源或删除奖励。取得和激活分别结算，后续跨界不重新发奖或改变原物品属性。

#### 9.2.3 传奇直接产出合练成品

**第三级界面传奇具有很大可能直接获得合练版本，其他层级按本界传承对应处理。** 奖励是完整且已完成合练的功法，不能把“一袋散篇”“还差最后一部的套装”或只改了名字的普通书当作满足要求。获得成品不等于立刻学会或满级，仍区分持有、学习、装备、修炼和实际运转。

| 副本所属层级 | 合练成品方向 | 数值与气源边界 |
| --- | --- | --- |
| 第一层：人界、魔界 | 对应当地修行体系的完整归一传承／合练真诀，可直接作为成品取得，不要求再次收齐散篇 | 按化神顶阶同类成品定标，元力与用途沿该功法定义；不凭“合练”变成仙阶功法 |
| 第二层：灵界、真魔界、妖界、幻冥界、地狱界 | 对应本界体系的完整上乘合练传承 | 按大乘顶阶同类成品定标，按灵／魔／妖／鬼等实际定义运转；有明确仙阶来源时另核仙凡资格，不自动全转仙力 |
| 第三层：仙界、修罗界、幽冥界、轮回界 | 高概率直接取得本界体系的完整合练真传，仙界沿道统真传，其他界面沿自身传承体系建立成品 | 按大罗顶阶同类合练成品定标，气源、道途、修习与战斗资格继续分别校验；不全部套成仙界道统与仙痕培养 |

**建议概率口径**：对第三级传奇的主要传承奖励槽，直接配置高概率的合练成品类别；首轮可用 70%～85% 作待审试算。不能先低概率抽中“功法”，再宣称其内部高合练率就是整本容易获得；统计同时报告到达主要奖励节点后的成品产出率与实际活着带出的比例。不保证未到节点、外围撤离或死亡也获奖。其他层级同样配置成品产出，具体概率和种类待逐界校准，不退回默认只给散篇。

类型、传承 ID、配方、属性、效果、初始等级与奖励节点在生成时冻结。建议成品初始 Lv1，已经完成的是合练步骤，后续熟练度仍需修炼。一个合练成品按一份完整奖励预算计算；按第 9.2.1 节的“顶阶同类成品”标尺校准，不在已经合练的预算上再次叠原 2.2／1.8 倍属性、全部散篇属性及传奇加成。普通／稀有／史诗不因此取消地图限制。

现有代码需要适配的具体边界：

1. **获得成品与玩家自行合练是两种来源。** 原自行合练继续核对原书、修为、仙界转化与 24 仙痕等原条件；副本是获取前人完成的成品，无需玩家再次收齐原书或重复支付制作费。新增明确的奖励登记入口，复用权威物品／学习、传承记录、效果校验和一次发奖事务，不伪造原书已学标志，也不调用普通合练后退费。
2. **先持有，再依法学习与成长。** 修为、道途或气源不足仍可以取得冻结的成品载体；满足学习资格后沿统一入口登记。唯一成品身份、已掌握记录与合练成长记录一致；直接获取者不能再次“自行合练”复制同一真传。已经拥有同一成品时按预先冻结的重复奖励规则处理，不重复加属性或重抽新品。
3. **现有仙界编译器有真实前提。** 当前 `compile_manual` 要求至少六部原始功法，并使用原道统 ID 与定义；选择现有合法道统可复用其确定性编译与机制继承，但不能把随机一本书随意加 `mastery`。新副本传承要有自己的合法配方／身份及最小培养定义，不强制把配方中的散篇额外发给玩家。
4. **各界接入是新增工作。** 现有校验拒绝修罗／幽冥／轮回本体功法的合练标记，第一、二层也没有可直接套用的同等合练入口。需要版本化的各体系成品定义、合法效果校验及后续修习规则；原仙界“只能在仙界参悟”的普通入口不能成为其余界面奖励无法培养的死路。本次授权的是副本成品来源及其必要使用／成长接入，不顺带开放所有世界的自由合练制作。
5. **完整功法不附送完整道果。** 不自动集齐道统、升满道统、激发邻域、获得至臻或绕过三尸／劫关。仙界原真传加持继续受真实已修道统／邻域及较低等级约束。效果预算、实付能源、冷却和次数仍沿同类权威规则，不能因为“成品”变成免费常驻全效果。

该新增奖励来源及各体系培养的适用差异，在正式实现时同步登记至功法领域文档、校验合同和必要的跨界例外说明；仅有本策划不代表原源码已接受这些成品。本轮不修改现有功法、原存档中的合练书或发行版本。

### 9.3 各修行阶段要给真正缺的东西

- 低中阶的普通、稀有、史诗：在地图允许的范围内提供装备／功法改良及修行资源。传奇即使由低阶玩家取得，也保持本界顶阶标尺，是否立即可用另按原资格。突破辅助符合道途与境界，不把对某道途无效的丹药宣传成通用大机缘。
- 元婴至大乘：从现行真实瓶颈出发配置资源、机制和传承，避免只增加低阶平铺属性；必要材料的数额对照原培养成本。
- 真仙及以上：检查仙痕、仙脉、元力转化、邻域与对应道途成长条件。大额普通战力不能替代邻域对抗能力，大额机缘也不能替代缺失的专属资源。
- 道祖层次：回报可以改善至臻体系的实战配置、稀缺器物或其他实际可用成长，但不创造一个新的“道祖境”，也不承诺不存在的至臻以上境界。

不同道途均需有有效收益候选。副本的主题与核心内容仍由生成时冻结，不因换功法、换界面或领奖时修为上升而重抽。若设有多种可选奖励，候选集也在生成时固定。

### 9.4 建议的首轮奖励目标

普通、稀有、史诗用对应地图阶段的正常修行收益作校准参照，数值不能越过地图上限；传奇先遵守本界顶阶定标，再核对所得总量。不能用“玩家低阶，十个行动也不值多少”反过来压低传奇单件奖励。下列数量定位仍是调试目标。

| 品质 | 完成主要目标后的建议定位 |
| --- | --- |
| 普通 | 约相当于 0.5～1 个常规行动单位的有效成长，或一项价值相近的配置改善 |
| 稀有 | 约 1.5～3 个单位，或解决一处明确瓶颈的奖励 |
| 史诗 | 约 4～8 个单位，加一项具有长期用途的关键收获；不能全换成无限叠加的永久属性 |
| 传奇 | 奖励条目为本界顶阶同类数值或略高；节点深度决定取得数量、家族与核心传承机会，不降低单件定标。V0.2 的“玩家当前阶段 10～20 个行动单位”不再作为传奇强度上限 |

这里的“或”表示价值折算，避免把材料、极品装备、全部行动收益再次相加。不同阶段一个行动的实际收益差别很大，不能以同一个机缘数覆盖所有境界。只在外围搜刮或提前逃离，不获得整份通关预算。

传奇核心机缘应固定存在于生成蓝图，取得条件可以非常困难；满足条件并完成结算后，不再临时骰一个“空箱”。活着出本本身不等于已经获得核心宝物。

### 9.5 防膨胀手段

1. 地图总量有限、单本建议一次进入、全局退出冷却，阻止无限重复获取。
2. 节点、交易、战胜和报答全部使用稳定奖励 ID，一次取得；重新加载不能再次领取。
3. 物品预算、机制数量、力阶、资源消耗分别设界限。传奇使用本界顶阶预算与略高系数，不能用防膨胀之名重新套上低阶地图限制；主要通过生成次数、取得数量、唯一结算和实际使用条件约束。
4. 尽量通过既有装备／功法选择和机制搭配形成取舍，审查现有可同时生效数量。不能假设已有槽位限制能自动约束所有新物品。
5. 永久基础属性奖励单独核算跨地图累计上限；建议在副本奖励范围内设置递减或累计额度，具体公式待审，不修改其他玩法的成长规则。
6. 奖励定义在取得前冻结。不加入“囤到更高境界使用就无限增值”的新型比例奖励；已有固定物品的动态效果另行计入预算，不能悄悄修改全局物品规则。
7. 聚合同一结算批次的资源，避免拆分机缘骗取多次仙痕附带判定。

### 9.6 如何验证玩家是否值得去

在多个修为、道途、装备和邻域配置下，用同组种子比较：不参加、外围获利后退出、深入探索、争夺核心、援助弱势者。记录实际存活、所得有效成长、消耗、损伤及未来冷却，而不仅是物品面板总价。

需要同时成立：普通／稀有有稳定吸引力；史诗有合作和谨慎探索的价值；传奇核心成功者确实改变处境，但明显实力不足者直接参战非常危险。不能为保证“所有人都愿意进”把传奇调成低阶的稳赚地点。

具体胜率不预先写死。尤其不把“九死一生”强制解释成所有玩家、所有路线都只有 10% 生还率。

## 十、与现有系统的接入边界

本节描述未来实施责任，不表示以下新字段或模块已经存在。

### 10.1 最小持久状态

| 状态 | 所有者与保存内容 | 不保存什么 |

### 10.3 建议模块职责

- 生成层：读取地图方案，生成确定蓝图、奖励配方和轻量人物原型；不直接改玩家状态。
- 会话层：负责进入、步骤、选择、真实退出、冷却、事务与一次结算，调用现有权威入口。
- 人物决策层：从已知事实、动机和准备状态选择行为；不管理世界势力财富和 NPC 抢宝库存。
- 战斗适配层：把已登场角色和玩家接到现有多人战斗，保存真实资源消耗；胜负后进入原生存结算。
- 表现层：根据已揭示事实生成叙事，信箱与副本 UI 只读取可公开投影，不得到完整种子蓝图。
- 日志与局势层：从同一事件事实产生具有来源的消息和局势卡投影，按玩家获知范围更新横条；不另外随机一份与事件相冲突的战报。

新增文件名称在实施时确定。禁止用归墟行动、组队博弈、背刺和后台抢宝函数包装成新副本，也不把新状态塞进旧 `guixu_state`。与归墟共同依赖本体战斗、库存、生存等权威入口，不等于复用归墟玩法。是否替换旧玩法仍是产品归属问题，不改变本案独立实现行动与博弈的要求。

## 十三、威名与凶名拆分：本次更新的共同基础

### 13.1 数值含义与承接

**凶名接管原有威名的数值与惩罚职责。** 杀戮、背约暴行及原规则中的违法败露继续产生明确代价；警觉、原凶名型围杀、畏惧和相关和解仍有实际作用。凶名不等于某宗的仇恨，原人物恩怨、势力敌意、通缉保持各自归属。

**新威名独立反映威望、实力和综合素质。** 它用于评价玩家是否值得敬重、争取或合作，并参与 NPC 邀约。威名和凶名可以同时很高，不能相减成一个净值；高威名不赦免杀戮代价，高凶名也不抹去玩家实际能力。

例如旧值为 600，承接后凶名为 600，不把其中一部分猜测为正面经历，也不再给新威名复制 600。新威名由原成长事实与独立威望依据计算。这是正式版的承接要求，不代表本轮已改写存档。

### 13.4 新威名的来源与防刷

建议采用四项统一投影，具体权重、缩放和等级称谓待校准：

- **实力基础**：原人物真实修为、符合资格的战斗能力及修炼成就，不另存一套战力。伤势、空蓝和临时消耗不必立刻抹去社会评价；切装、压制和解除压制不反复生成事迹。
- **地方威望**：在当前界面／实例实际建立的声誉、履行职责、帮助同道和完成公开事务等，均有事实依据。
- **已确认功绩**：重要斗法表现、救援、守约合作、主持法会、履行宗门责任等，以事件 ID、目标和结算凭据去重。
- **专业素质**：阵法、炼器等实际造诣与已有资格。专业能力另用于邀约适配时，避免与威名中的同一项无上限重复加权。

形式为 `威名 = 实力项 + 地方威望项 + 功绩项 + 专业项`，UI 展示总值并可查看依据。这不是复制旧 `fame`，也不把威名视为可以花掉的货币。建议只持久化必要事迹记录，其他项从权威成长状态计算；记录过期／失效有各自规则，不能读一次面板就记一次成长。

威名不是杀人数榜。击败强敌、保护盟友可以凭功绩获威望；同场发生的杀戮另记凶名，两条结算各有依据且不相抵。反复杀低阶、重复切磋、传播同一消息、加入退出队伍不能无限刷分；处理恶名目标也不能成为免代价刷威名的入口。

玩家可以查看自身综合威名。NPC 邀约与交涉使用其已知或合理获知的评价：未识破的本体、秘法和未公开功绩不能从一个总分泄漏。区分原人物能力、地方已传播评价和该 NPC 当前所知，不扩展为全世界逐人传播模拟。

### 13.5 新威名参与 NPC 邀约

先核对副本已生成、可联系与到场、存活和占用等硬条件，再比较合作收益。建议因素结构为：

`邀请评价 = 已知威名贡献 + 关系／守约评价 + 实力／专业适配 + 共同目标收益 − 凶名合作风险 − 分配与竞争风险`

上述是以合作为目的的评价，不涵盖所有动机。谋杀／刺探型邀约先依其真实目的评价接近玩家的价值与代价，公开说辞可伪装为合作；不能因正常合作评分低就禁止它邀约，也不能把高威名当作善意保证。威名仍影响对方对目标的判断，但不取消其固定目的或直接降低谋杀意图。

这还不是已校准的概率公式。威名对被考虑为合作对象具有正向贡献，但不保证所有 NPC 都邀请最高威名者：对方也可能担心被压制或机缘被夺。高凶名人物可以被急需强援的 NPC 接纳，但属于承担风险的选择，不是凶名被当作荣誉加分。

| 玩家情形 | 邀约倾向示例 |
| --- | --- |
| 威名较高、凶名较低，适合当前目标 | 更容易被主动争取合作，谈判条件可以更有利 |
| 威名与凶名均高 | 有强援价值，但守约与安全顾虑上升，可能要求明确约定、同盟保障或放弃邀请 |
| 威名尚低，有紧缺专业能力 | 仍可能被邀请，避免新角色没有参与机会 |
| 威名很高，但实力／利益与对方严重不匹配 | 可能被回避或只邀请处理特定事项，不强制组队 |

按“原 NPC／邀约角色 ID＋固定副本 ID＋有效评估时机”保存判定回执。威名变化可以在新的合法时机改变评价，不能反复开信箱、换装备或读同一信件给同次邀请重投骰。拒绝不换副本，已发邀请不重抽品质；接受与入本仍核对原人物状态。

威名影响合作与谈判，不改变既有奖励种子、不补传奇次数，也不意味着高威名者绝不会被背叛。宝物需求、准备、关系与双方实际能力继续参与本内博弈。

### 13.6 作用域、存档和 UI

当前 `fame_by_world` 实际使用跨界系统的作用域键，包含不同失落空间实例。凶名承接这套归属：普通界面、独立实例分开，原界凶名不凭空向另一界签发追杀，返回时恢复原值。活动值与映射旧快照可能暂时不同，承接逐字段保留，不相加、不取最大值、不拿旧映射覆盖已经结算的当前值。

新威名的实力依据随原人物成长；地方威望事迹建议按同一作用域保存。跨界不删除个人功绩，也不自动让异界 NPC 知道原界全部评价。独立副本内的杀戮如需向宿主界面传播，必须有明确事件与一次凭据，不能出本时复制全部凶名又再记一次。

当前源码及 [存档规范](save-code-format.md) 只支持结构 12，尚不做该结构的字段转换。原值归凶名是本次确定要求；正式版须显式定案结构编号或子版本以及结构 12 的单次承接入口，不能删掉 `fame` 后让新字段默认 0，也不能擅自丢弃旧值。结构 1～11 仍拒绝，不能借本次拆分恢复兼容。

正式承接只在明确版本边界识别旧字段，之后玩法只使用新名称。若旧、新字段同时存在且冲突，报错并保留原文件，不静默选择。沿备份和原子提交保护原存档；本轮不升级结构、不改合同字段、不转换用户存档。具体发布版本方案在实施前随本策划一并审定。

存量旧数值整体归凶名，不回放历史猜测“其中多少应当是威名”。新威名初始化读取确定的原成长和有明确映射依据的事迹，不消耗 RNG、不推进时间、不补邀请或奖励。待决事件、冻结的后续奖励和旧历史显示逐项审阅，保留原事件身份、已付代价与确定结果，不清空重抽。

UI 并列显示“威名”和“凶名”，各有数值、含义与来源。高威名用正面评价，高凶名明确提示风险，不再使用一个混合的“声名显赫／凶名震世”评语区。邀约可表述“慕名相邀”“看重你的阵法造诣”等公开理由，不暴露对方完整隐藏评分。两种名声的值与队伍内信任／敌意仍是不同指标。

### 13.7 正式实现专项验收

1. 多组旧活动值、作用域值、佛修有效值与撤令记录无损承接；新威名不复制旧值，两个数值不相加、抵消或互相覆盖。
2. 单独提高威名不触发凶名围杀；单独提高凶名不获得正面声望许可。原道途阈值、佛修庇护边界和具体势力恩怨继续有效。
3. 杀戮记应有凶名；非致命胜利、救援、弘法等按事迹记威名；同一事务的重复提交、读档和页面恢复不重复加分。
4. 相同候选与固定种子下，威名对邀请评分确实有贡献，凶名风险和关系、适配仍独立生效；高威名不绕过 NPC 占用或到场限制。
5. 跨界、不同空间、封印、夺舍和切装不复制数值、洗掉凶名或重复制造邀约；未知人物能力不通过威名总分或 UI 泄漏。
6. 检查本体、DLC 启停、Debug、事件、公开 API、页面和教程。旧 `fame` 只留在明确旧档承接、旧数据测试和历史说明中，不再是正式玩法依赖。
7. 修改持久字段时同步人工更新 [状态归属合同](world-transition-state-contract.json)；只读威名投影不误当作可直接写入资源。实际实施补齐名声领域、跨界、事件加载／提交与真实浏览器验收，本轮文档检查不能代替。
