## 1. 设计理念

> 艰苦是“进得去，还得出得来”；机遇是“越深越好”；风险来自觊觎宝物的修士和被困后流逝的寿元，而不是地图陷阱。

归墟是各界之外的界隙。各界遗落之物随潮汐汇入潮眼，每一处潮眼周期开闭，形成一座大型副本。归墟不通向轮回界，避免占用轮回设定。

三条核心反馈环：

| 环 | 正反馈 | 制衡 |
|---|---|---|
| 深入 | 越深宝物价值、气浓度和重宝概率越高 | 返程更长、修士更强、携宝后更易遇袭 |
| 时间 | 早入场预算更大，更容易取得无主宝物 | 宝物会随副本计时落入 NPC 手中，窗口耗尽则被困 |
| 被困 | 高气浓度可用于长期静修，最终突破出局 | 外部时间恢复流动，寿元照常消耗，寿尽必然坐化 |

宝物池会被历届参与者持续消耗。宝物搬空后副本仍按周期开启，但转为高气浓度的静修场，不再生成夺宝修士和夺宝事件。

## 2. 首版范围

### 2.1 本期实现【已定】

1. 人界大型周期副本“沧海归墟”1 座。
2. 灵界大型周期副本“虚天尾闾”1 座。
3. 每座副本四个常规层加一个秘层。
4. 预告、开启、闭合、下次开启的完整生命周期。
5. 开启期天级预算、外部时间冻结、窗口耗尽后被困。
6. 锚定副本而非玩家的参与修士名单。
7. 探宝、夺宝、遁走、求生交涉、拉拢、宝物交涉。
8. 每座 60 条独立宝物条目，覆盖功法、装备、丹符阵器、灵植灵药、炼器材料、灵石资源匣。

- 不制作魔界、真魔界、地狱界、妖界、仙界副本。
- 不做多人联机组队。
- 不做宗门名额、外交配额或跨 DLC 专属联动。
- 不改写本体的角色死亡、夺舍、轮回等结算。
- 不引入通用临时地图框架；首版以归墟专属状态和界面承载天级玩法。

### 2.3 复用的本体能力

- 扩展包发现、启停、JSON 合并与内容校验。
- 物品、功法、事件、成就的既有数据格式。
- 可复现随机状态 `rng_state`。
- 世界 NPC、临时遭遇目标、队伍战力和关系快照。
- 战斗目标、战斗报告、物品/功法发放与角色死亡流程。
- 年度世界结算、寿元、灵田、NPC 演化和世界新闻。
- 历史记录驱动的成就判定。

## 4. 生命周期与时间模型

### 4.1 生命周期

```text
关闭 → 预告 → 开启 → 闭合/结算 → 关闭
```

- 预告时从剩余宝物池抽取本届 6 件，不放回；其中价值最高的 1–2 件展示为重宝。
- 开启时生成本届修士名单、宝物所在层和各宝物的 NPC 取得时刻。
- 闭合时结算匿名修士、固定 NPC、被困者与宝物去向，并生成战报。
- 玩家不参加时仍进行同一套可复现结算，世界不会等待玩家才消耗宝物。
- 池内不足 6 件时全部进入本届；池空后预告只显示“归墟已空，仅余潮汐灵机”。

### 4.2 三种时间状态

| 状态 | 外部时钟 | 副本预算 | 寿元 | 层间移动 |
|---|---|---|---|---|
| 在外 | 正常 | 无 | 正常 | 本体地图按年 |
| 开启期在副本内 | 冻结 | 按天减少 | 不增加 | 按天扣除 |
| 窗口耗尽且被困 | 正常 | 无 | 正常 | 不消耗外部年份 |

开启期行动耗时【占位】：探宝 2 天、战斗 1 天、交涉 1 天、事件 1 天。行动开始前始终显示“剩余天数 / 从当前层返程所需”。行动耗时可以越过最后一天，行动完成后再转为被困。

### 4.3 多年行动的中断

本体虽然按境界提供 1、5、10、20、50、100 年等行动单位，但内部仍逐年循环。归墟生命周期在年度循环内检查：到达预告年或开启年时设置待处理事件，现有 `pending_event` 机制自然中断剩余年份并把控制权交还玩家，不另造第二套长期行动账本。

### 4.4 出局

1. 窗口内沿原路返程，扣除对应天数，回到入口地域。
2. 被困后等到下一届开门，原地恢复新一届天数预算，再决定返程或继续探索。
3. 修到“突破传出线”时立即传回入口地域，保留战利品。
4. 被困期间寿元耗尽时走本体坐化流程，没有豁免。

开启期不允许按年吐纳；修炼收益只来自事件。被困期恢复本体按年修炼，使用所在层的气获取效率。

## 5. 修士、遭遇与怀璧其罪

### 5.1 名单锚定副本

参与者境界只由副本的最高可入修为和层级权重决定，不随玩家缩放。

| 层 | 相对最高可入档位【占位】 | 保底 |
|---|---|---|
| 终层 | 最高档 20% / 次高档 60% / 再下一档 20% | 至少 2 名处于最高可入修为 |
| 内层 | 次高档 60% / 再下一档 30% / 更低档 10% | 至少 1 支两人小队 |
| 中层 | 中高档为主 | 可出现小队 |
| 外层 | 中低档为主 | 至多 1 名同侪，且占比不超过 15% |

名单由两类角色组成：

- 匿名修士：保存在本届副本状态内，不进入世界 NPC 池，闭合后移除。
- 固定 NPC：引用现有 `SectNpc`，每层至多 2 名。其死亡、撤离、被困和携宝结果可延续到世界中。

### 5.2 关系保护

师父、弟子、道侣、道友、玩家所纳侍妾均不主动攻击玩家。它们仍可能持有宝物，玩家可交易或交涉；若玩家主动杀人夺宝，必须经过两阶段背叛确认。

### 5.3 怀璧其罪

```text
遭遇权重倍率 = min(2.0, 1 + 0.5 × 所携副本宝物总价值 / 当前层参考价值)
```

只计算本次副本取得且尚未离开的宝物。空手者不受加成，携带重宝者返程最危险。

### 5.4 遭遇选项

| 选项 | 规则 |
|---|---|
| 交战 | 副本争夺战默认为致命战斗 |
| 遁走 | 根据境界差、神识、装备和队伍战力判定；失败转战斗 |
| 求生交涉 | 付出灵石、物品或战利品份额换取放行 |
| 拉拢 | 临时加入现有队伍，闭合或离开副本时离队 |
| 宝物交涉 | 对持宝者报价、加价或交换指定筹码 |

拉拢上限为 2 人【占位】；每人约定 30% 战利品份额【占位】。结算时份额不足会降低好感，匿名队友可能反水，关系人物只会退出或拒绝继续协助。

## 6. 宝物池总规则

### 6.1 独立宝物条目

- 每座副本恰有 60 条主池条目，共 120 条。
- “唯一”指 `pool_entry_id` 在整个存档世界中只会被发放或永久结算一次。
- 功法和装备通常对应一个内容 ID；灵石匣对应一次固定数量的下品灵石发放。
- 为复用本体货币，首版不新增中品/上品灵石币种，所有资源匣均折算为 `spirit_stone` 数量。
- 可堆叠内容的唯一性落在池条目而不是背包物品实例上；例如“潮纹石匣·甲”只开一次，但开出的下品灵石并入现有堆叠。
- 每届固定抽 6 条，完整池理论上约 10 届搬空；考虑 NPC 携出、玩家夺回和永久消失，长期体验目标为 8–12 届完成主池消耗。

### 6.2 分层与持有时刻

预告时确定本届条目，开启时为每条生成：

```text
pool_entry_id, content_kind, content_id/quantity, tier,
layer_id, claim_at_day, holder_id, resolution
```

- `claim_at_day` 之前，玩家抵达对应层并成功探宝即可取得。
- 到达 `claim_at_day` 后，条目由该层名单中的一名 NPC 持有。
- 玩家只能通过交易、宝物交涉或击杀持有者取得。
- 宝物权属只保存在条目上；NPC 名单不再复制一份权属数组，防止双源数据漂移。

### 6.3 闭合结算

| 持有者 | 结果 |
|---|---|
| 玩家 | 已进入背包或功法列表，永久离开主池 |
| 匿名修士 | 匿名修士消失，条目永久结算为失落 |
| 固定 NPC 撤离 | 条目继续绑定该 NPC，可在世界中追索 |
| 固定 NPC 被困 | 条目留在副本，后续可再次遭遇 |
| 无主且无人取得 | 条目回到剩余池，不视为消耗 |
| 固定 NPC 陨落 | 玩家造成的击杀正常掉落；离线结算陨落则条目失落 |

### 6.4 搬空后

- 副本照常预告和开启，但不显示重宝。
- 不生成新的夺宝名单，包括秘层 NPC。
- 事件池过滤 `treasure`、`robbery`、`carrier` 标签，只保留修炼、悟道、孤寂和秘层线索事件。
- 搬空前已经被困的固定 NPC 继续存在，直至撤离、陨落或被玩家处理。

## 9. 交涉、交易与背叛

### 9.1 求生交涉

判定输入：个人好感、威名、双方境界差、双方队伍战力比、玩家携宝价值和筹码价值。

| 结果 | 说明 |
|---|---|
| 放行 | 支付筹码后结束遭遇 |
| 索价 | 对方给出更高价，玩家可接受、还价或拒绝 |
| 破裂 | 转为战斗 |
| 拉拢 | 对方成为临时队友，并登记战利品份额 |

### 9.2 宝物交涉

```text
p = clamp(
  基础概率 + 好感/关系修正 + 筹码价值比修正
  - 稀有度惩罚 + 威名修正 + 境界差修正,
  p_min, p_max
)
```

结果为成交、加价或拒绝。关系人物拒绝时不会直接转为战斗。普通敌对修士在玩家恶意压价或威胁失败时可能翻脸。同一 NPC、同一宝物在同一届只能正式议价一次；固定 NPC 离开副本后冷却 1 个外部年【占位】。

### 9.3 主动击杀关系人物

- 不提供一步“直接击杀夺宝”。
- 第一步明确显示关系、因果、威名和可能引发的报复。
- 第二步确认后才进入致命战斗；成功时解除关系、结算因果与威名、掉落其所持副本条目。
- 此流程对师父、弟子、道侣、道友和玩家所纳侍妾一致生效。

## 10. 秘层与被困期

### 10.1 秘层解锁

- 外、中、内层可出现潮纹/界纹线索事件。
- 选择细察后进行神识判定，累计 3 条线索解锁秘层通道【占位】。
- 开启期未发现秘层且玩家被困后，每个外部年有 5% 概率触发补充线索【占位】。
- 主宝物池未空时，秘层每届有 1% 概率出现 1 名 NPC【占位】；主池搬空后不再生成。

### 10.2 秘层奖励

秘层奖励不消耗 60 条主池，也不产出新的永久唯一重宝。奖励限于：

- 当次修炼机缘、功法经验、神识经验、炼体积累。
- HP/MP 恢复、心魔缓解和突破准备。
- 少量通用灵石或非唯一材料。
- 被困期用于缩短静修破关时间的悟道事件。

### 10.3 被困期

- 外部世界恢复逐年演化，寿元、灵田、NPC、战争、拍卖等走本体年度结算。
- 五层之间移动不额外消耗外部年份，只改变下一次行动所在环境。
- 不再生成匿名修士；遭遇只来自闭合时同样被困的固定 NPC。
- 下一届开启时，被困者仍在原层，重新获得该届完整窗口预算。

## 12. 数据定义

首版副本规则集中在扩展专属 `guixu_tide.json`，普通内容继续使用本体已经支持的文件。

```text
dlc/guixu-tide/
  manifest.json
  content/
    guixu_tide.json       # 两座副本、层、周期、参数、60+60 条池条目
    items.json             # 装备、丹符、灵植、材料的 Item 定义

    guixu_events.json      # 开启期、被困期、秘层与交涉事件
    achievements.json      # 成就定义
```

`guixu_tide.json` 建议结构：

```json
{
  "schema_version": 1,
  "settings": {
    "draw_per_cycle": 6,
    "action_days": {"search": 2, "combat": 1, "negotiate": 1, "event": 1}
  },
  "dungeons": [
    {
      "id": "guixu_human_canghai",
      "world": "human",
      "entry_location_id": "lancang_sea",
      "max_entry_rank": [4, 9],
      "eject_rank": [5, 1],
      "period_years": 100,
      "announce_lead_years": 10,
      "window_days": 90,
      "layers": [],
      "treasure_pool": []
    }
  ]
}
```

条目引用统一使用：

```json
{
  "id": "canghai_tech_01",
  "kind": "technique",
  "content_id": "TECH_GUIXU_TIDE_RETURN",
  "tier": "major",
  "layer_weights": {"outer": 0, "middle": 1, "inner": 3, "final": 6}
}
```

灵石匣使用 `kind: "item_bundle"`、`content_id: "spirit_stone"` 和 `quantity`，不新增货币类型。

## 13. 存档与单一数据源

在 `GameState` 增加一个可选、可默认、可冻结的 `guixu_state: dict`，不把副本状态拆散到 `Player`、`auction_state`、`pending_event` 等多个容器。

```text
guixu_state:
  cycles[dungeon_id]:
    phase, cycle_index, next_announce_age, next_open_age
    pool_remaining[]
    round_entries[]:
      pool_entry_id, layer_id, claim_at_day, holder_id, resolution
    roster[]:
      actor_id, actor_kind, npc_id?, layer_id, rank, status
    last_report{}
  player_session:
    dungeon_id, cycle_index, layer_id
    remaining_days, trapped, entered_cycle
    clue_count, secret_unlocked
    recruited_actor_ids[], promised_shares{}
    negotiation_attempts{}
```

数据所有权约束：

- 条目权属只在 `round_entries[].holder_id` 保存。
- NPC 状态只在 `roster[]` 或被引用的 `SectNpc` 保存。
- 玩家真正获得内容后进入现有背包/功法列表，副本状态只记录条目已结算，不复制物品对象。
- 所有随机选择都消费现有 `rng_state`；不额外保存 Python `Random` 对象或第二随机种子。

## 16. 测试与验收

### 16.1 核心自动化测试

1. 两座副本定义、入口地域与修为边界合法。
2. 每座恰好 60 个不重复 `pool_entry_id`，分类计数为 10/12/8/10/10/10。
3. `content_id` 全部存在，功法和物品类型匹配。
4. 每届抽取 6 条、不放回、不超剩余；无主未取条目可回池。
5. 相同存档随机状态生成完全相同的名单、层、取得日和持有者。
6. 开启期行动只扣天数，不增加年龄、不推进世界。
7. 窗口耗尽转被困；被困年度推进完整调用本体世界结算。
8. 返程、下一届开门、突破传出三种出局方式正确。
9. 终层强者保底、同侪上限和固定 NPC 上限正确。
10. 师父、弟子、道侣、道友、侍妾均不会主动攻击。
11. 关系人物主动击杀必须经过两阶段确认。
12. 匿名修士、固定 NPC 撤离/被困/陨落的宝物结算正确。
13. 搬空后无新名单、无夺宝事件，但副本仍开启且可修炼。
14. 禁止的外界 API 在归墟内由服务端拒绝。
15. 旧存档缺少 `guixu_state` 时无损加载。
16. DLC 关闭并重启时，在副本内的玩家安全传回入口地域，其余状态冻结。

### 16.2 长期模拟

每座副本至少模拟 2,000 年、20 个随机种子，输出：

- 主池搬空所需届数，目标中位数 8–12 届。
- 玩家早入、中入、晚入的无主宝物获取率。
- 各层收益、死亡率、被困率和返程失败率。
- 固定 NPC 携宝进入世界的数量，防止世界长期状态膨胀。
- 搬空后 1,000 年运行稳定性。
- 存档体积增长和单次年度结算耗时。

   - 一个 `GuixuSystemMixin` 同时承载纯规则和薄编排；首版规模不足以拆成 `dungeon_system.py + dungeon_runtime.py` 两套模块。
   - 负责生命周期、名单、主池、天级行动、闭合、被困、交涉和公开视图。
5. `cultivation_life/engine.py`
   - `GameEngine` 继承 `GuixuSystemMixin`。
   - `advance()` 年度循环中调用 `_advance_guixu_calendar()`；它只在边界设置事件或闭合结算。
   - `present()` 增加一个 `guixu_tide` 公开字段。
   - 所有外界操作共用 `_assert_guixu_operation_allowed(operation)` 服务端守卫。
6. `cultivation_life/map_runtime.py`
   - `travel_map()` 只需在入口地域正常旅行；实际入场使用归墟 action，不改变 `player.location_id` 为虚构层 ID。
7. `cultivation_life/economy_system.py`
   - 将 `_grant_auction_content()` 的通用部分提取为 `_grant_trade_content()`，旧拍卖方法保留包装调用，避免回归。
   - 不复用 `_private_trade_attendee()`，因为它强制要求拍卖会开启。
8. `cultivation_life/concubine_system.py` 与关系 helper
   - 统一关系 ID 查询纳入 `player.concubines`。
   - 从魔修生擒流程抽出“查找关系人物、从队伍移除、解除角色关系、写后果”四个通用 helper；原生擒流程继续调用这些 helper。
9. `cultivation_life/server.py`
   - 只新增一个 `/api/games/{id}/guixu-action` 分支，payload 用 `action` 区分入场、移动、探宝、返程、交涉等，避免路由膨胀。
10. `web/guixu-panel.js`、`web/index.html`、`web/app.js`、样式文件
    - 独立渲染面板；主 `app.js` 只负责调用 `renderGuixu(data.guixu_tide)` 和公共 mutation。

### C.3 不做的架构改动

- 不修改 `MapCatalog` 支持天级路线、动态世界或临时图。
- 不把归墟状态塞入 `auction_state`、`active_trial`、`pending_event.runtime` 或 `encounter_npc_cache`。
- 不为两座副本引入通用 ECS、任务总线或新的数据库层。
- 不复制一套物品、功法、战斗、队伍、成就和 RNG 实现。
- 不让 DLC JSON 携带可执行 Python 规则。
- 不为每个归墟按钮增加独立服务端端点。

### C.4 核心数据流

```text
guixu_tide.json（只读定义）
        ↓
GuixuSystemMixin（规则与状态迁移）
        ↓
GameState.guixu_state（唯一运行态）
        ↓
present().guixu_tide（只读公开视图）
        ↓
guixu-panel.js（渲染与提交 action）
```

所有 mutation 都遵循现有引擎模式：`_load → 状态校验 → decode_rng → 修改状态 → 写 HistoryRecord → encode_rng → store.save → present`。前端不预测宝物归属、行动结果或剩余天数。

### C.5 生命周期接入点

`_advance_guixu_calendar(game, rng)` 放在每个年度已增加年龄、寿元检查尚未导致死亡之后，并在普通随机遭遇之前运行：

1. 命中预告年：抽取本届六件、写预告事件，返回中断。
2. 命中开启年：生成名单与取得日、写开启事件，返回中断。
3. 命中闭合边界：结算未完成届次、写战报；玩家在内则切为被困。
4. 非边界：不做任何工作。

被困玩家执行“修炼一年”时，归墟 mixin 主动调用现有 `_advance_world_year()`；开启期执行天级 action 时不调用 `advance_player_age()` 和 `_advance_world_year()`。

### C.6 交易与内容发放

归墟交涉只复用底层能力：

- `_catalog_price()` 作为基础价格。
- 提取后的 `_grant_trade_content()` 发放 item/technique。
- `add_item/remove_item` 处理灵石和筹码。
- `_find_npc()`、`_adjust_person_affinity()` 处理固定 NPC 好感。
- 匿名修士好感仅活在 roster，闭合后删除。

这样不会伪造一个拍卖会 attendee，也不会让归墟交易污染 `auction_state`。

### C.7 DLC 关闭与旧档

- 开关本就要求重启，因此在 `GameEngine` 初始化后首次 `_load()` 时检查内容是否启用。
- 若 DLC 未启用且 `player_session` 表示玩家正在副本：将玩家送回该副本保存的 `entry_location_id`，清空活动 session，写一条安全传出历史；`cycles` 原样保留为冻结数据。
- 若玩家不在副本：整个 `guixu_state` 原样保留，不推进周期、不结算主池。
- 已进入背包的 `Item` 和已学 `Technique` 在存档中是完整快照，关闭 DLC 不删除；但所有仍依赖 catalog 查找的使用路径必须纳入关闭 DLC 回归测试。
