# 浮生问道 · 特质与战斗属性策划案

V0.2 审阅稿 · 2026-11-24 · 以本体 v3.15.0 为讨论基线

## 本轮实装与试玩参数

玩家与 NPC 共用一次出生抽取，每次至多获得一项先天特质。空结果 80%，绿色 14%，蓝色 4.8%，紫色 1.1%，橙色 0.1%，同档等权。玩家按开局种子抽取，固定人物按该种子和固定身份抽取；使用动态编号的人物按该种子及同一来源的出生次序抽取，次序随档保存。同一种子复现相同出生结果，洗去后读取存档仍保留洗练结果。本轮采用存档结构 13。结构 1–12 在加载和导入时拒绝，已有文件保留；新人物的出生结果随档保存。试玩规则采用五行顺克、阴阳互克 ×1.2，五行逆克、风雷互抗 ×0.8，单项抗性上限 80%。星辰之体暂按物理伤害提高 12% 试玩。鱼鳞之体与五行之体可跨等级共存，鱼鳞之体与星辰之体按等级覆盖，赤炼筋骨与星辰之体须先洗去冲突项。

指定功法达到 Lv.9、对应神光精修至十重时检查授予。鱼鳞犀皮、鳞甲护身诀、坎道玄光可凝成鱼鳞之体。周天星辰体凝成星辰之体。五行转岳诀、五行界轮经和乾古素光凝成五行之体。大日真火采炼诀、太阳真火引、离上朱光凝成五行之焰。五行之焰可为两门真火功法选定攻击属性。试玩期洗去与重炼免费，重炼核验实际记录的大成来源。

2026-11-25 新增 101 项功法传承，其中绿色 42 项、蓝色 36 项、紫色 21 项、橙色 2 项。现有特质共 213 项。新增绿蓝也可随出生获得，紫橙通过修炼或指定法宝参悟取得。太元归墟剑大成可得紫色剑心「剑道阑珊」，开战时敌方全体各损失自身最大态势的 10%，之后可正常回满。配气特质在原招式定色后重新分配同一击的属性份额，物理份额保留。两项后天橙色分别由河图溯道经与蝉蜕玄章授予。[本批全部名称、效果与传承来源](trait-repertoire-catalog.md)

## 一、已确认的设计

1. **特质可先天获得，也可通过修炼取得。** 玩家与 NPC 均可获得先天特质，也可通过功法或神通大成获得特质。玩家创建新存档时有概率获得先天特质，例如「昊天之仙」，使本人所有修为境界的突破概率提高 25 个百分点，沿用各判定原有的概率上限。纯劫战不额外提供护持。指定功法或神通大成后也可取得特质，例如五行之体、五行之焰、星辰之体、鱼鳞之体。不同功法或神通可以授予同一个特质。
2. **特质有类型、等级、兼容性和稀有度。** 先天和修炼所得特质均按稀有度由低到高分为绿色、蓝色、紫色、橙色四档。 同类可替换特质由高等级覆盖低等级。设为兼容的同类特质可以跨等级共存。互斥特质必须先洗去冲突的一方，等级再高也无法直接覆盖。橙色特质须提供特殊机制，常驻提高境界突破概率属于已确认的例外。
3. **功法和法宝具备战斗属性，灵根要求单列。** 无灵根要求的功法也可以发动水属性攻击。凡、仙作用层级继续由原有规则独立判定。
4. **攻击伤害有明确类别。** 原先讨论中的纯无属性攻击统一称为物理攻击。物理伤害有独立倍率，五行、阴阳、风雷等属性的克制和抗性对物理部分均无效。
5. **属性克制影响实际伤害。** 五行按相克方向攻击时增伤，逆相克方向攻击时减伤。阴阳双向克制，风雷双向抵抗。各属性抗性独立削减对应伤害。
6. **邻域是大道。** 邻域独立执行大道对抗、庇护、封禁及施权。邻域本身及其施权伤害沿原流程结算，属性计算用于实际发生的普通出手、功法招式、神通和法宝攻击。

## 二、特质取得、覆盖和洗练

以下为 V0.2 建议。特质使用统一编号，类型、等级和稀有度写在特质定义里，同一特质通过不同来源获得时使用同一稀有度。人物的已得特质、功法或神通的大成记录、战斗中的临时效果各自按原归属保存。甲功法和乙神通都授予鱼鳞之体时，角色只拥有一份鱼鳞之体，来源可在习得记录里显示。配置同一门功法的多个栏位也只计算一次。

| 判定 | 建议处理 |
| --- | --- |
| 已拥有相同特质 | 保留原特质及其等级。可追加实际修成的来源，效果只生效一次。 |
| 存在互斥 | 比较指定特质或类型，按双方的限制共同核验。任一方互斥即阻止取得，先处理互斥、再比较等级。 |
| 同类且设为可覆盖 | 新特质须高于所有待覆盖的特质。符合条件时一次替换全部冲突项，兼容项保留。同级时保留现有特质。 |
| 设为兼容 | 各自生效。等级较低的一方继续提供其能力，具体数值仍服从战斗叠加规则。 |

**建议默认关系。** 同类型的特质默认比较等级并覆盖，内容可以显式指定同类共存或互斥。不同类型默认共存，互斥可点名特质、指定类型或覆盖全部其他特质。规则引用须可查，审核时尤其要核对锁住的是体质、神通特质还是全部特质。

**大成与洗练。** 沿用原修行和升级入口，在最后一步预告「获得」「覆盖」「共存」或「因某特质受阻」。建议允许功法本身完成大成，即使对应特质因冲突暂未炼成。已大成的来源可在条件恢复后通过明确的重炼入口尝试凝成。覆盖和洗练移除当前拥有的特质，既有大成记录保留。通过另一门尚未大成的合法来源也可重新获得，但仍须通过同一套兼容校验。洗练与重炼的工时、代价和地点待定。

### 先天特质与全局加成的接入建议

**建档时抽一次。** 普通、快速预设和自定义开局共用 `create_game`。建议在开局配置完成后、写入出生履历与首次保存前，用实际开局种子派生独立随机序列，按配置概率抽取，允许空结果。现有妖、鬼出生配置已有派生随机序列的先例。抽中的特质经过与大成授予相同的去重、覆盖和互斥校验，随本次出生一起保存。读档、导入和打开人物详情只读取结果。若将来加入改变资源上限的先天特质，建档时须按最终特质统一完成初始资源计算。 [角色创建](../cultivation_life/engine/orchestration/session.py) · [出生随机序列先例](../cultivation_life/engine/orchestration/dlc_birth.py)

**只保存归属，按用途计算效果。** 建议给每项特质配置有限的效果类型、数值单位、作用对象和叠加规则。领域公式按具体用途查询当前有效特质，取得逐来源明细与合计。第一项用途为「持有者本人的修为境界突破概率」。只在原概率公式中合计一次，预览和投骰共读返回值。洗练、覆盖或失去适用资格后，下一次查询自然得到新值，省去反向扣回永久面板的操作。战斗内的持续数值沿前述快照冻结。先天标记只说明获得途径，肉身或本魂归属须逐项定义。

**现有接口的取舍。** `path_modifiers.modifier` 遍历提供方，后一个非空结果覆盖前一个。佛愿已经使用 `breakthrough_base_bonus`。建议保留佛愿的现有取值，在境界突破公式旁单独汇总特质贡献，以特质编号去重并列明来源。现有功法秘术已有在各领域分别读取加成、由领域统一封顶的做法，可沿用这一结构。 [道途修正接口](../cultivation_life/system/path_modifiers.py) · [佛愿](../cultivation_life/system/buddhist_wish.py) · [功法秘术接入](technique-secret-arts.md)

**昊天之仙的计算口径。** 每次实际判定持有者的修为大、小境界突破概率时，在原封顶步骤前加 25 个百分点，再按原顺序处理本源损伤。例如无本源损伤且上限为 98% 时，40% 提至 65%，85% 提至 98%。先天特质清单确定后，再统一平衡各项特质的出生概率。 [原有概率与上限](../cultivation_life/engine/progression/breakthroughs.py)

例如，同一关的基础概率为 40%，满愿力贡献 5 个百分点，昊天之仙贡献 25 个百分点，其他修正为零时预览和实投均应为 70%。洗去特质后为 45%。这个案例可同时检出愿力被覆盖、重复叠加及洗练后加成残留。

| 已审查的路径 | 建议生效方式 |
| --- | --- |
| 练气自动冲层、手动大／小境界冲关、先投骰再渡劫 | 共用原突破概率公式。加成只在实际投骰时兑现一次，随后如有劫关仍按原条件通关。 |
| 仙界等专属高阶劫战、血脉确定性进化、佛门涅槃 | 这些路线有直接入战或满足条件后升境的分支。详情应显示实际路线。纯劫战按原有条件通关，昊天之仙不额外提供护持。 |
| 炼体突破、神识升级、仙脉开辟 | 各有独立对象或机制。建议「境界」只指持有者本人的修为境界，其他项目另设明确效果。 |

手动提交会先取概率，但部分高阶大关直接跳过投骰。人物详情与执行端对纯劫战的判断也并非完全一致。建议提取同一处路线判断，供执行端和所有概率展示共用。投骰路线显示特质贡献、实际成功率及上限，纯劫战路线显示通关条件。 [正式突破](../cultivation_life/engine/actions/cultivation.py) · [人物详情](../cultivation_life/engine/presentation/character.py) · [突破说明的页面显示](../web/app.js)

**建议验收。** 用固定种子分别验证抽中和未抽中、普通与预设及自定义开局、保存重载与导入。核对新抽取不推进原世界随机序列。对同一角色比较持有、洗去、重复来源及与佛愿同时存在四种情况，验证预览与实际投骰一致。另测概率封顶后再扣本源损伤、自动突破和其他角色独立判定。相同配置与战斗种子下，单独增减昊天之仙，纯劫战双方的初始护持和结算结果应一致。

| 境界突破 | 持有昊天之仙的 NPC 在自身实际升层、升境的概率判定中加 25 个百分点。普通 NPC 基础概率上限为 97%，自然修炼投骰另有 98% 的最终上限。建议把特质与此次突破的其他加成合计一次，再套用该入口原有最终上限，预览共用同一计算。原有境界封顶和通行资格先行核验。仅离界而未升境的判定、周期劫难、确定性高阶培养分别按其原规则执行。纯劫战无额外护持。 |
| 战斗与情报 | NPC 作为敌手、队友或参加后台交锋时，从实际参战者读取有效特质。多人战斗分别计算每个人的伤害与抗性，续战沿用该场快照。NPC 详情通过现有人物情报权限展示已知特质。 |

NPC 的人物记录、传法与培养已经有独立入口。建议将特质随同一人物保存，宗门名册、关系和战报名单按人物编号引用。专项验收应覆盖偶遇人物留名后特质一致、两种来源修成同一特质、兼容与洗练、玩家与 NPC 分别持有昊天之仙时只影响本人，以及同一 NPC 在前台和后台交锋中按相同规则兑现特质。 [人物与培养](npc-development.md) · [功法培养入口](../cultivation_life/system/npc_development/techniques.py) · [NPC 自然修炼](../cultivation_life/engine/world/npcs.py) · [NPC 基础概率](../cultivation_life/system/npc_system.py) · [高阶简化培养](npc-development-upper.md)

## 三、伤害类别、护身属性与抗性

- **出手属性**由实际使用的招式、神通或法宝提供。建议首轮定义为物理、金、木、水、火、土、阴、阳、风、雷。星辰等新增属性可单独登记，再决定它与现有属性的关系。
- **护身属性**用来查询属性关系表。建议一个目标在一次命中时只有一个当前护身属性，由实际生效的护体功法、法宝或体质提供。未形成属性护身时，照常计算护体和各项抗性。多个来源同时能提供护身属性时，建议玩家在战前配置主护体，NPC 按稳定优先级选取，战中仅由实际状态切换。
- **属性抗性**按伤害类别分别记录。同一修士可以采用火属性护身，同时由鱼鳞之体提供水抗。水伤先取水对火的克制倍率，再扣对应的水抗。建议抗性同类相加，最后统一封顶，具体上限待平衡。
- **物理伤害**有专用倍率。五行、阴阳、风雷等属性的克制与抗性对物理部分均无效。普通防护、护盾和凡仙资格照常适用。首轮是否另设「物理抗性」待审，建议先使用现有防护承接。

| 攻击属性与护身属性 | 倍率方向 |
| --- | --- |
| 金攻木、木攻土、土攻水、水攻火、火攻金 | 顺相克方向，对应攻击分量增伤。 |
| 木攻金、土攻木、水攻土、火攻水、金攻火 | 逆相克方向，对应攻击分量减伤，再按目标对该攻击属性的抗性结算。 |
| 阴攻阳、阳攻阴 | 两个方向均增伤。 |
| 风攻雷、雷攻风 | 两个方向均减伤。 |
| 同属性及其余未列出的属性组合 | 建议倍率为 1。对应抗性照常结算。 |
| 物理攻击 | 按专用物理倍率结算。 |

## 四、如何接进现有战斗

1. **战前准备。** 从原配置、已学功法、实际持有或装备的法宝、当前肉身及有效特质生成战斗配置。每个出手来源带着自身的属性、伤害占比、作用层级与费用规则。功法资料分别显示灵根要求、攻击属性与功法品阶。 [战前配置入口](../cultivation_life/system/combat_loadout.py)
2. **出手与资格。** 确定实际攻击者和实际使用的来源，沿原流程核验禁制、资源和凡仙防护。当前普通交锋可从多件手段取最高攻击层级。接入时需要保留最终选中的来源，使层级、费用和属性始终来自同一手段。主动招式沿原发动条件选择来源。 [现有攻击层级](../cultivation_life/system/combat/effects.py)
3. **基础伤害与分摊。** 六维攻防、破法及原伤害曲线负责算出基础量。团队普通交锋沿原贡献分配到真实攻击者与承受者，随后按该实际来源的配比拆分物理与各属性伤害，配比合计 100%。 [普通交锋结算](../cultivation_life/system/combat/voisinages.py)
4. **逐项修正。** 属性分量乘以自己的伤害倍率、属性关系倍率与 `(1 − 对应抗性)`。物理分量乘以自己的倍率。同一方面板、法宝与特质提供的修正走统一汇总入口，每次命中应用一次。
5. **合并与扣减。** 汇总后交还原交锋的护盾、受击上限和同时扣减。态势损耗、实际肉身损伤沿各自原公式落账。邻域阶段照常先完成其应结算的效果，实际发生的普通攻击才进入属性计算。 [战斗时序](combat-semantics.md) · [态势与肉身损伤](combat-resource-costs.md)
6. **战报与续战。** 战报展示实际来源、各分量、克制关系、抗性和最终损耗。可中断的劫战使用同一战斗快照记录战前配置、轮内状态及结果，续战按实际状态推进。玩家、劫战和 NPC 交战共用属性计算；后台简化战斗沿用原基础曲线，在真实有属性参与时也应用相同修正。 [战斗回放](combat-replay.md) · [后台 NPC 交战](../cultivation_life/system/combat/npc_battle.py)

**演算。** 某招基础伤害 100，配比为 70% 物理和 30% 水。假设物理倍率为 1.1、水伤倍率为 1，目标为火属性护身且有 25% 水抗，水克火倍率取 1.2。物理部分为 `70 × 1.1 = 77`，水伤部分为 `30 × 1.2 × (1 − 0.25) = 27`，属性阶段合计 104，再由原护盾等规则结算。反过来，若同样的一击含 70% 物理和 30% 火，目标为水属性护身且有 25% 火抗，假设逆向倍率取 0.8、火伤倍率为 1，则火伤为 `30 × 0.8 × (1 − 0.25) = 18`，物理部分为 77，合计 95。两例倍率仅供演算，正式增伤与减伤幅度待定。

## 五、内容接入、界面与验收

- **内容标注。** 建议从一批实战样例开始，包括纯物理炼体、无灵根要求的水法、多属性招式、攻击与护身法宝，以及四项示例特质。验证后逐批按内容定义标注现有功法与法宝。现有功法的「无属性」有时表示无灵根要求，逐项标注时分别审阅修习条件与战斗表现。 [现有通用功法定义](common-elemental-techniques.md)
- **信息展示。** 复用人物详情、功法与法宝详情、原修炼提交和战报导航。人物详情在特质名称旁用对应颜色和文字标示稀有度，并显示类型、等级、已知来源、限制与有效抗性。最后一次修炼、洗练和重炼的确认页显示具体得失，并用同一后端规则复验，过期提交按原命令处理。
- **存档与归属。** 结构 13 保存角色的特质与大成来源、出手配比和劫战快照。旧结构 1–12 需新建角色。 [存档规则](save-code-format.md) · [跨界开发规范](world-transition-development.md)
- **验收样例。** 双来源重复授予只生效一次；星辰覆盖鱼鳞、低等级与高等级兼容、互斥清洗后重炼；无灵根要求的水攻、五组五行相克逐对验证正向增伤和逆向减伤、阴阳互克、风雷互抗；物理与水混合攻击只对水段应用水抗；资格拦截、混合邻域回合、多人分摊、后台交战和劫战续战结果一致；真实修炼页面能预告覆盖、阻止重复提交并显示最终结果。
