# 仙界道统、仙脉、道门与 voisinage

> 维护基线：本体 v1.57.0 开发源码，2026-10-04。存档结构 8，支持 6→7→8；文中“旧档补全”仅适用于允许加载的结构。文件名保留历史编号以维持链接；历史采样不是本轮实测。

## 当前规则

- 仙界每个存档固定 25 门：太初归元、玄微守一两门固定传承，另 23 门按存档种子生成。
- 真仙快速开局赠予太初归元的一部功法和首层注解，并未额外生成第二十六门道统。道门名录完整列出已获与未获传承；初始主修《真仙引灵经》是基础功法，与赠予的道统传承不同。
- 每门生成 3–8 部独立功法，至少一部真仙品阶，其余在真仙、金仙、太乙、大罗间生成。
  先获得任意一部相应功法，才能从 Lv0 开始参悟。道统 LvN 要求门下一部功法先达 LvN，
  并持有该道统 LvN 的注解；两者分别成长，不自动同步升级。
- Lv4 激发仙域，Lv5 确认唯一的本源归属，Lv9 封顶。可同时将多门道统修至 Lv4，
  只有本源道统可以继续突破。确认必须由玩家明确操作，目前没有重塑本源功能。
- 只有已修层与紧接着的一层出现在接口和页面中。未获传承只显示名称与背景。
  每次专修至多跨一个道统等级，避免一个时间单位跳过多个揭示节点。
- 初始修炼年数为 100、180、280、420、650、1000、1600、2400、3600；
  Lv1–5 要求真仙，Lv6–7 要求金仙，Lv8 要求太乙，Lv9 要求大罗。均为待平衡的内容参数。
  时间累计按行动实际经过的年数，事件中断不会结算未经过时间。
- 仙界传承书市每个真仙时间单位轮换 5 部当前境界可用功法。购买或查看不刷新货单；
  重复购买获得现有功法合参系统可用的玉简。当前购买入口为右侧瑶池功勋商店，九至十二阶功法分别为 200／600／1200／2400 功勋；仙躯传承、仙药与金光材料也由瑶池提供，支持锁货和批量购买。还可向已结识的前辈请教功法，消耗灵石获得与当前功法同级的
  玉简，收入包裹后由玩家另行合参，从而先提升功法，再参悟道统。
- 道统和所属功法只在仙界生效。离开仙界保留传承与进度，停用完整仙域和功法加成。
  下界可借仿仙灵力投影为 4% 威能的灵域；二级界面也可获得无需道统路线的灵域残解。

## 九层境界与二十七条仙脉

真仙时间单位为 **100 年**，旧随机转化事件的“单位”也改为 100 年；金仙及以上仍使用
原有 500 年单位。真仙开始机缘没有储量上限，存档保存真实余额，不写 JSON Infinity。
角色常规面板、主题 HUD 和仙脉面板均显示“无尽”；充足机缘不会触发凡人突破或被截断。

保留九层小境界，每层三脉（每个大境界共 27 脉）。开满本层三脉后必须手动突破，
不再自动升层，也不能提前开启下一层仙脉。第九层二十七脉贯通后可冲击下一大境界；
真仙冲击金仙还须仙躯达到第 20 层。大罗第九层停在当前内容上限。

开脉消耗以全部仙境仙脉序号 n（从 0 开始）线性增加：机缘 6000 + 3000n；
仙痕 6 + 2n。开脉成功率按本境九层配置为 85/80/75/68/61/54/46/38/30%，
失败消耗本次资源，为当前这条脉增加 5 个百分点，最高 100%；成功清除这一脉的保底。
手动境界突破调用原有通用突破系统（最终上限仍为 98%），采用独立仙境冲关费用（四境首层分别为 18000／90000／120000／150000，每层递增基础值的 12%）；
失败仅扣除本次所需机缘的损失部分，不会把无尽机缘池截断。

仙痕是 Player.immortal_traces 数值，不是行囊物品。每个实际正向机缘授予判定一次 15%，
一亿机缘的单次奖励也只判定一次；扣费、读档、展示和时间流逝本身不判定。
采用独立、持久化的 SplitMix64 流，创建时由游戏种子初始化，不影响事件/NPC 随机序列，
每次判定 O(1)，不增加 NPC 年度遍历。旧仙痕物品在反序列化时等量归并；旧感悟行动只保留
其正常机缘收益，不再每十年固定生成仙痕。完成仙灵力转化后才可开脉。

## 真仙之躯与本源

仙界真仙可随时查看左侧仙躯面板，训练须炼体 100 层、完成仙灵力转化，并拥有独立仙躯功法。
仙躯功法及其配方由 cultivation.body 配置，与旧 body_technique 槽位隔离；右侧瑶池功勋商店可取得
两种入门仙躯传承和三种仙草灵药。每次淬炼消耗目标层数乘配方基数的药材，失败保底每次 +5
个百分点，上限 100%；换功法保留仙躯层数与失败积累，成功后重置。当前上限 100 层，可配置扩展。
每层本源 HP +5000、MP +4000（灵根法力倍率在总法力中照常生效）；升级保持当前资源比例。

第 20 层通过 golden_light(player) 解锁护体金光，战斗适配器据此设置玩家的仙级防护，
金光为被动防护，不消耗仙灵力；锤炼材料与五阶抵抗见 [金光与瑶池](immortal-1510.md)。NPC 既有模板与剧情显式能力保留；不增加 NPC 仙躯模拟。
真仙、金仙、太乙跨境分别接入人五衰、天五衰、斩三尸；邻域跨阶段另有五轮道统反噬。详见 [仙境劫战](immortal-1490.md)。

普通炼体每层增加本源 HP 12、MP 10，沿用鬼修本源/侵蚀体系。intrinsic_resources 是唯一
HP/MP 资源池的展示分解：本源当前值 = 本源有效上限 × 总当前值/总上限。普通伤害与恢复
只改变当前值，魂侵蚀才改变鬼修本源承载能力。条内深色段为本源，其余着色段为外部加成。

## 道门、注解与突破概率

左侧：道统（自身参悟）、仙脉（经络点位与境界）、真仙之躯、仙域（至少拥有一个已激发的 voisinage 才显示）。
右侧：道门（寻访与同道指点）、瑶池（功勋商店与委托）。

寻访免费且不推进时间，预览 Lv1–Lv9 的待选同道；确认结识才支付 1000 灵石并生成真实人物。每门最多九位，允许直接结识高层同道，未确认的预览不加入年度模拟。人物存入
`notable_npcs`。页面与接口只返回已发现的名单；知道未探索 NPC ID 也不能越过权限请教。
引路人确实具备其传授层级的功法、注解和道统，陨落或离开仙界后不能继续教学。

求取下一层注解消耗 `3000 × 目标等级` 灵石，注解永久保留，不随突破消耗。
功法请教消耗 `3000 × 目标功法等级²` 灵石，要求前辈能够指导目标等级。

| 目标道统等级 | 初始成功率 | 每次失败增加 |
| --- | --- | --- |
| Lv1 / Lv2 / Lv3 | 85% / 78% / 70% | 5 个百分点 |
| Lv4 / Lv5 / Lv6 | 62% / 54% / 46% | 4 个百分点 |
| Lv7 / Lv8 / Lv9 | 37% / 28% / 18% | 2 个百分点 |

成功率上限为 100%，能够达到真正的必成。失败消耗本次修炼积累，功法与注解保留；
每门道统、每个目标等级独立记录失败次数。每次行动至多尝试一次升级，不跳过揭示节点。
修炼完成但尚未选择本源时不提前掷 Lv5；确认本源后才尝试，若失败，已确认的本源归属
仍然生效，不能借失败改选。随机流由存档种子和实际尝试序号决定，查看和读档不重掷。

## 邻域培养与额外温养

邻域另有初成、化境、大成各四层与至臻，共十三级；跨阶段须通过反噬。集齐六至八部原始功法可合练唯一真传，并以仙痕参悟到 Lv9，详见 [合练与三尸](three-corpses-1512.md)。

只可选择一个已激发的邻域出战，可随时在已修至 Lv4 的道统之间切换。
稳固、侵夺、权能各可额外温养十重，每重增加该维度道统基础值的 3%，最高 30%。
每一重花费 `40000 × 目标重数` 机缘和 `8 × 目标重数` 仙痕；三个维度分别累计。
切换出战不丢失培养，道统升级后按新的基础值计算加成，不覆盖或复制原始定义。

## 词库与随机路线

词库位于 `content/doctrines.json`：32 个主题、192 个主题意象、62 个前缀、56 个功法动词、
24 个功法后缀、20 个仙域后缀、30 个权能动词、九级各 8 个阶段题名、16 个修持意象、
8 个修持结果、16 个获得场所，以及 6 个道统后缀。每个主题有独立背景描述。
配置加载时校验主要词库的数量与唯一性，避免退回少量词条循环拼接。

名称、机制、各级数值、功法使用分开的确定性随机流，命名改动不会消耗机制的随机数。
首次需要仙界内容时一次生成并保存完整九级路线，之后只解锁显示；读档、切换面板、
购买顺序不会重掷路线，也不消耗世界事件 RNG。已存档路线不因内容版本升级重新生成。

功法战力加成按 `expected_combat_power(对应境界, 1)` 的 3.5%–6.5% 反推；
机缘、气血、法力按品阶设置区间。功法仍接入既有主修、辅修、战斗槽位、仙灵力资格和
功法合参规则，不将功法战力换算为领域优势。

## 有限的随机战斗特色

道统不输出“领域综合强度”。输出以下独立数据：

| 维度 | 作用 |
| --- | --- |
| 稳固 `stability` | 抵挡敌方侵夺，决定己方单位能否保持庇护 |
| 侵夺 `incursion` | 对敌方庇护进行方向比较，决定能否支配目标 |
| 权能 `authority` | 突破庇护后，决定杀伤、镇压侵蚀或封禁收束的效力 |
| 展开、维持、施权费用 | 决定领域能否建立、持续与执行效果 |
| 覆盖数与额外覆盖费用 | 决定多目标能力及扩张的消耗、衰减 |

Lv4、Lv6、Lv8 分别获得一个机制特色，最多三个。生成器按兼容组合选取，不能生成
任意执行脚本：久持固界、初开夺势、守成反制、舍守锐进、长运归息、分疆同庇、乘隙施权。
这些特色分别作用于持续轮数、首次展开、上一轮抵抗、攻守取舍、维持费用、覆盖负担和
残弱目标上的权能。后续新增特色需要先给战斗内核明确的有限语义，再开放给生成器。

封禁型权能累计到 100% 后使目标退出本场战斗，不造成气血损失，也不直接产生永久俘虏。
这让封禁路线具有领域制胜方式，而不是只能封闭退路后等待耗尽资源。

## 分层与 NPC 预算

```text
content/doctrines.json：词库、修炼阈值、生成配置
          ↓
doctrine/generation.py：纯确定性编译 → 存档共享 definitions
          ↓
doctrine/cultivation.py：纯费用、前置检查与概率成长
          ↓
doctrine/progression.py：人物养成事实 → 有限能力
          ↓
doctrine/provider.py：人物事实 → CapabilitySource
          ↓
combat/contracts.py：合成能力快照
          ↓
combat/voisinages.py：有限阶段结算 → 原常规交锋

doctrine_system.py / immortal_system.py：玩家操作、存档、逐级披露
doctrine/daomen.py：按需发现真实同道与教学权限
web/doctrine-panel.js：养成界面与领域战报
```

纯生成/成长模块不导入引擎、存档或全局注册表；战斗内核不读取道统目录、不推进道统成长。
其他三级界面可实现自己的 `CapabilitySource`，不需要假装成仙界道统。
每个存档只保存一份目录，不把各存档随机功法加入全局 `TECHNIQUE_CATALOG`。

NPC 仅在现有 `transcendence` 内增加紧凑的 `doctrine` 子记录：功法 ID、进度、主修、
本源、最后结算时间和环境。初次参战时为仙界已转化人物按种子与 NPC ID 确定传承，
未转化旧人物及显式剧情领域保持原事实。NPC 只持有目录 ID，不复制九级定义。

之后仅在参与能力解析时，根据经过时间补算，最多检查九个阶段；每阶段用独立种子编译
带保底的有限尝试次数，将功法、注解取得的时间与失败耗时一并计入。NPC 初始已修层级
对应已掌握的功法、注解事实，成功晋级后同步记录更高层级的掌握。
年度循环不增加道统遍历。百万年跨度不会变成百万次运算，分次观察与一次补算结果相同。
未知跨界时间区间不追补仙界修炼。后台采用稳定单一道统和自动本源选择；教学引路人的
已公布修为固定，不因查看面板偷偷升级。没有模拟 NPC 每年挑选功法或重选路线。

## 转化与展示

主动仙灵力转化沿用五阶段，每阶段初值为 100、180、280、420、600 年。按真实经过时间
积累，一次行动最多检查五个阶段，调用现有阶段奖励逻辑。仙窍储量与 MP 分开，
转化完成后可凝练独立仙灵力，蓝条只显示转化百分比。选择主动转化后，停止等待随机转化事件；未选择的旧流程继续可用。

领域战报展示施术者、仙域、稳固/侵夺/权能、覆盖对象、资源、持续轮数、封禁进度及
方向性对抗。通常一二级界面没有领域数据，自然不显示；显示条件依赖实际战报而非世界等级。

内部能力、战斗变量、战报及新存档键统一使用 `voisinage`，不预设所有修士称其为仙域。
旧存档的 `domain` / `domain_ids` 等键一次性迁移，保留原能力 ID、生成路线和已修进度。
旧版本已修成层级补齐对应的既得注解与至少一门功法等级，未修成的下一层仍须按新规则
取得前置条件。静态内容边界继续读取旧 `domains` / `domain_ids`，新输出只用新命名。

## 验证与性能复现

- `python -m pytest -q`：完整回归。
- `python scripts/verify_doctrine_ui.py`：隔离存档，实际购买、推进修炼、确认本源、
  检查逐级披露、手机布局及真实领域战报；截图输出至 `build/doctrine-*.png`。
- `python scripts/benchmark_doctrines.py`：目录首次生成、重复读取、48 名 NPC 按需成长，
  以及 48 人真实生成领域交战。时间仅作诊断，不作为易波动的测试门槛。

早期实现的历史微基准（本轮未重跑，不能视为当前性能承诺）：首次生成 6.109 ms，48 人首次解析 1.916 ms，
48 人跨 100 / 10000 / 1000000 年补算分别为 1.231 / 1.363 / 1.452 ms，
48 人领域战斗 10.227 ms；示例目录约 222 KiB。此为新增模块的耗时，不是整个世界推进耗时。
