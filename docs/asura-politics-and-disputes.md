# 修罗派系深化与地方争议

2026-11-11第二批源码实现，承接[总督府第一批](asura-governorship-implementation.md)及[完整策划](asura-court-governorship-design.md)。本批不更新版本、不打包；仍为本体3.7.0／修罗包1.4.0的开发源码，存档仅结构12。驻防、调兵、抗命及起兵夺位见后续[第三批实现](asura-military-and-succession.md)。

## 分层与权威状态

本体 `institution_petitions` 只负责有限案卷、呈交、具名担保和一次结案；原NPC决策继续复用 `institution_ai.rules.choose`，新增明确允许零支出选择的参数，原经营任务默认仍要求正预算。NPC对内容的偏好由适配层提供，预算与有效事实过滤仍归本体，不另建人物或财政。`institution_authority` 统一原公款部分上缴与属员登记。

修罗专属事项、派系偏好、观察周期、期限及NPC单案拨款比例放入修罗包 `world.json`；实际适配位于 `system/asura_governorship/politics.py` 与 `disputes.py`。原署公款、王庭府库、原NPC、原项目、原建筑和原爵位仍唯一。案卷的金额是证据快照，不能充当钱包；原资材、建筑结算没有替代副本。

## 派系与私人支持

三派保留血裔诸族、征伐军府、万战城盟。现任府库总管、掌军使、养域使分别体现城盟、军府、血裔利益；无中枢职司者参考已发生任职／履约经历、原爵位职责及地方事务。新投影不再直接按人物ID哈希划派；历史贡赋及已发血战兼容原结算，不重置人物。

影响力由实际爵位、中枢职司、在任地方职责与对现君的履约支持归纳，三派合计100、单派5—70，界面展开显示来源。原派系忠诚、原人物好感、对具体议案的表态、对某人的私人支持分别保存；不因为势大或旧忠诚条偏低自动生成派系王位挑战。原本体个人相邻爵位血战及已发战书仍有效。

任职、具名担保和真实裁决会记录到具体原人物履历。同一人物每百年仅获得一次任职关系收益，反复换职不刷党羽。采纳与未采纳原主张分别影响支持；担保兑现加支持、未兑现减支持。支持至少12时可成为该人物的主要私人支持对象；UI只披露对玩家的已知关系，不下发完整私人关系图。履历最多8条、每人关系最多8个、总计最多64名原人物。

这些关系影响地方举荐人选排序、NPC议事偏好及影响力来源；已有政治支持对本体原血战谨慎程度提供至多20点的忠诚等价修正，仍须实际实力评估和原战斗，不产生战力或保证不挑战。三派对上缴、开放和项目处置有不同偏好；本体决策器先排除无权限、无原人选及不足预算的选项，再参考内容偏好。NPC君主在位时也会处理具名请示。

## 六类地方争议

| 事项 | 原始依据 | 可执行结果 |
| --- | --- | --- |
| 工程拨款 | 未建／损毁原府署、原市场工料报价、本府现金不足 | 原址呈交；君主在王庭批准或驳回。批准实转原府库款，不自动建楼；NPC单案最多使用当前府库10%，可部分拨付，回执写明实际到账和待筹款 |
| 地方上缴 | 原本府可用公款 | 照额、折半实缴或保留准备金；只转原公账到原王庭，不能支取项目托管和个人库存，未完工程准备金须保留 |
| 属员举荐 | 原址自由、符合任职及占用规则的原NPC | 任用首荐、改任备选或暂缓；原执事名册与共同任务占用同步，离场或受拘束的人选提交时拒绝 |
| 履约争议 | 真实在办项目的阻碍与支出回执 | 保留原任务／原截止年，或沿原项目入口交接并退原余款；缺货、离场不自动判侵吞，已耗工时不退款 |
| 公署开放 | 原府署产权及公开使用许可 | 向公众开放或限制来客；只改原public字段，现任仍凭任职许可访问，撤权立即失去该许可，不留下永久私人users记录 |
| 任期考核 | 最后100年、原任期及本任实际完工／实缴记录 | 呈请续任、王庭批准／驳回或交接辞任；批准在原截止年上延500年，不重置公款、建筑、责任和人物；旧任业绩不得永久重复用于续任 |

每府每类每百年最多受理一项，最多6项待决、24项结案回执；一般截止200年，续任案最迟到原任期结束。案卷可原址明确受理，也会在玩家原址当前实际年度或NPC总督原址年度观察；读页不生成、不投骰。年度last_tick去重，历史补算不能提前处理未来案卷，也不按玩家今天的位置补造过去的本人提案。

在场原人物以具名、带来源的表态参与；无真实在场人员时不造代言人。表态不是多数表决，玩家总督或君主保留原权限内裁决权。原君主必须自由并在王庭实际地点，NPC总督必须在原址且未被其他任务占用，才可自动处理。多人请款顺序读取同一个已扣减府库，不重复承诺同笔钱。

## 权限与收尾

地方决策须在任且在原址；预算和续任的最终批准须在王庭，由现君办理。中央只收到已具名呈交的原案，不获得所有地方隐私或完整私人人脉。玩家在外任地不能自批拨款、续任，非君主可在合法议事机关担保但不能越权裁定。

改职、旧报价／旧页面、人员离场、府署产权或地址改变、项目结项及期限变化均提交复验。真实资金缺口已补齐或原项目已结项时，旧案归档，不重复拨款、退款或无据追罚。撤任后原案留档待交接；停用DLC只允许撤回或到期收尾，既有担保的后果继续记账，不因开关清空政治责任。

原城市仍有许可时，未建或损毁府署可以办理必要工程请款、实款交接和原项目收尾；人员任用、公署开放及续任审议依赖完好原府署。没有新增跨界运输、传送或远程使用个人物资。所有字段已人工登记于[状态合同](world-transition-state-contract.json)。

## 界面与验证

沿现有王庭“政令”展示三派利益、原任职来源与对玩家的支持；“内政”办理地方呈案；原建筑“府务”增加折叠的地方争议。每案使用一个方案选择器和必要裁决／担保／交接控件，没有新侧栏按钮。采用修罗赭红与族／军／市文字徽记，两套像素主题与手机、横屏共用。重新呈现保留本次会话展开项和选择，权限与金额始终取新响应。

专项入口为 `tests/test_institution_petitions.py`、`tests/test_asura_politics.py` 和 `tests/browser_asura_politics.py`。覆盖六类真实效果、公款守恒、原项目退款、NPC预算与偏好、重复年份、关闭态担保、旧任续任、历史补算、伪造存档、旧页恢复及原建筑事件。并运行王庭、第一批总督府、本体机构、建筑、跨界与事件回归和三项门禁。运行结果以build日志为准，本批不声称全仓或双端发行验收。

2026-11-11验收结果：最终领域组87项通过（`build/asura-politics-final-domain.xml`），建筑／事件／跨界回归组187项通过（`build/asura-politics-regression.xml`）；两组按各自范围报告，不合并为全仓测试数。地方争议真实页面在两套主题的1440与390宽度及754横屏共五组通过，原事件浏览器回归通过。状态合同、模块依赖、文档三项检查均通过；截图与浏览器日志保存在 `build/asura-politics-browser/` 和对应日志文件中。
