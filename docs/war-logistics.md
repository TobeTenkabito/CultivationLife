# 战争军需与组织府库（v2.3.0）

本次更新依据用户追加需求和《CultivationLife_War_Economy_Adjustment.md》的商品闭环方案实施。固定 25% 军费回流方案已经取消；战争拉动当地经济的来源是实际采购付款、手续费与供需变化，已消耗的物资不得重新入市。

军需记录在原战争对象下，货物与灵石分别保存；显示时按前线当前市场参考折值计算。灵石仍从组织原府库调拨至战争托管账户，商品从固定驻地的府库扣除。每次运输、采购、消耗、劫掠都转移或扣除唯一存量，不能拿 UI 总值另行入账。商品短缺及府库不足均限制补给，预览和情报查询不得采购、推进时间或投骰。

同界双方按战场到最近己方驻地的实际道路计算损耗。跨界沿既有有限远征路线，不增设任意通道或搬动人物；攻方承担开启和维持费用，市场采购分别发生在各自实际进攻／防守端。默认前线本地采购目标为本回合需求的 20%，跨界攻方 10%，只在有钱、有货时实际成交，未成交部分不能伪造收入。运输与战斗损失为永久实物消耗。劫粮成功仅取得敌方被夺实物的 60%，其余损毁。

参战者可见己方军需，敌方只有成功侦察所得快照；旁观者可见本界双方军需。情报必须在服务端裁剪，不能仅隐藏 UI。每场会战前 NPC 对未由玩家指挥的阵营办理有限补给或劫粮；同一回合每项策略只能执行一次。严重缺资影响战斗力与士气，正式战斗、后台 AI 及玩家参战入口一致。种族／联盟摊派按真实参与组织实力分配，支付不足的组织退出本轮重分摊，不凭空垫款。NPC 主动宣战前检查至少三场会战的储备，防御不受这一开战偏好限制。

宗门／家族府库存于 `economy_v2.depots`，带固定世界与地点、原所有者、实物、有限申领记录及修订号；迁址不自动搬运库存。可流通普通物品与普通功法玉简分别计数，独立炼器实物不因同名变成标准商品。采购使用原组织府库，标准商品扣本地市场库存，普通玉简以有限的当地书坊抄录额度付费订购。申请至少等待一个行动单位，经任意有效门内高层审批后将实物从库存移入待领托管；战争不能征用已批准待领取的同一件物品。领取只在本组织驻地完成，并再次验证成员身份和修订号。

组织经营只统计一次有效成员境界直方图，以有限境界组计算劳动产能和供养；不为每个 NPC 单独运行经济决策。按需求选择至多四种本地原生商品，对真实经销商订单生产、销售，受境界能力、市场需求和买方现金限制。府库采购只动用经营盈余的一部分，不在旧档初始化时赠送物资。对应界面显示产能、支出、实有库存与审批进度。

仙灵力与煞元改为左侧独立转化入口，以 100／180／280／420／600 机缘推进五阶段，不再随机弹出阶段事件。已完成阶段保留；仙灵力旧按年积累按当前阶段完成比例抵扣费用。旧待处理转化节点退出，保留其他事件和后续奖励，禁止读档免费补阶段或重复奖励。

验收：最终源码通过 3,315 项 Python 回归、23 项浏览器脚本、字段合同／模块依赖／文档检查；Windows EXE 分别在有无 DLC 的隔离环境中通过实际操作，正式签名 Android 12 包通过 32 个原生验收场景（含新增功能四主题横竖屏）。设备验收使用 x86_64 模拟器，包同时包含 arm64-v8a 与 x86_64。完整证据见 `build/release-230-tests.log`、`build/exe-230-verification.json` 与 `build/android-runner-230.log`。

本轮采用最小闭环：军需分类的独立短缺惩罚、多节点补给网、独立破坏补给策略与战争金融留待后续。跨界财政接入既有岚疆有限远征，不新增任意跨界宣战或调兵权限。
