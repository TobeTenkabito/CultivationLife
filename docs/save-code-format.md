# 存档码 FSWD1

> 维护基线：本体 v1.59.2，2026-10-05。开发源码存档结构 9，支持 6→7→8→9；文中“旧档补全”仅适用于允许加载的结构。发行包未随诸天 M1 重建。

本地流程为：原 JSON → 带版本与扩展摘要的 JSON 封套 → DEFLATE（zlib，等级 9）→ AES-256-GCM → Base64url。

服务端以原始 JSON 为准导出，不调用游戏推进或会话准备。结构校验与迁移使用 `save_schema.py` 的统一入口；结构 9 不做转换，已登记的 6→7→8→9 转换仅作用于副本，不改动导出源文件。导入保留未启用扩展的字段，也不重置角色编号、随机数、NPC、履历或关系。全局成就、界面偏好、DLC 文件不在角色存档范围内。

当前开发源码写出存档结构 **9**，支持结构 **6→7→8→9** 迁移；结构 1–5 的本地文件及存档码均拒绝加载或导入，需新建角色。6→7 将普通关系中的人物快照收敛为 NPC ID 引用，保留人物、关系专属信息与随机状态。7→8 通过明确的旧生擒标记迁移拘禁状态，不把真正死亡者复活；缺失来源 ID 的旧活傀不猜测绑定，详见 [人物拘禁契约](npc-custody.md)。8→9 仅增加诸天空容器，未知子协议和不支持的诸天状态拒绝载入，不清空恢复。预览不写回源文件。FSWD1 封套版本与角色存档结构版本独立；此次没有改变加密及分段格式，也没有重新生成发行包。

选择 DEFLATE 是为了共享 Windows / Android Python 标准库实现，不引入新的原生依赖。测试中，含 12,000 条履历、13,038,097 字节的样本压缩为 275,039 字节；这不是所有存档的固定比例。相比同一长期存档的 LZMA 探测，DEFLATE 压缩更快；保留完整数据，不通过删除历史缩短码长。

## 加密封套

前缀 `FSWD1.`，后接无填充 Base64url。解码后的字节依次为 32 字节随机密钥、12 字节随机 nonce、密文及 16 字节 GCM tag。附加认证数据固定为 UTF-8 `浮生问道 / FSWD1 / deflate / AES-256-GCM`。密钥与 nonce 每次由 Web Crypto 随机生成，加解密使用 [Web Crypto AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt)。应用通过本地 loopback 提供页面，支持所需的安全上下文。

**这是可携带的持有码者凭据，不是密码保护或防作弊协议。** 为满足“仅凭整段文本即可恢复”，密钥随封套携带；完整代码持有者可以读取与恢复数据。AES-GCM 用于加密封装及检测复制损坏，不声称能阻止懂得协议的人重新封装修改后的存档。没有自创密码算法或固定密钥，没有网络上传。

## 长文本

超过 100,000 字符时，分段格式为 `FSWDP1.<组摘要>.<序号>.<总数>.<正文>`。组摘要为整个 FSWD1 文本的 SHA-256 前 12 字节的十六进制串。正文按顺序拼合后检查摘要，再做 AES-GCM 认证；可乱序、批量接收，完全相同的重复段不计数，混用组或冲突段拒绝。

Android 进程间通信存在 [Binder 事务缓冲区限制](https://developer.android.com/guide/components/activities/parcelables-and-bundles)，因此不把数 MB 文本一次写入剪贴板。原生桥限制复制文本为 120,000 字符，每段正文最多 100,000 字符；浏览器与安卓采用同一分段格式。粘贴依然需要玩家主动点击，应用不在后台读取剪贴板。

## 校验与写入

原始封套上限 64 MiB，压缩数据上限 12 MiB；服务端只对导入/预览端点放宽 JSON 请求体限制。解压使用有输出上限的增量解压器，拒绝超限、截断和尾随数据。JSON 不允许重复键或非有限数值，随后检查格式版本、游戏版本、存档编号与 GameState 结构，包括角色境界和随机数状态。所有输入都是数据，不反序列化 pickle、不执行脚本。

导入预览返回已有存档的 SHA-256。确认时重新检查，若本机进度已变则要求重新预览。相同编号只在用户确认后替换，先在 `data/save-backups` 保存原字节，再以临时文件原子替换目标；新编号不会覆盖其它角色。未启用扩展的数据保持原样，提示两端启用对应扩展。
