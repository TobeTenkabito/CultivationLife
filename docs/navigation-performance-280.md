# 分类导航与性能复核

维护基线：本体 **v2.13.4 / 存档结构 10**；下方早期版本采样保留为历史对照。

## 玩家操作

Windows 普通宽度窗口恢复 v2.7.2 的左右功能栏，直接点击原按钮打开面板，并保留后来新增的玩法入口。安卓（包括宽屏平板）、宽度不超过 900px 的窗口和高度不超过 520px 的触摸横屏采用六项固定底栏：常用、修行、百艺、经营、同道、诸界；宽屏鼠标窗口不会因高度较矮而切换为手机布局。窗口尺寸切换只搬移同一个原按钮节点，保留其事件、解锁、DLC、忙碌禁用及空间权限，不复制功能按钮，也不修改角色存档。

分类只展开当前目录；搜索覆盖所有已开放功能，星标最多八项，最近打开最多四项。偏好复用本机界面设置的原子保存入口，浏览器存储仅作后备，不属于角色存档；安卓进程重启、服务地址改变后仍可读取。分类提示继承原功能通知。拍卖会、交换会的预告与开放状态在手机“常用”内显示，并在桌面的对应原按钮上保留提示。地图、行囊、灵田的按需绘制不受桌面布局恢复影响。

自定义二级界面携带灵域传承后，左侧“灵域”（手机位于“修行”）从 Lv1 即可查看已学传承，并可前往行囊合参玉简。Lv4 才可展开、启用灵力储备；未满四级不补发灵力，也不开放战斗资格。不同界面、道途与独立空间的限制照常生效。

地图、行囊和灵田在打开面板时绘制；已经打开的面板随行动立即更新。未打开时只保留最新响应的绘制任务，切换角色会覆盖旧任务。空间地图仍由原空间展示入口构建，地点、实例和操作权限保持独立。

## 采样方法与发现

隔离存档、全 DLC、三个固定种子，每种子三次真实真仙百年休息；中位数分别 3605、3640、3879ms，总体取各种子中位数的中位数 **3640ms**。为测满百年，基准工具屏蔽归墟随机中断；正常游戏仍保留中断。cProfile 的插桩会显著增加耗时，不能用插桩总时长当玩家等待时间。

该采样使用新建真仙的初始世界，不代表长期人口变化后的大存档或其他硬件。完整页面状态的读档、拷贝和展示另做独立采样，不能用模拟耗时推断页面流畅度。

年度世界推进约占剖析累计时间 95%。商队推进约 51%，其中候选货物评估约 45%；消费结算约 38%，组织推进约 26%，生产约 25%，报价约 15%。这些是调用树中的嵌套累计占比，**不能相加**。一次百年剖析约调用报价 48 万次，仍是最值得继续优化的路径。

另用 `tools/audit_ui_performance.py` 在桌面 Chromium 的 412×915 视口，对同一普通/真仙响应各做十一次采样，丢弃首次预热样本、保留十次有效采样：计时覆盖真实 `render()` 和强制布局，两次绘制帧分隔样本。

| 场景 | 旧版主页面绘制中位数 | 最终代码 | DOM 减少 | 原 DOM 元素 | 最终 DOM 元素 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通开局 | 122.10ms | 30.40ms | 30.2% | 8301 | 5797 |
| 真仙开局 | 163.80ms | 57.80ms | 30.8% | 9904 | 6855 |

最终采样在浏览器与原生回归结束、关闭本次验收模拟器后执行，在同一主机连续测量隔离 Git 归档中的 2.7.2 与冻结后的 2.8.0。采样期间主机负载仍有明显波动，因此表中计时仅为实测样本，不能将差值全部归因于代码优化；DOM 数量下降是可复核的工作量变化。原基线仍保留，最终报告绑定生产代码哈希。后端获取完整页面状态（含读档准备）约 73.68/99.19ms，响应约 0.64/0.86MB。该入口剖析中读档准备约占 72–74%，深拷贝约占 57–60%，展示约占 26–28%；均是嵌套累计占比，不能相加。

这是前端主页面工作量下降，首次打开对应面板仍需完成其绘制，不代表百年模拟或手机帧率提升。本次没有缩减传输体积，不能为减少拷贝破坏事务回滚、存档缓存和角色隔离。

最终百年结算复测中位数为 **7182ms**，当前环境旧版对照 **6619ms**，早期原基线 **3640ms**；本轮单次采样约 3.8–7.6 秒，波动明显。本次后台模拟算法保持不变，这组计时不足以分离机器负载影响，继续优化的依据是调用剖析与重复工作量。新旧版本三种子各三次的完整结算状态均与原基线一致。对照仅排除墙钟保存时间，并要求最后保存版本等于各自正在运行的发行版本，其余字段完整比较。原始样本、首次打开面板耗时及剖析文件保留在 `build/performance-280/`。

## 继续优化的顺序与边界

1. 商队候选和报价：同一交易事务内复用基础估值、目录属性与固定配方信息；成交、库存、资金、路线或风险状态变更后必须失效。不能跨成交复用依赖供需的最终报价。
2. 组织生产和消费：继续按既有用途、阶数、人口境界聚合，减少重复候选构造和库存扫描；保留真实物品扣除、采购顺序、负债、欠费与战争军需结果。
3. 页面与响应：测量其他隐藏面板的绘制收益；拆分接口前先剥离 `ensure_*` 和会话准备副作用。不能把有随机、历史、战争准备或保存效果的展示入口直接当纯缓存函数。
4. 读档和拷贝：先确认缓存命中和快照复制的次数；只对经过审阅的不可变目录共享引用。人物、组织、物资和资源池必须保持唯一权威归属，不能共享可变存档副本。

后端改算法须在相同结构 10 初始存档与 RNG 下比较完整结算状态，并覆盖正常百年、中断、死亡、跨界、忙碌及部分年份结算。不能用年度抽样或跳过人物行动换取速度，不能逐年增加全商品或全 NPC 的新扫描。本次只改变界面构建时机，没有改模拟结算与游戏随机序列。

现有前十二候选已采用有界堆，复杂度约为 O(N log 12)；大宗报价已用积分公式，数量增长不会带来逐件循环。继续优化应减少重复评估，不能把候选长期固定，也不能省略成交后的重新估值。

新增功能按钮须在 `web/navigation.js` 的分类表登记；分类目录应复用原按钮节点，不另造绕过权限的操作按钮。

## 验收

### v2.11.1 灵界大乘百年与地图入口复核

地图窗口的“地域地图”保留文字行程，“可视地图”独立展示道路与影响，二者不叠放。合纵连横窗口顶部提供影响地图、地方政策与决议两项直达入口。可视页通过彩环、影响数值、宗门颜色图例、地区列表影响条展示同一权威地图投影；政策页直接展示议事内容，无资格时保留说明。手机图形内部可横向查看，地区列表提供较大文字和可点击地域，不新增侧栏功能键。入口和规则见[地方影响开发说明](territory-development.md)。

2026-10-11 按用户反馈复核 Edge、灵界大乘、全九项 DLC、一次真实 100 年修炼。剖析的年度阶段约占累计时间 95%；商队候选约占 48%，组织经营约占 25%，居民消费约占 22%，这些是嵌套调用树占比，不能相加。一次剖析约 3.8 万次旅行规划、57.2 万次商品报价，不能把带剖析工具的总时长当玩家等待时间。

静态道路改为按出发地计算最短路树，目录实例内最多缓存 256 个出发地；重新核验地图内容清空缓存。每次仍检查当前目的地门槛、境界速度与行程倍率。商队的传送阵投影与源市场购买报价仅在一次选货过程内复用，下一队、下一笔成交与下一年度重新取得动态数据；超过资金的组合提前停止计算卖价。前十二候选保持价格比、库存比、ID 的原顺序，按当前目的地重新选择，不固定货品，不改成交、货物归属、时间或 RNG。

用同一初始快照在旧版 Git 归档与当前代码之间对照，在独立 Edge 155.0.4283.45 中各实际点击三次，期间不并行跑其他验收。原有“归墟事件弹窗”设置关闭以避免半途潮讯暂停，归墟与所有 DLC 正常演化。点击到页面恢复的中位数 **11,227.9 → 9,480.7ms**（减少约15.6%）；HTTP 请求中位数 **10,199.7 → 8,619.4ms**（减少约15.5%）。这是隔离新档与本机环境的对照，不能直接将差值套入用户约9秒的长期存档或其他硬件，也不代表安卓必然更快。

可复用 `python tools/benchmark_spirit_action.py --output build/spirit-action-benchmark.json` 测量本机实际 Edge 点击。使用 `--snapshot` 指定同一初始快照、`--source-root` 指定隔离旧版目录，可做版本对照；只读取输入，在临时目录测试，不写用户存档与偏好。报告保存源码摘要、九项 DLC、浏览器版本、全部样本及请求／界面耗时。

本轮专项回归 434 项通过；地方地图真实页面 22 组覆盖四主题、桌面／手机及三种资格状态；旧地图名录与事件提交浏览器回归通过。此为源码修正与基准记录，不替代新发行包的 Windows／Android 成品验收。

同一初始快照另做旧版／新版各三次完整状态对照：使用正式 HTTP 请求的准备与命令作用域、实际百年结算，只固定测试中新创建实物的 UUID 序列，比较全部持久字段及 RNG。六次结果完全一致，仅排除墙钟 `updated_at`。未删掉财政、战争、市场、人物或历史字段，也不以抽样相似代替一致性验证。

`tests/test_release_280.py` 覆盖五个二级界面、四个携带等级的权威开局、灵力和展开门槛。`tests/browser_release_280.py` 用真实表单提交与页面点击覆盖四主题、桌面/360/412/横屏、搜索、星标、退出、读档与角色切换；实际导航不改角色存档。浏览器与签名 Android 原生验收同时覆盖空间地图、事件旧交互、禁用选项、教程、DLC 和跨端存档。发行门禁、成品和源码哈希见当前 `dist/` 清单与 `build/release-280-acceptance.json`。

## v2.13.4 百年行动结算专项优化

2026-10-14 按用户反馈检查通用百年行动，经济托管开启与关闭均覆盖。剖析确认年度世界推进占绝大多数时间；商队选货、组织生产、居民消费与宗门 NPC 演化是主要路径，累计时间互相嵌套。此次保留每年的全部结算、随机调用、资源归属和中断规则，仅减少可证明重复的计算：

- 采掘地点的静态物资种类使用最多 256 项的进程内缓存；当前世界阶数参与缓存键。只缓存不可变 ID 元组，不缓存库存、额度、价格或角色状态。
- 账本一次转账只解析一次原组织／商人账户；仍在扣款前验证收款方，资金直接写入原权威库藏。个人账本函数的重复导入移至模块入口。
- 商队先检查原候选中最小批次的购货、运费与工资；最小批次已超过预算才排除同货物更大批次。保持原前十二项、排序、数量集合与最终评分；买价缓存仍限于一次选货。
- 无原料生产在经销商资金、资源额度与生产者余额约束后减少数量二分；单件实收低于四灵石且要求盈利时，保留原搜索以维持整数工资边界，不更改原料不足、实际生产、手续费或流水语义。
- 宗门年度更新仅在 NPC 真正突破时计算旧境界职衔；通过只读境界参数计算历史称谓，不复制或临时修改 NPC。招募仅在既定招募年检查既有资格，NPC 循环中的重复导入移到年度入口。

后台以灵界大乘、仙界初始存档分别覆盖托管开关，真实点击采用灵界大乘；十项 DLC、真实百年修炼，各场景旧／新代码三次串行采样。仅把临时基准进程固定到 CPU 0 来减少调度差异，正式游戏不设置 CPU 亲和性。正常设置关闭归墟事件弹窗以跑满百年，归墟演化仍执行。最终代码实测中位数如下：

| 测量范围 | 改动前 | 改动后 | 减少 |
| --- | ---: | ---: | ---: |
| 灵界后台行动，关闭托管（年度推进、保存、展示） | 4111.8ms | 3807.3ms | 7.4% |
| 灵界后台行动，开启托管 | 4129.4ms | 3748.8ms | 9.2% |
| 仙界后台行动，关闭托管 | 4785.2ms | 4506.9ms | 5.8% |
| 仙界后台行动，开启托管 | 4862.7ms | 4384.9ms | 9.8% |
| Chromium 真实点击至解除忙碌并完成两帧 | 4681.3ms | 4496.7ms | 3.9% |
| 点击测试中的 HTTP 行动请求 | 4285.9ms | 4014.1ms | 6.3% |

页面测试仅开启一个 Chromium 页面，V8 堆限 128MiB，并阻止与此次行动无关的地图素材加载。它验证实际主页面请求和恢复操作，不代表地图首次打开耗时或原生安装包表现。后台四场景样本行动结束后的进程 RSS 最大观测值为旧版 157.2MiB、新版 156.8MiB，属于采样点值而非全程峰值。新建隔离档的计时不能直接套用长期大存档、其他硬件或用户正在运行其他软件的环境；页面样本也有明显波动（旧版 4.65–6.39 秒、新版 4.42–5.06 秒）。计时以此处最终代码的同档样本为准。

从改动前 Git 归档恢复完全相同的初始存档并固定测试中新实物 UUID 序列，灵界／仙界及各自托管开关四个场景逐项比较全部持久字段、历史、财政和 RNG，只排除墙钟 `updated_at`；每次确实推进一百年。另覆盖真实年度入口在第三年触发既有事件、第三年寿尽、已有事件阻止行动，分别确认三年／三年／零年与旧代码完整状态一致。正常游戏不固定 UUID，也不关闭事件。

边界测试见 `tests/test_action_time_performance.py` 与 `tests/test_economy_performance.py`，覆盖低价整数工资、资金守恒、负余额拒绝读档、动态阶数缓存、旧职衔只读投影及原商队候选规则。最终代码的 527 项专项测试、三项开发门禁及事件／经济真实页面验收通过。按用户要求仅进行改动领域与开发约定要求的回归，测试进程和浏览器串行运行；不启动 Android 模拟器，不写用户存档。单模块测试进程树 RSS 采样峰值 127.9MiB，浏览器进程树 855.2MiB；进程工作集求和可能重复计入共享页面。本次为源码优化，版本号未变，既有安装包不包含此次修改。

原始成对后台／点击样本、完整状态对照与代码摘要在 `build/action-100-performance/`，最终汇总为 `final-report.json`；专项回归与进程树 RSS 采样在 `build/action-performance-validation/report.json`。后台、页面、边界与专项回归绑定同一个最终源码摘要。这些构建目录产物是本次本机证据，不能替代发布时最终源码对应的 Windows／Android 成品验收。
