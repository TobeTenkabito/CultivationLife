# 分类导航与性能复核

维护基线：本体 **v2.8.0 / 存档结构 10**。

## 玩家操作

Windows 普通宽度窗口恢复 v2.7.2 的左右功能栏，直接点击原按钮打开面板，并保留后来新增的玩法入口。安卓（包括宽屏平板）、宽度不超过 900px 的窗口和高度不超过 520px 的触摸横屏采用六项固定底栏：常用、修行、百艺、经营、同道、诸界；宽屏鼠标窗口不会因高度较矮而切换为手机布局。窗口尺寸切换只搬移同一个原按钮节点，保留其事件、解锁、DLC、忙碌禁用及空间权限，不复制功能按钮，也不修改角色存档。

分类只展开当前目录；搜索覆盖所有已开放功能，星标最多八项，最近打开最多四项。偏好复用本机界面设置的原子保存入口，浏览器存储仅作后备，不属于角色存档；安卓进程重启、服务地址改变后仍可读取。分类提示继承原功能通知。拍卖会、交换会的预告与开放状态在手机“常用”内显示，并在桌面的对应原按钮上保留提示。地图、行囊、灵田的按需绘制不受桌面布局恢复影响。

自定义二级界面携带灵域传承后，左侧“灵域”（手机位于“修行”）从 Lv1 即可查看已学传承，并可前往行囊合参玉简。Lv4 才可展开、启用灵力储备；未满四级不补发灵力，也不开放战斗资格。不同界面、道途与独立空间的限制照常生效。

地图、行囊和灵田在打开面板时绘制；已经打开的面板随行动立即更新。未打开时只保留最新响应的绘制任务，切换角色会覆盖旧任务。空间地图仍由原空间展示入口构建，地点、实例和操作权限保持独立。

## 采样方法与发现

隔离存档、全 DLC、三个固定种子，每种子三次真实真仙百年休息；中位数分别 3605、3640、3879ms，总体取各种子中位数的中位数 **3640ms**。为测满百年，基准工具屏蔽归墟随机中断；正常游戏仍保留中断。cProfile 的插桩会显著增加耗时，不能用插桩总时长当玩家等待时间。

该采样使用新建真仙的初始世界，不代表长期人口变化后的大存档或其他硬件。完整页面状态的读档、拷贝和展示另做独立采样，不能用模拟耗时推断页面流畅度。

年度世界推进约占剖析累计时间 95%。商队推进约 51%，其中候选货物评估约 45%；消费结算约 38%，组织推进约 26%，生产约 25%，报价约 15%。这些是调用树中的嵌套累计占比，**不能相加**。一次百年剖析约调用报价 48 万次，仍是最值得继续优化的路径。

另用 `tools/audit_ui_performance.py` 在桌面 Chromium 的 412×915 视口，对同一普通/真仙响应各做十一次采样，丢弃首次预热样本、保留十次有效采样：计时覆盖真实 `render()` 和强制布局，两次绘制帧分隔样本。

| 场景 | 旧版主页面绘制中位数 | 最终代码 | DOM 减少 | 原 DOM 元素 | 最终 DOM 元素 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通开局 | 122.10ms | 30.40ms | 30.2% | 8301 | 5797 |
| 真仙开局 | 163.80ms | 57.80ms | 30.8% | 9904 | 6855 |

最终采样在浏览器与原生回归结束、关闭本次验收模拟器后执行，在同一主机连续测量隔离 Git 归档中的 2.7.2 与冻结后的 2.8.0。采样期间主机负载仍有明显波动，因此表中计时仅为实测样本，不能将差值全部归因于代码优化；DOM 数量下降是可复核的工作量变化。原基线仍保留，最终报告绑定生产代码哈希。后端获取完整页面状态（含读档准备）约 73.68/99.19ms，响应约 0.64/0.86MB。该入口剖析中读档准备约占 72–74%，深拷贝约占 57–60%，展示约占 26–28%；均是嵌套累计占比，不能相加。

这是前端主页面工作量下降，首次打开对应面板仍需完成其绘制，不代表百年模拟或手机帧率提升。本次没有缩减传输体积，不能为减少拷贝破坏事务回滚、存档缓存和角色隔离。

最终百年结算复测中位数为 **7182ms**，当前环境旧版对照 **6619ms**，早期原基线 **3640ms**；本轮单次采样约 3.8–7.6 秒，波动明显。本次后台模拟算法保持不变，这组计时不足以分离机器负载影响，继续优化的依据是调用剖析与重复工作量。新旧版本三种子各三次的完整结算状态均与原基线一致。对照仅排除墙钟保存时间，并要求最后保存版本等于各自正在运行的发行版本，其余字段完整比较。原始样本、首次打开面板耗时及剖析文件保留在 `build/performance-280/`。

## 继续优化的顺序与边界

1. 商队候选和报价：同一交易事务内复用基础估值、目录属性与固定配方信息；成交、库存、资金、路线或风险状态变更后必须失效。不能跨成交复用依赖供需的最终报价。
2. 组织生产和消费：继续按既有用途、阶数、人口境界聚合，减少重复候选构造和库存扫描；保留真实物品扣除、采购顺序、负债、欠费与战争军需结果。
3. 页面与响应：测量其他隐藏面板的绘制收益；拆分接口前先剥离 `ensure_*` 和会话准备副作用。不能把有随机、历史、战争准备或保存效果的展示入口直接当纯缓存函数。
4. 读档和拷贝：先确认缓存命中和快照复制的次数；只对经过审阅的不可变目录共享引用。人物、组织、物资和资源池必须保持唯一权威归属，不能共享可变存档副本。

后端改算法须在相同结构 10 初始存档与 RNG 下比较完整结算状态，并覆盖正常百年、中断、死亡、跨界、忙碌及部分年份结算。不能用年度抽样或跳过人物行动换取速度，不能逐年增加全商品或全 NPC 的新扫描。本次只改变界面构建时机，没有改模拟结算与游戏随机序列。

现有前十二候选已采用有界堆，复杂度约为 O(N log 12)；大宗报价已用积分公式，数量增长不会带来逐件循环。继续优化应减少重复评估，不能把候选长期固定，也不能省略成交后的重新估值。

新增功能按钮须在 `web/navigation.js` 的分类表登记；分类目录应复用原按钮节点，不另造绕过权限的操作按钮。

## 验收

`tests/test_release_280.py` 覆盖五个二级界面、四个携带等级的权威开局、灵力和展开门槛。`tests/browser_release_280.py` 用真实表单提交与页面点击覆盖四主题、桌面/360/412/横屏、搜索、星标、退出、读档与角色切换；实际导航不改角色存档。浏览器与签名 Android 原生验收同时覆盖空间地图、事件旧交互、禁用选项、教程、DLC 和跨端存档。发行门禁、成品和源码哈希见当前 `dist/` 清单与 `build/release-280-acceptance.json`。

桌面恢复另用 `tests/browser_desktop_navigation.py` 验证四主题、1440×960 / 1024×768 / 1440×480 的直接面板点击、重复缩放后的按钮身份、真实行动请求期间的忙碌禁用、角色存档不变及安卓桥接 / 安卓 UA 宽屏 / 触摸横屏分类导航；`tests/browser_release_290.py` 同时覆盖两种布局的限时活动生命周期。此处布局修复的截图与报告位于 `build/desktop-navigation/`，不替代发布时的最终成品验收。
