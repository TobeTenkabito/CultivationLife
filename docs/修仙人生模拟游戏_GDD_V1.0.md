# 浮生问道：当前产品与系统规格

维护基线：本体 v2.13.5，2026-10-14。文件名沿用最初 GDD 编号以保持引用；正文描述当前实现。当前发行说明见 [CHANGELOG](../CHANGELOG.md)。

## 产品与运行方式

单人、本地、事件驱动的修仙人生模拟。Python 标准库后端提供 HTTP API，原生 HTML/CSS/JavaScript 呈现界面；Windows 启动器与 Android WebView 使用共同规则和内容。六套主题分别维护布局，游戏不依赖云账号或联网服务。

普通开局与多种快速开局并存。角色从修行、游历、经营、关系和势力行动中积累资源、改变身份并推进世界；没有代码保证的固定单局时长。随机种子与 RNG 状态随存档保存，重放需同时固定时钟、UUID、内容配置及操作序列。

## 世界、时间与事件

当前有十一界：人界、魔界、灵界、真魔界、妖界、幻冥界、地狱界、仙界、修罗界、幽冥界、轮回界。世界、地图、通用功法与物品由本体提供；对应 DLC 控制专属系统和剧情，不负责移除本体地图。

行动单位按修为确定，可包含多年，不能把一次点击等同一年。普通行动与地图旅行共用 `time_flow.py` 的年度收尾、单位结算；年度系统顺序由 `engine/orchestration/world_time.py` 维护。两者的单位取值、金光／本命结算位置、神机钩子与市场时钟有明确策略差异，详见 [引擎时间流程](../cultivation_life/engine/README.md)。

事件、天劫、生死和活动窗口可中断行动，只计实际经过时间。商盟工作、佛门法会、鬼道等待及归墟专属活动保留自身时间语义。跨界资格由道途流程判断，公共计划与提交负责路线、封印、落点及同行人物，见 [跨界系统](world-transitions.md)。

## 修行与资源

修为、炼体、神识独立成长；功法有主修、辅修和战斗用途，四气与灵根条件影响可用性。普通路线沿现有自动层级、手动关口及天劫规则。机缘上限不是全局统一值：仙境采用独立仙脉与冲关费用；修罗显圣加载后的上境魔修采用无上限储量、魔脉及专属劫战；其它路线按本体与已加载扩展判断。

仙界包括固定及随机道统、唯一道统本源、仙脉、仙躯、护体金光、邻域培养、真传合练和跨境劫战。仙痕按正数机缘授予独立判定，当前概率 15%；价格、概率和成长阈值以 `content/doctrines.json` 为依据，详见 [仙界养成](doctrines.md)。

修罗、幽冥、轮回有本体九级邻域和独立高阶元力；修罗显圣满足资格后由八部魔域接管修罗入口。领域与普通 MP 分账，跨界封存不免费补充。详见 [三界邻域](upper-voisinages-1522.md)。

## 战斗与人物

普通战斗以六维、战斗目的、阵容及有限资源结算；邻域通过中立 `CapabilitySource` 提供稳固、侵夺、权能和有限效果。领域效果与普通行动独立计数，付费普通处决仍占用行动。玩家、NPC 与劫战共用底层规则，NPC 保留简化常规交锋模型；不能把面板战力直接换算成邻域优势。

战斗语义 V3 与原血脉／神机 V1、V2 分开，按实际阶段读取事实、处理计数和状态。领域内核不认识道统名称、DLC 或剧情人物。见 [内核](combat-domains.md)、[效果](combat-effects.md)、[语义](combat-semantics.md)。

NPC ID 关联权威人物。师徒、道侣、道友、俘虏及侍妾记录只持久化关系特有字段；姓名、生死、世界、修为等读取同一人物。事件生成人物保存在 `relationship_npcs` 并保留原年度安排，不强行加入自由 NPC 池。

俘虏与俘虏来源侍妾关联受控名册中的 NPC，`alive` 只表示真实生存，拘禁与是否自由活动分别记录。生擒不再伪装死亡，释放不能复活死者；活傀、拘魂和后代成长仍按专用流程结算，见 [状态契约](npc-custody.md)。

## 经营、势力与扩展

本体提供坊市、拍卖、黑市、交换会、商盟委托、灵田炼丹、五槽炼器、九宫阵法、本命法宝和傀儡工坊。资源扣除、返还、持有和订单交付由实际账本决定，预览不能替代提交时校验。

宗门、家族、种族和机构分型。天庭、瑶池、修罗王庭、万妖宫及轮回殿不占用宗门身份；各机构拥有独立政历、功勋或权限。战争、伤亡、和约与内政通过具名依赖接入。归墟已有十一界副本，见 [归墟现行规格](归墟之潮_九死一生_DLC策划案_V0.2.md)。

八个官方 DLC 及当前清单见 [DLC 目录](../dlc/README.md)。扩展按本体→DLC→MOD 顺序加载，数据通过校验后合并，不执行包内脚本。界面根据本次实际加载状态及角色门槛显示玩法；待重启偏好不等于玩法已启用。

## 存档与开发边界

当前仅支持结构 10；结构 1–9 不兼容，不映射、不转换。读档依次经过文档读取、结构校验、模型解码与分阶段会话准备；准备不能消费随机数或执行玩法，写入成功前不得破坏原文件。FSWD1 封装版本与角色结构独立，见 [传输协议](save-code-format.md)。

`GameEngine` 是稳定入口，算法使用普通模块函数、窄依赖契约与显式装配。现有九个局部 Mixin 不因“Mixin”这个名称就必须删除；优先拆分跨系统编排与共享状态写入。当前仍有展示补全副作用和少量兼容入口，新增系统遵循 [引擎](../cultivation_life/engine/README.md) 与 [系统](../cultivation_life/system/README.md) 的依赖边界。

验证采用 pytest、显式依赖检查、固定种子回放、浏览器及各平台发行验收。文档中的功能存在不等于全部设备已验证；最新执行结果与待改进项见 [项目诊断](project-diagnosis.md)。

## 非经济系统边界修复（v2.13.4 源码）

鬼修轮回须先解除秘法压制、沿原通道解除下界封印并结束寄身。资格、直接命令及事件效果使用同一校验；已有不合法轮回提示保留，提交选项禁用，仍可放弃并领取原后续奖励。拒绝不消耗资源、随机数或轮回印记，不删除原修为保存记录。

普通炼器主材按权威定义品阶计算，缺失或无效品阶不能用玩家境界替代。普通及神机动态材料读取各自定义的 `tier`；归墟材料、灵植读取原副本最高入场境界（本目录为 4／6／11），跨界携带不改来源。灵田采收主材使用 `content/crafting.json` 的实生年份阶表：不足百年为 1 阶，百年、千年、万年起依次为 2／3／4 阶；品质和锚定价值仍按原采收结果。实际成器基准不超过使用者当前境界，预览显示主材基准。既有成品与用户存档不自动重算。

归墟旧 `trapped_cultivate` 保留每次一年，主行动保留原行动单位；两者共用年度收尾结算魂蚀，年度事件或宿身死亡即停止后续年份。魂基归零后的战力展示只保护比例分母，不补回魂基、气血或复活人物。

归墟品阶目录采用单份有界缓存，不增加年度遍历或持久字段；同一堆叠材料在炼器中最多投影四个选材位置，阵法中最多投影九个，保留真实总数量，开炉、启阵和收阵仍按实际份数扣取或返还，避免大量库存展开成海量临时对象。专项入口为 `tests/test_other_systems_audit_fixes.py`、`tests/browser_other_systems_audit_fixes.py`，另执行事件、修为、鬼道、炼器、神机、灵田、阵法、归墟、时间、战斗和跨界相关回归以及三项开发门禁；均串行执行，浏览器每次只保留一个页面，不运行全仓。本次为源码修复，未更新版本或重打安装包。

上一轮验收：449 项专项通过（含 45 项新增回归），三项门禁、JavaScript 语法检查，以及新专项和原事件专项的桌面／手机真实点击全部通过。生产源码校验为 `325dde7c14c7c73fe5924d8c3e1b0412e03648faf2b88120a25bcabd18e34002`，对应上一轮最终代码。测试进程树采样峰值约 135 MiB，浏览器约 783 MiB（共享页可能重复计数）；未运行全仓或 Android 模拟器，未修改用户存档。日志与记录见 `build/other-systems-fix-validation/final-report.json`。

## 关系与夺舍边界修复（v2.13.4 源码）

夺舍资格统一排除压制修为及下界封印，覆盖俘虏夺舍、反夺拘魂者、战陨夺舍和底层寄身入口；寄身期间禁止启停压制。旧压制后寄身状态可先离舍再解除压制，保留尚在压制记录中的本魂原修为与机缘，不自动编辑用户存档。

派遣、师徒、道侣、道友、随行、引荐及关系解除命令先检查玩家存活。师徒交付与收徒使用权威人物的世界和实例资格，离界后关系保留，赠物、传功、索物和收徒暂停，返界后恢复；拒绝不写档、不投骰、不消耗年度次数或物品。资格只作页面投影，无新增年度扫描、运输或持久字段。相关源码验收入口为 `tests/test_relationship_possession_audit_fixes.py`、`tests/browser_relationship_possession_audit_fixes.py`，串行运行改动领域与开发门禁，版本和安装包不在本次更新范围。

本轮最终验收：373 项相关回归通过（含 34 项新增真实接口及权限边界回归），三项门禁、JavaScript 语法检查、新专项和原事件专项桌面／手机点击通过，覆盖过期提交一次拒绝与一次重读、忙碌解除、禁用状态、正常返界交付、奖励和离舍。生产源码校验为 `42c2d0850d7bbafaf89e8ba303f4a1e6603c94f4fb74e24aa960ab77408fa7e2`，验收期间保持一致。全程串行、每次一个浏览器页面；测试进程树采样峰值约 176 MiB，浏览器约 827 MiB（共享页可能重复计数）。未运行全仓、Android 模拟器或发行打包，未修改用户存档。记录见 `build/relationship-possession-fix-validation/report.json`。
