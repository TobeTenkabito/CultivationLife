# 人物生存、拘禁与名册契约

维护基线：v1.58.0，存档结构 8，2026-10-04。

`alive` 只表示原人物是否存活。被俘或受活傀控制不会伪装成死亡；释放也不能将真正死亡的人复活。人物保持原 NPC ID，关系与人物分开持久化。

## 状态与数据归属

| 字段／容器 | 含义 |
| --- | --- |
| `SectNpc.alive`、`death_reason` | 真实生命状态与死因 |
| `roster_state=active` | 仍属于原自由／事件人物名册，按原系统规则决定是否参与活动 |
| `roster_state=held` | 玩家持有的俘虏、俘虏来源侍妾或活傀原人物，不参加自由 NPC 演算 |
| `roster_state=retired` | 已离开活动名册，不代表死亡；实际死亡另看 `alive` |
| `custody` | 受控类型 `prisoner`／`concubine`／`living_puppet`、控制方存档 ID 和起始年龄 |
| `roster_origin` | 被移出容器的位置；释放只恢复仍有效且同界的原势力 |
| `GameState.inactive_npcs` | 受控／离册人物的权威记录，供关系引用解析 |
| 俘虏、侍妾关系记录 | NPC ID、捕获来源和关系操作字段，不重复持久化个人生死与修为 |
| 活傀记录 | 专用战斗／培养资源，新增 `source_npc_id`；生命转换回写原人物，释放时带回培养后的修为、炼体和功法 |

`npc_custody.py` 提供拘禁、释放、死亡、离册和活傀结算操作，不导入引擎、模型或玩法系统。`find_person` 解析权威人物，包括受控名册；引擎 `_find_npc` 仅供原名册操作。关系或后代回退路径必须检查 `is_free`，不能因人物存活就重新加入队伍、宗门或自由年度演算。

## 转换

| 操作 | 人物结果 | 保留的玩法规则 |
| --- | --- | --- |
| 战斗生擒、关系背叛生擒、议和人质 | 存活＋受控，移出自由容器与队伍 | 捕获概率、好感变化与奖励 |
| 释放俘虏、遣散仍存活的俘虏来源侍妾 | 恢复有效原名册；失效／异界势力改入留名人物 | 原好感结算，不覆盖实际死亡 |
| 俘虏转侍妾 | 同一人物改为侍妾受控身份 | 原侍妾年度成长，去重后每年一次；普通俘虏不新增年度成长 |
| 成功种下活傀印 | 原人物存活、受控，傀儡资源记下原 ID | 活傀继承战力、控制度与专用培养 |
| 活傀解除控制或逃脱 | 原人物回到有效自由名册 | 逃脱概率、反噬伤害与已获得培养 |
| 处决、炼尸成败、夺舍消灭原神魂、吞噬或战斗摧毁活傀、凝练修罗肉身 | 原人物实际死亡，受控名册改为离册；尸体／神魂等资源由专用玩法保存 | 原资源消耗、概率、战利品与业力流程 |
| 临时跨界 | 受控人物随持有者切换世界 | 不给其自由队伍资格；回到原界前不会恢复原宗门 |
| 永久飞升清理 | 存活人物离册，结束控制关系 | 原有清空俘虏、侍妾、傀儡规则，不新增释放奖励或虚构死亡 |

自由关系人物继续受原世界年度流程管理。后代家庭记录保留独立成长结构，但拘禁、释放、死亡和跨界会同步实际状态；受控后不能再次自动入族或重复成长。机构监禁、玩家拘魂、夜行魂仆原本就有专用状态，本次未强行改写这些制度及其时钟。

## 旧档与验证边界

2026-10-19 架构验收续核：诸天勘察引用校验遵守拘禁入口移除自由空间名册的既有规则，受控时保留原人物与勘察引用。原普通居民在同一勘察实例获释时恢复其原 `world_npcs` 权威容器和空间名册，避免被误判为新关系职责而无法续行；其他实例仍沿原关系名册规则处理，不复制人物、不远程恢复原空间。镜律与因果遗址验证实际保存、暂停、同场获释、续行及拒绝伪造受控空间名单。

2026-10-18 拘魂续审：拘魂忍耐、反抗和反夺入口先校验待处理事件、活动劫战，拒绝不投骰、不增龄、不耗资源、不修改魂印或后续奖励。仅这三个按钮随事件／劫战禁用，原允许事件中换魂位的规则保留；旧页面拒绝后读取权威状态一次。拘魂年度在实际改变玩家本界地点时取消旧远行；忍耐命令在年度业务与魂蚀完成后复用市场收尾入口，普通修炼／休息沿原行动收尾刷新，避免长行动中每年重刷市场和打乱业务随机顺序。不改写 world、不增加跨界能力。验证见 `tests/test_audit_followup_guards.py` 与 `tests/browser_audit_followup_guards.py`。

2026-10-18 续审：`transfer_free_person` 仅移动自由人物的权威名册归属，合并或解散后从旧宗门、家族及散修容器移除原条目，再交给新宗门或散修名册；身体地址、关系引用和生命不变，受控人物不借和约释放或重建。活傀年度控制自然衰减至零仍为活体，可按原付费入口加固；真实战损的 `alive=false`、机关耐久和炼尸完整度归零、原人物陨落才阻止培养与奖励。公开投影同时清零死亡资产贡献、年度机缘，界面仅留解除入口。已登记拘魂者死亡解除个人魂印；未登记临时对手只有快照时不凭缺失人物推断死亡。

2026-10-18 结构10复核：拘禁还须移除实例 `npc_ids`，以 `roster_origin` 的 `spatial/id/index` 记录原名册位置；空间年度和人物查询排除受控、离册及实际世界不符者。释放恢复原人物在实际所在地的自由名册：同一实例保留原宗籍，外界或其他实例解除旧实例引用和旧宗籍，不能让两个失落界面共用一个人的活动资格。已受控旧结构10空间引用在原拘禁绑定入口移出，不复活已死亡人物。

改变自由名册前，沿原确定性规则固化尚未保存的实例家族编号分组，避免名单缩短或插入后让其他 NPC 自动换族；同实例释放还原原名册位置。原人物家族编号不随俘虏复制到另一实例，家族显示只解析当前实例自由名册。

新活傀从原人物记录 `age/lifespan`，修为培养沿现有寿元增益规则结算；解除控制或逃脱时将已付培养后的寿元交还同一原人物。缺少这两项的旧活傀仅在下一次合法培养报价时读取原人物作为输入，成功扣费后保存，不推测历史奖励，无穷寿元仍为 `null`。已毁傀儡或原人物已死亡的活傀不能喂丹、改修、加固、培养或吞噬；黑市不展示也不收购已毁机关傀儡／炼尸。仍可解除控制清理残留资产，不能复活原人物。专项回归 `tests/test_pending_audit_fixes.py` 使用真实捕获提交、跨界通道、付费培养与未替换的战斗结算。

注册的纯迁移链为 **6→7→8**。6→7 先迁移普通关系，保留俘虏快照供下一步处理；7→8 仅把死因以“生擒／扣作议和人质／炼为活傀”结尾的明确旧退场标记改为存活，不修正真实处决或寿尽记录。仍持有的俘虏／侍妾可按 ID 建立受控关系；原文件在完整迁移与模型校验成功前保持不动，迁移不消费 RNG、不结算玩法。

旧活傀在生成时丢弃了原人物 ID，不能可靠恢复来源。同名不能证明同一身份：这类旧活傀继续使用专用资源记录，不强行关联 NPC；只有旧人物自身的明确假死亡标记会被修正为“存活、离册”。新生成活傀均记录来源 ID。结构 1–5 的拒绝策略不变。

回归集中在 `tests/test_npc_custody.py`，覆盖捕获、释放、实际死亡、侍妾年度成长、活傀成败／逃脱／吞噬、跨界、后代重入防护、引用回读、克隆隔离和逐级迁移；已有关系、魔道、鬼道、家族及跨界测试继续执行。验证方法与开发边界见 [项目诊断](project-diagnosis.md)。
