# 第5步：经济、战斗与DLC迁移

## 第一批迁移结果

本批先确定三个后续子系统都要依赖的边界：物品账本、战斗快照和扩展注册。它们全部引用第4步的角色、修炼、世界与势力实体，没有创建第二份Player或NPC快照作为权威数据。

## 经济边界

- `economy.inventory`是角色物品与冻结数量的唯一权威账本。
- 灵石与普通物品使用同一个原子增减通道；失败命令不会保存任何中间扣款。
- `economy.market`是角色当前坊市批次、货物与锁定状态的权威位置。
- 锁定按货架分组互斥，刷新时保留同地点的锁定货物。
- 购买功法通过`economy.technique.purchased`事件请求修炼领域验证和入库；经济领域不直接改写功法槽。

## 战斗边界

`ResolveCombat`从权威实体读取境界、道路、功法、行囊和当前伤势，生成一次不可变的战斗输入快照。回合解算只消耗该快照和确定性随机流，输出：

- `combat.condition`中的HP/MP比例；
- 独立`combat:*`战报实体；
- `combat.resolved`事实事件；
- 必要时的`character.lethal_hazard`或`combat_prisoner`关系。

战斗领域不直接把角色标记为死亡；最终生死仍由人物领域统一处理。

## 扩展加载边界

V2使用独立扩展加载器读取`manifest.json`和内容覆盖，并复用`data/extension_preferences.json`中的玩家开关。加载顺序为DLC先于MOD，同类再按`load_order`和ID排序。每个候选包合并后都会重新构建并验证V2定义；失败的包被标记为`error`并跳过。存档会记录已加载包的ID和版本，扩展升级但没有对应迁移时拒绝用新规则静默读取旧状态。

V2不导入V1的`extension_system`、`ContentRegistry`或任何具体DLC Python模块。

## 官方DLC的首批运行状态

| DLC | 权威组件 | 已接入行为 |
| --- | --- | --- |
| 百鬼夜行：轮回往生 | `dlc.ghost.soul` | 魂基、魂蚀率、按实际时间累积的魂蚀单位、往生消耗入口 |
| 妖修道途：血脉与进化 | `dlc.monster.bloodline` | 不可重置的本源谱系选择、地点实际经过年数和环境适应解锁 |
| 明争暗斗：合纵连横 | `dlc.intrigue.governance` | 势力独立职位表、成员/境界/控制权验证后的任免 |

DLC关闭时，已存在的组件保留但不继续演算；重新启用后从冻结值继续，不追溯关闭期间的年度效果。

## 后续批次

本批确立的是第5步基础和可玩最小闭环，下列内容仍需逐批迁移：

1. 拍卖托管账本与取消/退款，再迁移灵田、炼丹、炼器、阵法和黑市。
2. 队伍战斗、阵法/地形/特质钩子、战争战场和俘虏/傀儡后续处理。
3. 鬼修魂位、百鬼夜行、附灵、夺舍与完整轮回。
4. 妖修进化图、随机血脉特质、返祖和自创祖血规则解释器。
5. 内政决议队列、一人一票、弟子招募、客卿职责和实体监狱。
