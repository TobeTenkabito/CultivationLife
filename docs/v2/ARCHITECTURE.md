# V2架构约束

## 决策

V2采用确定性模拟内核和领域模块化单体。它与V1并行开发，但不得依赖V1的`GameEngine`、`Player`、`GameState`或JSON存档类。

```text
presentation → application → domain modules → kernel
                         infrastructure ─┘
```

- `kernel`只提供时间、实体、命令、事件、调度和不变量机制，不认识修炼、宗门或DLC。
- `domain`拥有业务状态和规则，只依赖kernel，不导入数据库、HTTP或V1模块。
- `application`负责加载、执行一个命令、验证、原子保存和生成投影。
- `infrastructure`实现SQLite等端口，不包含游戏规则。
- 未来DLC只能注册命令、事件处理器、投影、迁移和不变量，不能继承总引擎。
- DLC/MOD内容包由V2基础设施独立发现、合并和验证；单个包失败时应跳过该包，不得借用V1扩展运行时。

## 状态写入规则

1. 外部意图必须表示为有类型的命令。
2. 一个命令在一份内存状态上完成；失败时不写入存档。
3. 跨领域已经发生的事实使用有类型、有来源、有作用域的事件表达。事件可被其他领域消费，但不能直接调用其内部函数。
4. 时间只能通过`TimeService`推进。
5. 实体组件必须通过`EntityStore`读写；读取返回副本，避免命令外的别名修改。
6. 每个成功命令在保存前运行全局不变量。
7. SQLite修订号实行乐观并发控制，旧快照不能覆盖新快照。

## 时间与事件顺序

调度事件按`(due_year, sequence)`稳定排序。模拟时钟逐个推进到事件时刻并立即派发；若受控角色在长行动中寿尽或遇到致死事件，时间在死亡当年停止，余下行动事件被取消。处理器因而始终观察事件真正发生的时刻。

所有已迁移的耗时玩法先在`core.action_runtime`登记行动令牌、起止年份和来源，再由统一时间服务推进。交互事件可以在任意调度点暂停；待选择完成后，运行时从原目标年份继续，而不是重新提交或重复扣除行动成本。

`story.state`持久化当前交互、后续队列、剧情历史、标记和里程碑。内容文件会被编译为有类型的事件、选项与效果定义；只有所有效果都已注册的完整事件链才会进入随机候选池，避免尚未迁移的效果被静默跳过。

领域事件写入追加式日志，用于调试和未来影子运行。当前存档依然以快照为加载来源，不采用完整事件溯源。

## 实体原则

一个游戏事实只能有一个权威存储位置。人物、势力等都是带有组件的规范实体；人际关系和势力身份是指向实体ID的类型化边，不保存NPC人物副本。关系仓库可共享，但领域投影必须按边类型隔离，不向人际关系界面暴露势力成员边。

## 存档边界

- 格式标识：`cultivation-life-v2`
- 当前V2 Schema：`7`
- 默认建议路径：`data/v2/saves.sqlite3`
- V1和V2不共享表、不共享文件、不互相覆盖。
- 核心和每个领域/DLC分别持有模块版本；后续迁移按模块注册。
- 每个存档记录已加载扩展的包ID与版本；版本变化时必须先提供该包的专用迁移，不能静默使用新规则解释旧状态。
- V1导入是基础设施层的单向适配：只读原始JSON，不实例化V1模型，不覆盖源文件，并为所有降级项生成审计报告。
- V1导入必须先完成内容寻址备份并同步落盘，之后才能开启V2 SQLite写事务；备份失败即导入失败。
- V2没有V1格式写回端口，任何V2状态都不能覆盖或降级保存为V1 JSON。
- 同时依赖V1/V2的影子运行代码只能位于`cultivation_life.migration`集成边界，任何V2模块都不得反向引用它。

## 迁移验证

旧存档导入和V1/V2规则等价性是两个独立问题。导入器负责在一个时间点安全搬运可表达状态；影子运行器负责从同一种子和命令序列观察两套规则的后续差异。影子比较使用稳定语义投影，不比较实体ID、事件ID、修订号和时间戳等实现细节。

正式切换由`docs/v2/feature_matrix.json`控制。冻结的V1公开操作必须在矩阵中完整且唯一覆盖，所有必需功能必须为`pass`，证据文件必须存在。废弃功能必须有决策记录并显式移出必需项；启动器和前端不得绕过该门禁提前指向V2。

## 当前垂直切片

现有命令覆盖角色创建、角色注册、按行动单位修炼/休息/炼体/锻炼神识、功法学习与分槽配置、基础突破、变化术、地图移动、下界飞升与跨界往返、人际关系建立/结束、势力基础操作、行囊与坊市交易、单场自动战斗，以及首批DLC命令。

Schema 6 将炼体、神识和变化术拆成独立组件；Schema 7 新增持久化试炼状态。传统突破、天劫、天魔劫及仙/修罗九重飞升均逐关提交选择，可跨保存读取继续。永久跨界采用准备—领域回执—提交三段式事务：关系、势力、经济和战斗领域缺少任一回执时，世界坐标不得改变；事件处理器内发起的跨界由最后一个回执自动提交。跨界只发布一个规范事实，各领域自行清理其权威状态，避免在世界模块中直接修改侍妾、宗门、冻结资产或俘虏数据。

公开投影已拆分人物、修炼、世界、人际关系、所属势力、行囊、坊市、战斗和扩展状态。它是V2领域的应用边界，不是V1 API兼容层。
