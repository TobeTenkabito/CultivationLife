# 第4步：核心领域迁移

## 目标与范围

本阶段先迁移人物、修炼、世界、关系和势力的权威数据模型与基础行为，使后续经济、战斗和DLC可以指向同一份人物/世界/势力事实。迁移不是把V1大类复制进V2，而是将数据所有权和跨领域协作方式固定下来。

## 权威状态

| 领域 | 权威状态 | 不保存的重复数据 |
| --- | --- | --- |
| 人物 | `core.identity`、`character.life`、`character.activity` | 关系或势力中的人物副本 |
| 修炼 | `cultivation.state`、`cultivation.practice` | 世界灵气、地点效率和功法定义副本 |
| 世界 | `world.location` | 角色列表和势力列表 |
| 关系 | `RelationStore`中的类型化边 | 人物公开数据快照 |
| 势力 | `faction.profile`、`faction.governance`和`faction_membership`边 | 全局人物贡献字段 |

势力贡献属于某一条成员关系；退出势力会结束该关系，加入新势力必然从零开始。这从模型上消除了V1的“贡献带入新宗门”问题。

## 跨领域事件

- `character.created`触发修炼和世界组件初始化。
- `character.lifespan.changed`重新计算寿尽事件，不由突破模块自行管理死亡。
- `character.died`取消未完成的修炼/移动事件，必要时置空势力控制权。
- `world.lethal_hazard`交由人物领域统一执行死亡，世界领域不直接改写寿命。

## 时间语义

修炼行动按年安排细粒度事件，而不是一次跳到整个行动的终点。这保证寿尽、旅行危险和未来的随机事件能在正确年份打断行动。调度顺序只由`(due_year, sequence)`决定，相同种子和命令序列会得到相同游戏结果。

## 内容数据边界

V2内容加载器的核心定义读取`world.json`、`maps.json`、`factions.json`、`techniques.json`、`items.json`和`market.json`，并验证重复键、引用、路线和灵气来源等约束。第5步起还会在每个DLC/MOD合并后重新验证这些定义。它不导入V1 Python运行时；共用的只是可版本化内容文档。

## 尚未迁移的边界

当前实现是第4步的核心基础，不表示下列玩法已与V1平价：

- 人物战斗面板、物品/装备、状态效果和完整NPC初始化；
- 高阶突破试炼、飞升、跨界和世界持久性变迁；
- 势力NPC阵容、职位事件、资源和经营循环；
- 人际事件、好感度和关系专属玩法。

这些应在同一领域边界上继续增量迁移，不应再建立第二份人物、世界或势力状态。
