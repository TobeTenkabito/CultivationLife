# 地图建筑与洞府

维护基线：本体 v2.17.1，存档结构 10。v2.17.0 城市与重建采用 buildings 全仓配置；本次建筑视觉与游历采用 building-visits 相关领域配置，不做全仓。正式交付须有匹配最终代码的源码、页面、EXE 与签名 Android 验收。

## 边界

- 区域承载 `city`、`scenery`、`industry`、`artificiality`、`other` 五类建筑。地址分别记录界面、实例与地点；进入建筑只开事件会话，不移动玩家，不创建独立空间，不切换地区时钟。
- 十一界各新增两座初始城市和一处纯景色，初始内容只读采用，实际产权、等级或状态改变时才保存唯一覆盖记录。洞府、原产业、佛门寺庙继续沿原状态结算；城市分军事、经济、综合用途及一级城市、二级大城市、三级大都市。
- 建筑分别记录所有者、使用许可和公开使用标志。没有使用权不能进入；在场勘看建筑及其遗址不等于取得使用权。联系所有者的谈判、租赁和自动授权规则暂不实装。景观默认为无主、公开观景，禁止损坏或摧毁，不给属性、物品或洗涤资质。
- 产业仅引用原 `economy_v2.estates`，不复制仓库、生产任务或资金。寺庙按原 `buddhist_state` 实时投影，建造、扩建及加持复用原佛门结算；关闭对应 DLC 时不显示寺庙，不删除原寺庙数据。

## 城市与活动

用途和居民属性分别选择；修士之城、凡人之城、混居之城不自动授予新的玩家通行资格。非人族界面的“凡人”指尚未入道的居民，并非强制增加人族。初始城池公开使用；自建城市归本人所有并公开街坊。未模拟城市居民 NPC 或复制任何原人物，也不新增城市年度税金、人口和经济循环。

| 界面 | 初始城市 |
| --- | --- |
| 人界 | 无羁城、岚津城 |
| 灵界 | 垂虹城、霆门城 |
| 魔界 | 聚煞城、赤髓城 |
| 真魔界 | 渊极城、乌砾城 |
| 妖界 | 万兽城、青丘城 |
| 幻冥界 | 月棱城、九尾梦城 |
| 地狱界 | 幽关城、魂灯城 |
| 仙界 | 接云城、玉京仙城 |
| 修罗界 | 修罗关城、万战城 |
| 幽冥界 | 祖苑城、栖枝城 |
| 轮回界 | 因果城、彼岸城 |

每城有专有城府、坊巷、演武文案和独立两分支逸事。城府与坊巷只叙事、不发奖；逸事每城每人生仅结算一次，奖励为本城参照境界基础机缘的 2%，演武最多尝试三次，首次胜出仅结算一次、奖励为 1%。均沿原机缘、四气、修炼上限入口结算，不直接改写资质、HP/MP 上限或境界。次数绑定稳定城市编号，重建、产权变化、跨界、读档均不刷新；演武是原非致命战斗，气血法力照常消耗，现行资格与仙界律令不豁免。没有真实城主人物的场景仅由值房主簿出面，不冒用异地 NPC 的职位或修为。

## 筑城与发展

只能在普通地图实际所在地筑城。每位玩家每地域最多一座自建城，保留的遗址也占这个位置。初建只为一级，可选择三种用途和三种居民属性；城名沿角色名生成。材料来自原行囊，不自动购料、不过界取货。

| 工程 | 结构矿材 | 导灵矿材 | 蓄灵矿材 | 工费倍数 |
| --- | --- | --- | --- | --- |
| 一级筑城／城市重建 | 1200 | 600 | 300 | 40000 |
| 扩建二级 | 3600 | 1800 | 900 | 160000 |
| 扩建三级 | 9600 | 4800 | 2400 | 640000 |

三种矿材使用本界通用商品，第一／二／三界层分别为一／五／九阶；工费乘同阶通用原材料基准价。一级人界工费为 80000 灵石，另需 2100 件矿材。材料实际消耗，工费进入原地区营造经营账户，不创建新的城库余额。

一级到二级需 6 次治理，二级到三级需 12 次治理；每城每真实年只能治理一次，每次另消耗 20／10／5 件三种矿材与当前规格工费的 1/20。年份只能在建筑外沿原行动推进，不能靠菜单或来回进出刷新。扩建每次只升一级；三级不再累加无效进度。城市重建从一级和零进度开始，但已得活动奖励不恢复。

## 摧毁与重建

地图的“营造”入口打开所在地的勘看事件。原所有者或对原产业有经营权的人可以主动拆除；破坏他人建筑必须达到展示的实际战力要求并支付最大法力的 1/4，资格不足时在服务端拒绝。所有操作需独立确认，报价令牌绑定用途、原地址、产权、等级、状态和实际工料，过期页面不得按新价暗扣。

城市保留同一编号和“原城名遗址”，可由原所有者或公开城市的捐建者重建，捐建不夺取产权；其他废墟也保留原址。洞府按原等级品质全额修复，旧投入不作为免费修复折扣；寺庙沿原佛门付费入口从一级重建，停止时不计寺庙等级收益，原信众与加持记录不复制。

产业设施毁坏撤销经营与托管、暂停已付批次；原仓库、在途货物、原周转金、资源储量仍在原权威记录中，旧债与仓储维护照常。重建按原规格产权基准价支付，不填满库存、不恢复矿藏；原批次完工时刻仅顺延真实停工年份，恢复后仍须手动配置新经营。

原战役每次真实会战在原世界地点对非城市、非景色建筑各有 8% 损毁概率；用种子、战役、会战序号与建筑编号确定，不额外消耗原玩法 RNG，同一会战只判一次。冻结地区仍沿原战役补算，不从界面查看启动模拟。城市不会被此自动规则摧毁，主动破坏沿同一资格入口。建筑损毁不凭空登记任何真实人物死亡、击杀奖励或资源退款。

## 洞府

在普通地图的“此地建筑”中开辟；每位玩家每处地域最多一座自有洞府。初版以支付资材或营造委托费即时完成，不虚构施工人物与工期；菜单和建筑内行动均不推进年份。专业营造效果优于自行开辟。

| 规格 | 自行开辟费用 / 气收益 | 专业营造费用 / 气收益 |
| --- | --- | --- |
| 一级 | 200 / +2% | 800 / +4% |
| 二级 | 800 / +4% | 3200 / +8% |
| 三级 | 1800 / +6% | 7200 / +12% |

费用乘所在界面的原 tier。整修只补历史投入与目标费用的差额，不降级、不降品质；实际支付入原地区经营账户。数值配置位于 `content/world.json` 的 `systems.building_system`。

建成或进入有使用权的洞府后选为当地聚气处。离开建筑再按原修炼入口消耗真实年份，洞府仅放大此地图原有气经验，不增加机缘、不新增气种、不叠加洞府。换地图、换界、进入空间或失去使用权后不享受原地加成。取值为地址索引 O(1)，不新增年度扫描或经济模拟任务。

## 事件与展示

v2.17.1 的概览与地图详情共用文字名录。名称、类型、等级和状态在收起时可扫描，进入与营造仍直接可点；展开后显示建筑画稿、完整风貌及权限。每个建筑是平直名录行，不增加导航、不在地域卡中嵌套装饰卡片；图像在折叠状态不占版面。

景色有循迹、天候、旧迹三组双分支探索，均不发物品、属性、机缘或四气，不推进时间，不消费随机数。六类产业各有双分支作业见闻，查账只读原产业仓储及在制批次，不提货、不改配方、不造产量。寺庙随原佛门 DLC 显隐，新增听钟、香客和义理对话，不增加信众、愿力或业德。

每处产业及寺庙各有一次心得：本界起始参照境界（一／五／九）的基础机缘乘配置 `visit_insight_opportunity_fraction=0.005`，复用原机缘与四气结算；不直接改资质、HP/MP或境界。`visit_usage[building_id].insight=1`在实际选择后持久化，读档、跨界、产权变化、DLC开关与原址重建均不重置。叙事分支可重看，但不能再领奖。所有进入、阅读与选择仍复验原地址、原使用权与当前事件编号，失效会话保留后续奖励。

视觉素材为内置 image_gen 生成的透明画稿 [building-gazetteer-2171.png](../web/assets/building-gazetteer-2171.png)，未使用 CLI 或编辑用户截图。生成提示：1536×1024、严格3列2行透明图集，依次为城门、山水、工坊、洞府、佛寺、亭院；细致木刻与水墨、松绿和少量朱红、完整孤立的等距场景、各格12%透明留白，无文字、背景纸张、边框或发光。按钮使用 Lucide 0.468.0 的原图标与随附 ISC 许可，资源位于 `web/assets/building-icons/`。

地域概览列表直接显示建筑及开辟入口，平面和立体地图均显示建筑数量标记，选中地域可看类别、等级、状态和使用权；异地只读，当前地才可进入。沿用现有地图导航，不增加侧栏入口。城市文案按三类用途与三级规模组合，只有具有实际阵法/禁制标志才描述相应防御；洞府按等级与营造品质、寺庙按原等级及信众数生成描述。

每次进入或选项跳转都生成单调递增事件编号。提交复验地址、状态、使用权、资金与所提供选项；旧页面和重复提交拒绝，失败不重复收费。读档恢复原会话，不重抽随机数。会话失效仅移除建筑事件，保留已获后续奖励。建筑内阻止其他变更命令，须先离开再修炼、移动或参与其他事务。

`GameState.building_state` 全局保留：建筑和聚气引用是固定地址资产，会话是原地址上的临时事件。已人工登记于[跨界字段合同](world-transition-state-contract.json)。不改写玩家 world，不复制 NPC 或经济库存，无跨界规则例外。专项入口为 `tests/test_building_system.py`、`tests/browser_buildings.py`，另运行跨界、事件及文档依赖门禁。

建筑前置检查与原鬼道、归墟、佛门检查一样，仅为只读准入检查，已登记在空间和试境允许的检查列表。建筑动作本身不在这些允许列表内；实际 HTTP 同时验证空间入宗、试境暂停仍可用，而在这两类场景筑城仍被拒绝。已实有初始城市按保存地址保留，后续内容目录调整城址不搬动或重复投影原城市。

## 验证入口

小版本使用 `verify_scoped_release.py --profile building-visits --shards 3 --workers 2`。显式范围见脚本 `BUILDING_VISIT_TESTS`，包含新游历、原建筑和城市、产业原账、佛门、Debug、事件、持久化、跨界及发行测试，不借用旧版本全仓证据；五组浏览器包含新名录与游历、原建筑、十一界城市、原产业、release212。Windows实际HTTP覆盖新分支及无DLC拒绝；Android以 `verify_android_buildings.ps1 -Visits` 运行building-visits与economy-enterprises横竖屏，四主题真实点击并核对安装包指纹。

隔离调试副本通过 `building action` 调用同一正式建筑入口，选项仍须提交当前事件编号；控制台的其他普通操作也执行建筑忙碌检查，不绕过材料、地点、权限或限次。`tests/test_debug_capabilities.py` 验证实际营造收费、过期提交回滚与原存档隔离。

`tests/test_city_buildings.py` 覆盖十一界目录与实际事件提交、有限奖励、真实工料扣除、治理年份、逐级发展、遗址重建、原产业停工及战役损毁。`tests/browser_city_buildings.py` 与原 `browser_buildings.py` 验证四主题桌面／手机、十一界城市、过期页面、禁用状态、后续奖励与忙碌解除；原事件入口另运行 `browser_events_212.py`。发行脚本为 `verify_scoped_release.py --profile buildings`、`verify_release_exe.py`、签名 Android 原生 buildings / economy-enterprises 横竖屏阶段及 `package_scoped_release.py`。只有完整证据匹配最终包与源码后才生成同版清单。

`tools/benchmark_buildings.py` 在隔离档用相同种子、确定性身份生成，比较 0、1、128 条建筑记录及同等数量的已领奖记录各一次真实休息行动，预热一次后取三次中位数，并核对经济结算数据一致。气收益采用地址直接查找，另有禁止名录迭代的断言。性能对照包含保存校验和地图投影，不是更新前后提升证明；数据和源码指纹在 `build/building-performance.json`。
