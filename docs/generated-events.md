# 本体种子随机异闻

开发源码新增，存档仍为结构 **10**；不转换结构 1–9。本功能不依赖 DLC，尚未加入塔层、Boss 或新的地图实例。

## 玩家入口

主行动区的“历练与生计 → 勘察异闻”执行一次本地勘察。至少踏入炼气或对应道途的一阶；十一普通界面均可使用，仙界仍须满足原仙灵力适配规则。独立空间、归墟、受控魂魄、拘禁、活动试炼和待处理事件遵循已有操作限制。

每次最多推进一个正常行动单位，年龄、寿元、魂蚀、世界年度、机构和其他单位系统仍通过公共时间结算。若年度事件打断勘察，只计真实经过时间；已经发现的异闻排在该事件链末端，不覆盖原事件。勘察本身不移动玩家，也不额外赠送机缘。静默模式只抑制普通随机弹窗，不取消玩家明确发起的勘察。

首版有灵泉、阵枢、封匣、古碑、灵植、灵灯六类情境，每类两种相反状态。种子决定情境、状态、选项顺序、资源比例及合法目录奖励。玩家根据正文线索选择处理方法，或放弃取藏；文字提示法力代价与可能损失的气血比例。两个处理选项采用相同的气血安全门槛，避免按钮可用性泄漏正确答案。处理失当受创且遗藏损毁，判断正确取得已确定奖励及少量机缘。

选择不额外推进年份。气血不足以承受公开风险、法力不足时处理选项禁用，放弃仍可提交。若前置授权事件使玩家离开原地点或受控，只允许无收益地放弃。已打开事件不因修为变化重新筛选或重抽。

## 生成与状态

`generated_event_generation.generate(seed, sequence, source, reward_pool)` 是纯生成器，输入显式地点、境界与合法奖励描述，不读取玩家、不扣资源、不保存，也不执行任意脚本。情境与奖励使用独立的稳定随机流，生成版本纳入种子。结果完整保存，而不是读档时根据最新目录重新构造。

`GameState.generated_event_state` 保存子协议版本、递增序号、一份未完成记录及最近一次处理结果。记录包含原 `(world, instance_id, location_id)`、生成版本、正文、选项及固定后果。`pending_event` 只投影本次唯一事件编号、标题、线索和公开选项；不发送隐藏后果、奖励和判断结果。序号不随放弃、读档或换页重置。

结构 10 中缺少该字段时表示尚未勘察，默认为空；不补发历史事件或奖励。未知生成版本、非法数字、附加效果脚本等记录拒绝加载并保留原文件。新字段归属登记在[状态合同](world-transition-state-contract.json)。

## 提交与复用

系统层的 `generated_events.prepare` 使用既有本地探宝奖励目录，再调用纯生成器。奖励不创建新装备定义，不绕过秘境或归墟专属货源隔离。

选择仍从正式 `choose` 入口提交。生成事件必须携带本次唯一 `event_id`，校验实际提供选项、当前所在地、受控状态和资源后，读取保存的权威记录；效果仅转换为已有 `restore_mp`、`damage`、`add_opportunity`、`add_item`、`learn_technique`。真实机缘、物品、功法、重复玉简和相关成长都由原入口结算；不另建库存或资源池。

处理完成清除活动记录，保存有限信号 `released / stabilized / preserved / damaged / left` 并记入历史。后续副本可以读取这些结果，显式组装自己的 Boss 和奖励条件；当前异闻不会凭空修改不存在的 Boss。

读档准备从活动记录修复展示和禁用状态，保留后续事件。缺失展示指针时只恢复已保存事件，不重抽。旧页面、本次事件未提供的选项与重复领奖拒绝；前端沿用一次拒绝后刷新权威状态的流程，不自动重发副作用请求。
