# NPC培养系统跨界影响审阅

2026-11-05，基于当前3.5.2源码与结构12。范围包括收徒关系、培养对象、受禁人物、活傀／炼尸／机关、培养材料和高阶能力。初次审阅后，按用户要求完成以下三处修复；未更新版本或改写用户原存档。

## 修复后的责任入口与限制

1. `EntourageManifest.commit` 接收正式迁移计划的 `arrival_location`，仅为获准随行且存活的人物写入新地点，同步已有后代快照。落选、死亡及留在原界者不伪造抵达，关系继续引用同一个NPC。
2. `apply_world_transition` 在临时通行时为随身held人物登记目标普通地点或目标空间实例地点；第二元婴保持既定例外。`release_person(at_player=True)` 用于当面释放俘虏、遣散俘虏来源侍妾、解除活傀控制，按当前实例地点落地；异界或缺少有效落点时拒绝。默认远程释放保留原人物地点。特殊空间内移动后释放同样按新地点登记，身份、成长和实例名册保持一致。
3. `spatial_capabilities` 开放独立培养窗口读取和原有传法。新旧入口共用 `targets.require`，以 `site_key` 检查空间内实际地点；异界、异实例、异地、死亡、封印、任务占用仍拒绝。普通升阶、专材培养和能源更换在独立空间继续禁用，不将未知界面默认为人界。

新增回归：`tests/test_npc_transition_training.py` 覆盖实际跨界规划／提交、释放、重载、同一人物、保留能源、两种空间及两套入口的拒绝原子性。`tests/browser_npc_transition_training.py` 用桌面和移动视口点击真实新／旧传法按钮，验证过期提交不扣费、恢复后传法成功，以及应禁用的培养按钮与伪造请求仍被拒绝。原有跨界、拘禁、身魂及事件回归同步执行。所有验收使用临时存档。

修复后验收：领域131项、跨界与培养245项、额外公开跨界→释放→培养→重载1项，共377项通过（新增跨界培养用例20项）。两类独立空间的桌面／移动端真实点击通过；`browser_events_212.py` 的过期恢复、后续奖励、忙碌解除与鬼修禁用控件验收通过。跨界状态契约、模块依赖、文档三项检查通过。日志：`build/npc-transition-domain-tests.txt`、`build/npc-transition-regression.txt`、`build/npc-transition-passage-test.txt`、`build/npc-transition-browser.txt`、`build/npc-transition-events-browser.txt`。

## 修复前复现记录（三项均已修复）

### 1. 共同飞升后的道侣仍保留旧界地点

责任入口：`system/world_transition_system.py:EntourageManifest.commit`。随行清单正确复用原NPC，调用原人物跨界结算，但只更新`world`及离界记录，没有更新抵达地点。

真实规划／提交复现：玩家和道侣从人界共同抵达灵界。玩家落点为`tianyuan_realm`，道侣的`world`已是`spirit`，`location_id`却仍是人界`wudi_plain`。关系仍指向同一人物，但新培养服务拒绝“须确认人物与你在同一实际地点”。有旧地点的人物也不会走势力驻地兜底。

影响：保留下来的道侣无法正常接受当面培养；同一提交入口中的存活随行道友也存在相同的地点遗漏。建议由正式迁移提交把已获准随行的人物登记到计划落点，而不是放宽培养检查或跟随玩家动态猜测地点。

### 2. 受禁人物跨界后释放，仍停留在旧界地点

责任入口：`system/world_transition_system.py:apply_world_transition`中非永久通行的held人物循环，以及`npc_custody.py:release_person`。通行会更新受控原人物的世界，释放会恢复原身份／名册，但两者均未登记新的实际地点。

复现：妖界`myriad_beast_city`的受禁弟子随玩家抵达幻冥界`moonbeast_plain`。受禁时凭原控制关系可以培养；释放后仍为同一弟子，却保存“幻冥界＋妖界旧地点”，自由培养立即失败。

建议：随身受控人物的落点必须在通行／释放的权威入口登记。普通驻地、原宗门成员资格和特殊空间实例分别处理，不能把释放等同于传送回原宗门，也不能复制人物补名册。

### 3. 独立空间的新旧培养入口不一致

责任入口：`system/spatial_capabilities.py`、`system/spatial.py:guard`及`system/npc_development/service.py:teach`。

通过真实空间进入与公开引擎命令复现：在失落界面，同实例同地点的弟子使用新`npc_development`窗口被外层空间白名单拒绝；旧`gift_disciple(..., 'technique', ...)`入口仍成功传授主修，实际登记1级。只看内部报价函数会漏掉这个外层差异。

影响：关系页仍有培养快捷入口，但进入后报空间隔绝；旧传法和新窗口无法提供一致能力。不能简单新增普通界面兜底。建议明确区分“可以查看”“可以原有传法／赠物”“可以主动升阶”：如保留空间内原有传法，新窗口应同样呈现允许项，升阶／专材仍按空间规则禁用。

## 现有规则对培养投入的影响

| 跨界方式／条件 | 当前行为 | 对新系统的影响 |
| --- | --- | --- |
| 永久飞升／永久离界清理 | 清空傀儡、受禁／侍妾记录、师承、弟子及待决拜师帖；道侣／道友仅保留原随行清单允许者 | 已培养傀儡连同已装能源、剩余耐久、备用能源一起遗失；弟子的原NPC与成长仍留在原界，解除关系不等于删除人物 |
| 普通临时往返 | 保留原关系和傀儡资产；自由弟子不自动跟随，队伍由原通行规则解除 | 异界不能遥控培养；返回同地点并满足状态限制后恢复；傀儡耐久、备用能源不会因往返补满 |
| 封印／秘法压制 | 培养公共目标校验拒绝 | 当前是全部培养操作受限，包含能源更换；不能因为背包有材料而绕过封印 |
| 四大道途上境 | 道→仙界、魔→修罗界、妖→幽冥界、鬼→轮回界 | 主动上境升阶、转化、邻域与对应专材仍须在目标道途上界；培养不替代人物迁界 |
| 个人访学／开拓通道 | 原路线拒绝同行队伍和活着的held人物 | 控制中的活傀来源人物也参与held检查；培养系统不新增携人权限 |
| 材料与能源 | 背包库存保留；材料使用／能源安装另验当前界层 | 能获得、能携带，不代表能当地使用；能源换装不能刷新原件耐久 |

永久离界清理是既有玩法规则，不是本轮发现的扣费错误。其代价现在更大：NPC培养投入和可更换能源扩大了傀儡的价值。若要允许保留，需要单独修改跨界携行规则及成本，不能作为地点修复顺带豁免。现有装备能源的战斗使用与新安装限制是两个入口；供能模块按傀儡阶位、能源阶位、剩余耐久和玩家可用余额结算，本次未更改低界压制或仙阶伤害规则。

## 已验证的正常边界

- 使用原跨界规划／提交验证临时下界及返回：原自由弟子身份、地点、成长保持；傀儡剩余47耐久与备用23耐久保持，不复制、不回满。
- 四个对应上界的合法培养报价可用；现有领域回归覆盖错误上界、跨层材料和专属能力限制。
- 使用公开`cross_world`命令后，旧培养页面revision提交被拒绝；稳定读取后的存档文件保持不变，没有扣材料或机缘。
- 原人物元力沿`npc_lifecycle.move_world`结清旧环境并设置新环境恢复速率；培养扩容不回满元力。新成长没有独立移动入口。
