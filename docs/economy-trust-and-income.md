# 年度收支、成交额与经济托管

宗门、家族财政展示年度收入与年度支出，并同时保留本期经营收入、本期实付支出和本期成交额。年度数值为最近实际结算区间的金额除以实际年数；例如五年收入 5000、支出 2000，年度收入 1000、年度支出 400。界面明确披露覆盖年数；没有新结算记录时显示待年度结算，不猜测旧记录覆盖区间。

组织经营收入沿用原净工料口径：真实生产订单销售实收减采购与劳务；固定产业先收回已经实付的成本，再确认盈余。另列支出为供养、公共设施、福利、分红等，不再次扣同一工料。实收税费、上供和商队利润分红计入收入；融资注资、本金归还和货物调拨不计收入。家族分红进入真实支出，上供同时记付款宗门支出和收款家族收入。商队早于组织结算，已实付分红暂存一次性非现金收据，在下次组织结算消费。

成交额合计真实采购与销售的商品价款，收入为实际售货所得或扣成本后的组织经营所得，利润还要扣运费、养护等费用。产业、商队的累计成交额从统计启用后的真实交易开始；原市场累计成交额继续包含当地全部交易。初始年度结算前或偏远宗门五年结算间隙的实际经营记录独立保存为待结算收入、支出、成交额，在原真实区间结算消费一次，不覆盖丢失，也不混入上一期折年值；这部分盈余的可选养护延后到本期结算支付一次。个人流水改称现金流入、现金流出，包含注资、提款与归还本金，不把资金调拨称作经营收入。查询不初始化账目、不结算、不使用 RNG。

护卫仍是原商队付薪聚合战力。个人商队经营列表、宗门和家族经营区均提供“委派护卫”按钮，调用原 fleet_action 事务；权限复用原订单 authorized，包括本人领办及玩家执掌组织的原商队，不要求改写 player_controlled。必须同界同地、驻留且未满额，失去组织经营权即失去护卫办理权。手工聘用由本人支付，托管聘用由商队自身周转金支付，计入经营成本。运输中、已经足额、忙碌或失去权限时不得办理。

设置中的“经济托管”默认关闭、随结构 10 存档保存。开启后，只在原年度入口管理玩家有经营权的固定产业、本人领办和执掌组织的原商队。产业先交真实维护、清算既付批次，再复用掌柜 plan 的本地利润、原料、资源、仓储和市场流动性检查。保留原产业方案，关闭后恢复；手动调整重新保存方案。收回授权不取消已经支付的生产，也不取消在途货物；产权转让和战争交接删除前任配置快照。

托管经营允许当地掌柜在玩家离界后继续执行已授权方案，这是自动年度管理的具体例外，责任入口为 advance_estates / advance_caravans；不放开原手工亲赴条件，不搬移玩家、货物、NPC 或府库。本人产业仅使用已有产业周转金，不自动扣行囊。商队保留手动暂停、单次和长期订单，仅自动贸易模式按既有利润选路，护卫补足必须另外保留三年养护和工资资金。

实际盈利后，每五个世界年最多进行一次投资决策，不补跑被跳过的年份。可用预算不超过托管后新增已实现产业净收支的三分之一及扣除三年维护储备后现金的三分之一；组织存在供养缺口或参战时暂停。启用时记录原净收支基线，避免把前任或历史利润重复投资。优先扩建原产业，或从原地点有限地块中选一处具有可盈利配方的产权，支付真实价格并为本人新产业拨付周转金。新购产业下一年度才加入经营，不递归触发新投资；扩建不恢复矿藏、不提高天然资源品阶。产业上限五级，商队扩编也须本趟和累计经营盈利。

托管选生产方案时，每种当地允许的配方最多比较三个合法批量（单批、半容量、满容量），以分摊真实固定维护；不会按产量或年数逐件报价。候选批量受实际资源余量及原料缺口库存约束，单次付款、仓储、采购资格、实际市场收购能力与 5% 利润门槛仍由原 start_job 再检查。扩建先验证下一等级仍可盈利，并保留新等级的养护储备；不会为了制造扩张记录买下枯竭矿区或增加无法承担的固定成本。原独立掌柜委托保持其已有单批节拍。

性能约束：复用原产业和商队遍历；投资候选最多五个本地地块；不增加逐 NPC、逐商品年度全表扫描或补跑多年经营。验收按单模块顺序执行，浏览器每个布局单独启动并释放，一个 Chromium 实例和一个页面同时存活；经济及事件专项可跳过无关地形素材解码。设置环境变量 `CULTIVATION_BROWSER_LOW_MEMORY=1` 后，`tests/browser_economy_trust.py` 和 `tests/browser_events_212.py` 保留主题 a 桌面/手机的真实点击、加载、提交、过期恢复、奖励及忙碌解除，避免加载无关主题场景；默认经济专项仍测 a/f 四布局，发行事件默认仍测四主题。针对性回归见 `tests/test_economy_trust.py` 与 `tests/browser_economy_trust.py`。

## 六项经济审计修复

外姓入族时，市场控制权与原府库一并从 sect 标识改为 family，保留手续费游标、权利取得年及累计实收；不改变运营现金或市场库存。家族产业扩建复用原家族决策资格。战后接管的组织商队不再保存本人领办标记；既存结构10误留的标记由原和约收据识别，实际经营权、在籍领办身份在订单、护卫、注资、托管和详情投影共用核验。退宗或失去组织经营权不能凭旧接管标记继续控制商队，真正本人领办的组织商队在仍在籍时保持权限。

商队在同界运输、待售、跨界途中及通道受阻期间均按原年度区间实付护卫薪饷；周转金不足按原比例削减护卫，不丢弃原在途货物。已付工资立即记经营费用和累计净收支，本趟非现金 running_costs 留存至交割，净利润及分红扣除该费用但不二次扣累计净收支。旧批次缺少此记录按零处理，仅从下一真实年度区间开始计薪，不追扣旧年。新设队伍不收成立前工资，同年重复结算不再付薪。普通自动贸易预计利润及资金检查包含航程工资。

手动府库采购的实付费用和商品成交额写入当前实际区间，尚未结算时进入 pending_expense/pending_turnover；年度采购在原结算中的同一财务记录登记一次。市场控制方实际收到的税费采用相同收入区间判断，五年结算间隙的金额进入 pending_income，在真实区间结束时消费一次。组织扩建支出亦采用原支出记账入口。验证见 `tests/test_economy_audit_followup.py` 与 `tests/browser_economy_audit_followup.py`，后者顺序运行主题a桌面／手机实际入族重载、采购提交和过期护卫页面拒绝恢复；只运行相关领域、跨界入口及真实页面验收。

## 后续经营边界修复

组织固定产业、商队及市场管理共用的 owner_allowed 先核验原组织的当前成员身份，再检查创办、执掌及修为资格；冻结的控制者缓存和旧创办记录不授予退宗后的经营权。仍在籍但失去执掌资格时，缓存也须通过原 organization_authority.player_controls 的当前境界与原成员核验，不能代替真实权限；仅已有缓存声称玩家执掌时进行此项检查，不增加逐 NPC 年度经营。本人的固定产业仍保留原产权，合法离界后的驻地自动委托仍可运行，不开放异地手工操作。

重新购置背景持有的产业保留唯一地点、等级、矿藏、库存及历史，按本次购置者资质选择配方，并关闭原自动采购、销售和委托。每次开工都重新检查当前玩家经营资质及需要采购的原料品阶；产业仓库的自动采购和商铺进货也复用此检查。已支付的批次按原工期完工，不因资质降低销毁投入或追加付款；自主经营的其他组织保持原劳动与府库结算。

跨界自动选货的去程预测扣除实际路径往返护卫工资，返程选货扣除返程路径工资；报价与年度实付共用 guard_wages，周转金同时保留已知工资和既有返航关税储备。明确指定的手工货单可接受亏损，但同样须有工资和返航资金。多段路径按每条实际通道时间求和，不按跨界次数猜测时间；不新增逐年规划或商品全表回放。新设商队在本次成立前的补结算区间不交工资或养护，从下一真实年度开始计费。

成员供养先消费原府库非预留库存，再用原府库资金采购实际缺口；这些真实采购的商品价款累计至本期组织成交额一次。收入、供养费用和已持有物资消耗保持各自口径，不能把成交额再次当作收入或现金。

拍卖每件玩家寄售品交割前核验原世界买方背景资金足以支付完整拍定价及手续费。资金不足按流拍处理，原标准物品或炼器法宝实例原样退回一次，占位费不退，历史记录原因；后续拍品使用同一资金池。成功及流拍均通过原 economy_settled 结清标记避免重载、跨界取消或重复结拍再次付款、退货，休息等耗时动作正常继续。字段归属见状态合同，专项见 `tests/test_economy_audit_round2.py` 和 `tests/browser_economy_round2.py`；浏览器顺序验证主题a桌面／手机的旧资质开工拒绝、恢复后的禁用按钮、退宗后旧库存按钮拒绝恢复，以及真实寄售结拍、流拍退货和重载幂等。

## 产权记账与同界货单边界

组织聚合产业的宗门扩建入口复用当前 `owner_allowed`，不再单凭旧执掌缓存放行；仍要求在籍及亲赴组织驻地。家族扩建保留原家族决策资格。既有扩建按钮只读投影相同资格和地点条件，失权或异地时禁用；旧页面提交仍由后端核验。同界手工贸易、产业调货及长期货单的空返，均核验本段实际路线的购货、运费与 `guard_wages`；预留工资仍在原商队现金中，仅在真实年度入口实付，不在启程时重复记为已付成本，允许玩家明确承担贸易亏损。

组织购置产权及有偿受让的实付款为资本支出，统一在产权入口登记一次：已有实际结算区间且仍在同年则进入本期支出，否则进入 `pending_expense`；NPC 原年度购置直接记正在结算的实际区间，托管不另重复登记。购置费不属于商品成交额、销售收入或生产工料，不再通过 `estate_cost_credit` 对未来收入重复抵扣。个人购置仍由原行囊支付并记录个人现金流，产业独立周转账户的经营费用继续只记录采购、劳务、养护及已有扩建费用。

在有偿交接、交回／重新购置及战后交接改变产权之前，原持有人与接收组织分别确认各自已有产业的未收回成本；接收方初始化不包含即将转入地块的前任历史费用。原组织别名仍指向同一府库和成本账。同一地块的历史、库存、在制批次、矿藏和编号保持原记录，交接不转移现金成本收据、不复制物资。此项只防止后续交接串账，不猜测并重算旧档已经登记的财政数字。

没有新增持久字段或逐 NPC 年度扫描；只有实际购置／交接时采用尚未登记的成本账，最多扫描一次该组织已有产业，之后复用原记录。验证见 `tests/test_economy_audit_round3.py` 与 `tests/browser_economy_round3.py`，验收采用隔离存档并串行运行，不重打包安装程序。

本轮最终源码验收：391 项专项回归通过，其中新增 12 项边界回归；字段合同、模块依赖、文档门禁及主题 a 桌面／手机的真实经营、旧事件流程通过。同一灵界初始档旧／新各三次完整百年结算，固定临时进程 CPU 0 的中位数为 3.9868／3.9786 秒，基本持平；全部持久状态与 RNG 一致，仅排除墙钟 `updated_at`。此为隔离新档采样，不代表长期大档；只有实际购置／交接增加成本归属确认，不增加逐年 NPC 或商品全表扫描。最终汇总位于 `build/economy-round3-fixed-validation/final-report.json`，绑定同一最终生产源码摘要；测试、浏览器及百年采样顺序执行，用户存档未修改，安装包未重建。
